## Goal

Every screen in the app behaves predictably when the network is slow, the data is empty, or the request
fails. A player on a car-park 3G connection sees a skeleton and then either their event or a line of copy
with a Retry button, never a blank white screen and never a spinner that spins forever. The audit is
written down, so the claim can be checked rather than believed.

## Context

The conventions in `CLAUDE.md` §3 say "Every screen must handle four states: loading, empty, error,
populated. A story is not done if any are missing." [D49](../00-decisions.md) pushed the per-screen
specification back into each story's own UI-states table precisely so this story is a **check and a
sweep**, not a rework project. [D57](../00-decisions.md) is the rule for the whole epic: every story ships
its own tests, and Epic 7 verifies rather than backfills. If this story finds a screen with three states,
that screen's story was not done.

Three things sit here because no single feature story owns them:

- The **audit artifact** — one table covering every route in [D34](../00-decisions.md), so a reviewer can
  see coverage at a glance instead of reading thirteen components.
- **"No unhandled promise rejections"**, which is a repo-wide lint and harness concern, not a screen concern.
- The **375px sweep**. [D40](../00-decisions.md) fixes the 44px minimum once in S0.2 and
  [D42](../00-decisions.md) fixes the response list as cards, but nothing checks that every screen still
  obeys both after twenty stories of building.

This story's PR is the one stated exception to "one story per PR": it may touch any screen file in the
repo to close a state gap. It may not add a feature, change copy that a story fixed, or widen scope.

Depends on [D48](../00-decisions.md) for the optimistic-response failure line and
[D49](../00-decisions.md) for the fixed empty and error copy.

## Scope

**In**

- `docs/state-coverage.md`: one row per route, one column per state, every cell naming the test that proves it.
- A Vitest harness that renders every route under each of the four states.
- Closing every gap the audit finds, in the same PR.
- Confirming the type-aware ESLint rules that catch floating and misused promises are live, adding the one
  `no-misused-promises` option override, and fixing the repo clean.
- Failing a Vitest run and a Playwright run on any unhandled rejection or uncaught page error.
- Confirming the Sentry unhandled-rejection path is live and scrubbed.
- A Playwright layout sweep at 375x667: no horizontal scroll, no interactive element under 44px.

**Out**

- Writing new screens, new copy, or new features. A gap is closed by adding the missing state to an
  existing screen using the copy already fixed in that screen's story or in [D49](../00-decisions.md).
- Visual regression testing or screenshot diffing. Not in the stack table, and not worth it at this size.
- Accessibility auditing beyond touch-target size. Not asked for; do not scope-creep into it.
- Offline behaviour beyond what [D43](../00-decisions.md) already specifies. There is no offline write
  queue ([D48](../00-decisions.md)).
- Performance budgets. [D21](../00-decisions.md) put the only timing number on a real device in
  [S7.4](S7.4-device-pass.md).

## Acceptance criteria

Each criterion is independently checkable by a person or a test.

- [ ] **AC1** — `docs/state-coverage.md` exists and contains one row for every route in
      [D34](../00-decisions.md) (`/`, `/login`, `/register`, `/join/:token`, `/reset/:token`, `/event/:id`,
      `/history`, `/manage`, `/manage/event/new`, `/manage/event/:id`, `/manage/team/:teamId/members`,
      `/admin`, 404) plus the two conditional surfaces ([S2.7](S2.7-escape-the-whatsapp-browser.md) escape
      prompt, [S2.8](S2.8-add-to-home-screen-guide.md) install guide). No cell is blank: each is either a
      test name or the literal `n/a — <reason>`.
- [ ] **AC2** — `npm run test` (`vitest run`, the script fixed in [S0.1](S0.1-project-scaffold.md)) includes
      `src/test/states.test.tsx`, which mounts every route above in each of the four states and asserts the
      documented behaviour. A route missing a state fails the test, not the review.
- [ ] **AC3** — Every error state renders an inline message **and** a control that refetches. The test
      asserts the control is present, clicks it, and asserts a second request is issued. No screen falls
      through to the S0.6 error boundary as its designed error state.
- [ ] **AC4** — No route renders an empty document body in any of the four states. The loading state of a
      cold deep link to `/#/event/:id` renders the app shell and a skeleton, never a white page.
- [ ] **AC5** — `@typescript-eslint/no-floating-promises` and `@typescript-eslint/no-misused-promises`
      report as errors. Both come from `tseslint.configs.strictTypeChecked`, already in
      [S0.1](S0.1-project-scaffold.md)'s flat config, so this story's job is to confirm they are live, add
      the `no-misused-promises` option override in the implementation notes, and get the repo clean.
      `npm run lint` exits 0 with no `eslint-disable` added to make it pass. Any genuine fire-and-forget
      call is written `void promise` with a one-line comment saying why. Checked by deleting one `void`
      and confirming lint goes red.
- [ ] **AC6** — The Vitest setup file fails the run on an unhandled rejection, and a deliberately
      introduced floating rejection makes the suite red. Demonstrated once and then removed.
- [ ] **AC7** — The Playwright auto-fixture fails any test whose page emitted a `pageerror` or a
      `console.error`. Demonstrated the same way.
- [ ] **AC8** — Sentry's `onunhandledrejection` integration is enabled, is not filtered out by `beforeSend`,
      and a rejection carrying an E.164 number in its message arrives redacted. Asserted against the
      [D16](../00-decisions.md) scrubber in a unit test, with no network call.
- [ ] **AC9** — `tests/e2e/layout.spec.ts` visits every route in the list at 375x667 and asserts
      `document.documentElement.scrollWidth <= clientWidth` and that every element matching
      `button, a[href], input, select, [role="button"], [role="switch"]` has a rendered box at least 44px on
      its smaller axis.
- [ ] **AC10** — The "Gaps" section of `docs/state-coverage.md` lists every gap found and, for each, the
      commit that closed it. The story is not done while a gap is open.
- [ ] **AC11** — The lint rule from [D35](../00-decisions.md) banning `toLocaleString`,
      `toLocaleDateString`, `toLocaleTimeString` and `new Intl.DateTimeFormat` outside `src/lib/time.ts`

      been weakened somewhere and that is the finding.

## Implementation notes

### The audit artifact

`docs/state-coverage.md`. One table, then a Gaps section. Cells name the test, not the component, because
the test is the thing that keeps being true.

```
| Route | Loading | Empty | Error | Populated |
|---|---|---|---|---|
| `/` | states › home › loading | states › home › empty | states › home › error | states › home › populated |
| `/login` | states › login › submitting | n/a — form, no server read | states › login › bad password | states › login › ready |
```

### Rendering every route without a new dependency

MSW is not in the stack table and is not being added. Stub at the client boundary instead. One file,
`src/test/supabase-stub.ts`, exporting a factory that produces a `SupabaseClient`-shaped object whose
query builder is thenable:

```ts
type Scenario = 'loading' | 'empty' | 'error' | 'populated'

export function stubSupabase(scenario: Scenario, fixtures: Fixtures): SupabaseClient<Database>
// 'loading'    → every terminal `.then()` returns a promise that never settles
// 'empty'      → { data: [], error: null }  (or { data: null, error: null } for .single())
// 'error'      → { data: null, error: { message: 'stub failure', code: 'PGRST000' } }
// 'populated'  → { data: fixtures[table], error: null }
```

Install it with `vi.mock('@/lib/supabase', () => ({ supabase: stubSupabase(scenario, fixtures) }))`.
Fixtures live in `src/test/fixtures.ts` and are plain objects typed against the S1.5 Zod schemas, so a
schema change breaks the harness rather than letting it drift.

`src/test/render-route.tsx`:

```ts
export function renderRoute(
  path: string,
  opts: { scenario: Scenario; user?: FakeCurrentUser },
): RenderResult
```

It wraps the route element in a fresh `QueryClient` with `retry: false` and
`gcTime: 0`, a `MemoryRouter` seeded with `initialEntries: [path]`, and a stubbed `useCurrentUser()`
([S2.9](S2.9-auth-guard-and-role-context.md)) so role-gated routes render without an auth round trip. A
fresh client per test is mandatory; a shared one leaks a populated cache into the loading case and the
test passes for the wrong reason.

`src/test/states.test.tsx` is a `describe.each` over a route manifest:

```ts
const ROUTES = [
  { path: '/',                 name: 'home',    states: ['loading','empty','error','populated'] },
  { path: '/login',            name: 'login',   states: ['loading','error','populated'] },
  // ...
] as const
```

The manifest is the single source of truth for AC1 and AC2 both: a Vitest test reads
`docs/state-coverage.md`, parses the route column, and fails if it does not match `ROUTES`. That keeps the
document honest without anyone remembering to update it.

### Expected behaviour per state

Loading is a skeleton, not a spinner, on any screen that has a known shape (`/`, `/event/:id`, `/history`,
`/manage`, `/manage/event/:id`, `/manage/team/:teamId/members`, `/admin`). A spinner is acceptable only
inside a submit button. Empty copy is fixed by [D49](../00-decisions.md); do not invent new wording.
Error is always an inline message plus a Retry control wired to the query's `refetch`.

### Floating promises

Turn on type-aware linting in `eslint.config.js`:

```js
languageOptions: { parserOptions: { projectService: true, tsconfigRootDir: import.meta.dirname } },
rules: {
  '@typescript-eslint/no-floating-promises': 'error',
  '@typescript-eslint/no-misused-promises': ['error', { checksVoidReturn: { attributes: false } }],
}
```

Both rules are already on through `strictTypeChecked`; the block above restates them so the intent is
visible and adds the one option that matters.
`checksVoidReturn: { attributes: false }` is required, or every React Hook Form
`onSubmit={handleSubmit(fn)}` and every `onClick` calling a mutation goes red for no benefit. Real
fire-and-forget calls — analytics-shaped things, the [S2.8](S2.8-add-to-home-screen-guide.md)
`deferredPrompt.prompt()` — are written `void x()` with a comment.

### Harness guards

`src/test/setup.ts` (referenced from `vitest.config.ts` `setupFiles`):

```ts
process.on('unhandledRejection', (reason) => {
  throw reason instanceof Error ? reason : new Error(String(reason))
})
```

`tests/e2e/fixtures.ts` gains an auto fixture used by every spec, including the ones
[S2.5](S2.5-deep-link-return-path.md) and [S7.3](S7.3-end-to-end-journey.md) own:

```ts
export const test = base.extend<{ failOnPageError: void }>({
  failOnPageError: [async ({ page }, use) => {
    const errors: string[] = []
    page.on('pageerror', (e) => errors.push(String(e)))
    page.on('console', (m) => { if (m.type() === 'error') errors.push(m.text()) })
    await use()
    expect(errors, 'page emitted errors').toEqual([])
  }, { auto: true }],
})
```

### Sentry

Do not add a second `unhandledrejection` listener. `@sentry/react`'s browser integrations already capture
them. Confirm the integration is present, confirm `beforeSend` from [D16](../00-decisions.md) does not drop
the event, and unit-test that a rejection reason containing `+353871234567` is redacted before it leaves.
The scrubber's own coverage belongs to [S7.2](S7.2-unit-tests.md); this story only asserts the wiring.

### Layout sweep

`tests/e2e/layout.spec.ts`, running under the existing mobile project in `playwright.config.ts` with
`viewport: { width: 375, height: 667 }`. Sign in once as a seeded manager so the manage and admin routes
render populated; the [S1.2](S1.2-profile-provisioning-and-seed.md) seed provides the fixtures. Measure
with `boundingBox()` and skip elements with `visibility: hidden` or zero area. Elements hidden behind a
closed dialog are skipped, not failed.

## Data and API surface

No new tables, RPCs or migrations. No new Zod schemas. No new TanStack Query keys.

The Vitest harness reads `src/api/` hooks through the stubbed client only; it never opens a socket. The
Playwright layout sweep signs in as the seeded manager with `signInWithPassword` and reads whatever the
existing S1.3 policies allow. Gap fixes may add `refetch` wiring to existing query hooks in `src/api/`, but
must not change a query key, a filter, or a mutation's payload.

## Test plan

- **Unit** — `src/test/states.test.tsx` renders every route in every state and asserts the table above.
  `src/test/state-coverage-doc.test.ts` parses `docs/state-coverage.md` and asserts its route list matches
  the `ROUTES` manifest. A scrubber wiring test asserts Sentry's rejection path redacts an E.164 number.
- **Integration / RLS** — None. This story adds no policy and no RPC. The
  [S1.4](S1.4-rls-test-suite.md) suite must still pass unchanged; if closing a gap required a policy
  change, the gap was misdiagnosed.
- **E2E** — `tests/e2e/layout.spec.ts`: 375x667 sweep over every route, no horizontal scroll, no
  interactive element under 44px. The auto fixture failing on `pageerror` and `console.error` applies to
  every existing spec from this story onward.
- **Manual** — Throttle DevTools to Slow 3G and load `/#/event/:id` cold. Confirm the shell and a skeleton
  appear, not a white page. Kill the Supabase container and reload `/`; confirm an inline error with a
  working Retry, and that the S0.6 boundary never appears.

## Open questions

1. **Does the state harness stub the Supabase client, or add MSW?** Proposed default: stub the client, as
   specified. MSW is a new runtime dependency for test-only benefit, and the client boundary is the same
   boundary `src/api/` already isolates.
2. **Do dialogs and sheets count as screens for the audit?** Proposed default: no, except the two
   conditional surfaces named in AC1, which get a Populated cell only. A confirm dialog reads no server
   state and has one state.
3. **What happens if the audit finds a gap large enough to be its own story?** Proposed default: close it
   here anyway if it is a missing state on an existing screen. If it is a missing screen, stop and flag it
   rather than building it inside this PR.
