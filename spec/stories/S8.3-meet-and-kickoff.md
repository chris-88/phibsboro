## Goal
A match carries two times: **Kick-off** (when the game starts) and **Meet** (when to arrive). The manager
sets both; players see both; the share shows "KO: 13:30 | Meet: 12:30".

## Context
[V4](../00-decisions-v1.1.0.md): `starts_at` stays kick-off and keeps driving the respond-until-start rule
(S3.4/D12). `meet_at` is a new nullable, match-only column, earlier than kick-off. Chris's choice: two times
on matches only; training/social keep one start time.

## Scope
**In**
- `events.meet_at timestamptz null` via migration, with a check `meet_at < starts_at` when both set.
- Match form: a Meet time input beside Kick-off (relabel "Start time" → "Kick-off" for matches). Both
  composed in Dublin wall-time to UTC through the time helper.
- Event detail and manager view show both times via formatEventTime; a new `'time'` variant renders HH:MM.

**Out**
- The share message format ([S9.3](S9.3-match-share-rewrite.md)) — this story adds the data and the display; the share rewrite consumes it.
- Meet times for training/social (not shown; column stays null).

## Acceptance criteria
- [ ] **AC1** — Migration adds `meet_at timestamptz null` with a check that `meet_at < starts_at` when both are set; runs clean on the live DB; existing rows unaffected.
- [ ] **AC2** — The match form shows Kick-off and Meet inputs; both are composed Dublin-wall-time → UTC via the time helper (no `new Date(y,m,d,...)`/`Date.parse`), verified by a unit test at a DST boundary.
- [ ] **AC3** — Submitting a match with meet before kick-off stores both; a meet at/after kick-off is rejected inline before submit and by the DB check as a backstop.
- [ ] **AC4** — Event detail and manager view show "Kick-off {time}" and "Meet {time}" (Dublin) via formatEventTime's `'time'` variant; a unit test covers the variant under TZ=UTC.
- [ ] **AC5** — `starts_at` still drives the S3.4 respond-until cutoff unchanged (a response after kick-off is still refused by the DB); no regression in the RLS suite.
- [ ] **AC6** — Training/social forms show a single start time and no meet field.

## Implementation notes
- `formatEventTime` gains a `'time'` variant → "1.30pm" or "13:30" (pick the club's style; the share shows
  "13:30" so use 24h for the `'time'` variant, keep the 12h style for the existing date variants — or a
  dedicated `'ko'` variant; decide and document). Only new variant, in `src/lib/time.ts` (the one formatter).
- Event schema gains `meetAt` (optional, match-only, `< startsAt` refinement). Form conditional on type.
- No RLS change — new column on `events`, already policied. Regenerate types.

## Data and API surface
`events.meet_at`. Event Zod schema + mutations. `formatEventTime` `'time'`/`'ko'` variant. Regenerated types.
