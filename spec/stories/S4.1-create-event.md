## Goal

A manager can put Saturday's match into the app from a phone in under a minute: type, title, date, start
time, location, optional notes, one button. The event appears at the top of the team's list straight
away, ready to be shared into WhatsApp. This is the first step of the only journey that matters, and
nothing downstream exists without it.

## Context

This is the brief's S4.1. It is story 29 in the build order of record ([D20](../00-decisions.md)), which
means every screen that reads events already exists and works against seeded rows; this story only adds
the write path. Two decisions shape it:

- **[D24](../00-decisions.md)** — `type` and `status` are Postgres enums, so the form's `z.enum` members
  are asserted equal to `Enums<'event_type'>`. A value added in SQL breaks
  typecheck rather than shipping a broken select.
- **[D50](../00-decisions.md)** — `events` INSERT additionally requires `teams.active = true`, enforced in
  RLS. The team picker lists active teams only, but the refusal is handled as copy, not as a crash,
  because the UI check is convenience and RLS is the enforcement layer.
- **[D48](../00-decisions.md)** — every "is this in the future" judgement uses `serverNow()` from
  `src/lib/serverClock.ts` ([S3.3](S3.3-event-detail-screen.md)), never the device clock. That covers the
  future-only validation, the date input's `min`, and the Upcoming / Past split on `/manage`.

Two things the brief leaves unstated and this story settles. First, the route list is fixed by
**[D34](../00-decisions.md)**: `/manage` and `/manage/event/new` exist, and there is no separate edit
route, so this story owns both the manager landing list and the create form, and [S4.2](S4.2-edit-and-cancel-event.md)
reuses the same form component inside a dialog. Second, `CLAUDE.md` mandates `formatEventTime()` for
display and bans ad-hoc `toLocaleString`, but says nothing about the inverse conversion a form needs.
This story delivers it, in `src/lib/time.ts` beside `formatEventTime()`, so nobody writes
`new Date('2026-03-14T19:30')` and silently uses the device timezone.

A manager may manage more than one team (`CLAUDE.md` section 4), so the form is always scoped to exactly
one team and says which.

## Scope

**In**
- `/manage` — the manager landing screen: team picker when they manage more than one, a "New event"
  button, and the team's events split into Upcoming and Past.
- `/manage/event/new` — the create form: type, title, date, start time, location, notes.
- `eventFormSchema` (Zod) plus the title-defaulting rules, shared with [S4.2](S4.2-edit-and-cancel-event.md),
  driven by React Hook Form with `zodResolver`.
- `dublinLocalToUtcIso()` and `utcIsoToDublinParts()` in `src/lib/time.ts`, with DST tests.
- `useTeamEvents()` and `useCreateEvent()` in `src/api/events.ts`, the first consumers of
  `eventKeys.list(teamId)` and `eventKeys.responses(eventId)` from S1.5's factory.
- Mapping a PostgREST refusal (inactive team, wrong team, check constraint) to inline copy.

**Out**
- Editing, cancelling, reinstating or deleting — [S4.2](S4.2-edit-and-cancel-event.md).
- The per-event manager screen and the response counts — [S4.3](S4.3-manager-event-view.md).
- Sharing the created event to WhatsApp — [S5.1](S5.1-message-generator.md) and [S5.2](S5.2-share-action.md).
  This story's success toast links to the event and nothing more.
- Recurring generation — [S4.6](S4.6-recurring-training.md). The form creates exactly one event.
- Moving an event to another team. `team_id` is fixed at creation and is not editable anywhere.
- Opponent, kick-off versus meet time, squad selection, results. Out of scope in `CLAUDE.md` and not
  smuggled in as notes fields.

## Acceptance criteria

Each criterion is independently checkable by a person or a test.

- [x] **AC1** — `/manage/event/new` renders six fields and nothing else: type (training / match), title,
      date, start time, location, notes — plus AC8's team select for a manager of more than one team, and
      no other field. Every interactive element is at least 44px high at 375px width
      ([D40](../00-decisions.md)).
- [x] **AC2** — Type defaults to `training` and title defaults to `Training`. Switching type to `match`
      rewrites the title to `Match` **only** when the current title is empty or is exactly the other
      type's default label; a manager who has typed `Kilbarrack away` keeps it when they switch type.
- [x] **AC3** — Submitting valid input inserts one `events` row with `starts_at` stored as a UTC
      `timestamptz` that equals the Dublin wall-clock time the manager typed. A 19:30 event on 14 March
      (GMT) stores `19:30Z`; a 19:30 event on 14 July (IST) stores `18:30Z`. Asserted in Vitest against
      `dublinLocalToUtcIso()` and once end to end against the database.
- [x] **AC4** — After a successful create, the app navigates to `/manage` and the new event is visible in
      the Upcoming section without a manual refresh, its time rendered by
      `formatEventTime(starts_at, 'short')`. [S4.3](S4.3-manager-event-view.md) AC14 later moves that
      destination to `/manage/event/{id}`; until S4.3 ships it is `/manage`.
- [x] **AC5** — Validation errors render inline under the offending field and the form does not submit:
      empty title, title over 80 characters, empty location, location over 120 characters, notes over 500
      characters, missing date, missing time.
- [x] **AC6** — A start instant at or before the schema's injected `now` is rejected inline with "Pick a
      time in the future.", and one more than 365 days ahead is rejected with "That's more than a year
      away." The screen injects `serverNow()`, so a device clock set ten minutes fast does not let a past
      event through and does not block a valid one ([D48](../00-decisions.md)).
- [x] **AC7** — Notes left blank are stored as SQL `NULL`, never as an empty string, so
      [S5.1](S5.1-message-generator.md) can omit the notes line by a null check alone.
- [x] **AC8** — A manager who manages exactly one team sees no team picker and the form is scoped to that
      team implicitly. A manager who manages more than one sees a required team select listing their
      managed active teams, and the chosen team survives a hard refresh of `/manage/event/new`.
- [x] **AC9** — An insert refused by RLS (inactive team, or a team the caller does not manage) renders an
      inline form-level message — "You can't add events to that team." — with the typed values intact. No
      unhandled rejection, no Sentry error boundary, no raw Postgres text on screen.
- [x] **AC10** — A player who navigates to `/manage` or `/manage/event/new` is redirected by the
      [S2.9](S2.9-auth-guard-and-role-context.md) guard, not shown a broken screen. The guard is
      convenience; RLS refuses the insert regardless.
- [x] **AC11** — The submit button is disabled while the mutation is in flight and a double tap creates
      exactly one row.
- [x] **AC12** — `/manage` handles all four states, including a team with no events at all
      ("No events yet. Add Saturday's match.") and a failed load (inline message plus a Retry button).
- [x] **AC13** — `/manage` splits the list into Upcoming and Past against `serverNow()`, ascending then
      reverse-chronological, with cancelled events left in place and badged rather than hidden. With the
      device clock wound forward an hour, an event starting in thirty minutes is still in Upcoming.

## Implementation notes

### Time conversion

`src/lib/time.ts` already exports `formatEventTime()` from [S1.5](S1.5-typed-data-layer-and-shared-helpers.md).
Add the inverse. No new dependency: `Intl.DateTimeFormat` with `timeZone: 'Europe/Dublin'` gives the
offset at any instant, and two passes settle DST.

```ts
/** Offset of Europe/Dublin at a given UTC instant, in milliseconds. */
function dublinOffsetMs(utcMs: number): number

/** "2026-03-14" + "19:30" (Dublin wall clock) → "2026-03-14T19:30:00.000Z" */
export function dublinLocalToUtcIso(date: string, time: string): string

/** The inverse, for populating the S4.2 edit form. */
export function utcIsoToDublinParts(iso: string): { date: string; time: string }
```

`dublinLocalToUtcIso` parses `${date}T${time}:00Z` as if it were UTC, subtracts the offset at that
instant, then subtracts the offset at the corrected instant. Two passes is enough for a one-hour shift.
Settle the two DST edge cases now and test both:

- **Spring gap** (01:30 on the last Sunday in March does not exist): resolves forward, to 02:30 IST.
- **Autumn overlap** (01:30 on the last Sunday in October happens twice): resolves to the first, summer
  occurrence.

Neither is a real training time. They are specified so the function is deterministic and the tests can
assert something.

Do not use `new Date(y, m, d, h, m)`, `Date.parse` on a naive string, or `toLocaleString` anywhere. The
ESLint rule from [S1.5](S1.5-typed-data-layer-and-shared-helpers.md) forbids the last one.

### Form schema

`src/features/events/schemas.ts` — the one schema file for this feature, which
[S4.6](S4.6-recurring-training.md) later adds the series schema to:

```ts
import { z } from 'zod'
import { eventTypeValues } from '@/lib/enums'   // S1.5, asserted against the generated enum union

export function eventFormSchema(opts: { requireFuture: boolean; now: Date }) {
  return z
  .object({
    teamId:   z.string().uuid(),
    type:     z.enum(eventTypeValues),
    title:    z.string().trim().min(1, 'Give it a title.').max(80, 'Keep the title under 80 characters.'),
    date:     z.string().regex(/^\d{4}-\d{2}-\d{2}$/, 'Pick a date.'),
    time:     z.string().regex(/^\d{2}:\d{2}$/, 'Pick a start time.'),
    location: z.string().trim().min(1, 'Where is it?').max(120, 'Keep the location under 120 characters.'),
    notes:    z.string().trim().max(500, 'Keep notes under 500 characters.'),
  })
  .superRefine((v, ctx) => {
    // instant = dublinLocalToUtcIso(v.date, v.time)
    // when opts.requireFuture and instant <= opts.now  -> issue on ['time'], "Pick a time in the future."
    // when instant > opts.now + 365 days               -> issue on ['date'], "That's more than a year away."
  })
}

export type EventFormValues = z.infer<ReturnType<typeof eventFormSchema>>

export const DEFAULT_TITLES = { training: 'Training', match: 'Match' } as const

/** True when switching type should overwrite the title. */
export function shouldRewriteTitle(current: string, nextType: EventType): boolean

/** Form values → the insert row. Empty notes become null. */
export function toEventInsert(v: EventFormValues, createdBy: string): EventInsert
```

It is a factory rather than a bare schema for two reasons. [S4.2](S4.2-edit-and-cancel-event.md) needs the
future-only rule off when editing an event whose start time is not changing, and the `now` the horizon
rules compare against must be injected rather than read inside the schema — `serverNow()` in the app
([D48](../00-decisions.md)), a fixed `new Date('2026-03-14T12:00:00Z')` in the unit tests. A schema that
calls the clock itself is untestable and trusts the device. Create always calls
`eventFormSchema({ requireFuture: true, now: serverNow() })`. One schema, two callers, one flag.

`notes` stays a non-optional `string` in the form (React Hook Form and uncontrolled textareas dislike
`undefined`) and becomes `null` in `toEventInsert`. That is where AC7 is enforced, and it is unit tested.

The 365-day horizon is a typo guard, not a product rule: it catches `2206` typed for `2026`.
[S4.6](S4.6-recurring-training.md)'s 16-week cap ([D30](../00-decisions.md)) is a separate, tighter rule
and does not replace this one.

### Screens

`src/features/events/` gets:

- `ManageEventsScreen.tsx` — route `/manage`.
- `NewEventScreen.tsx` — route `/manage/event/new`.
- `EventForm.tsx` — the field set, a `mode: 'create' | 'edit'` prop, `defaultValues`, and an
  `onSubmit(values)` callback. [S4.2](S4.2-edit-and-cancel-event.md) mounts this same component inside a
  shadcn `Dialog`. It owns no mutation of its own.
- `EventListRow.tsx` — one row: type badge, title, `formatEventTime(starts_at, 'short')`, location, and a
  `Cancelled` badge when `status = 'cancelled'`. [S4.2](S4.2-edit-and-cancel-event.md) adds the overflow
  menu to this component.

`EventForm` is a React Hook Form form:

```ts
useForm<EventFormValues>({
  resolver: zodResolver(eventFormSchema({ requireFuture, now: serverNow() })),
  defaultValues,
  mode: 'onBlur',
})
```

bound through shadcn's `Form`, `FormField`, `FormItem` and `FormMessage` wrappers, so AC5's messages
render under their own fields with no bespoke error plumbing.

shadcn components only: `Form`, `Input`, `Textarea`, `Label`, `Button`, `Select`, `ToggleGroup`, `Badge`,
`Card`, `Skeleton`, `Sonner` for the success toast. Type is a two-item `ToggleGroup`, not a select — two
options, one tap.

Date and time are native `<Input type="date">` and `<Input type="time">`. The OS wheel beats a web
calendar on a phone and adds no dependency; `type="time"` presents in the device locale but its value is
always 24-hour `HH:mm`, which is what the schema expects. Set `min` on the date input to today's date in
Dublin, from `utcIsoToDublinParts(serverNow().toISOString()).date` — a convenience, with AC6 as the real
check.

`/manage` is a full-nav route, so the fixed bottom nav from [D41](../00-decisions.md) is visible and page
content is bottom-padded to clear it.

### Team selection

The managed teams come from `useCurrentUser()` ([S2.9](S2.9-auth-guard-and-role-context.md)): memberships
with `role = 'manager'`, filtered to `teams.active`. Inactive teams are already invisible to non-admins
([D50](../00-decisions.md)), so the filter matters only for an admin.
[S6.3](S6.3-all-teams-view.md) later widens this list for admins without a second code path.

The selected team lives in a Zustand store, `src/features/teams/manageStore.ts`, holding `selectedTeamId`
only — UI state, never server data, per `CLAUDE.md` section 2. `/manage/event/new` reads `?team=<uuid>`
first, falls back to the store, then to the single managed team. On change it writes both.

**AC8's hard refresh is met by the query parameter in this story, not by the store.** The store is
in-memory until [S6.3](S6.3-all-teams-view.md) adds `persist`, so a hard refresh survives only because
`?team=` is in the URL. S6.3 then deletes the `?team=` read and the persisted store carries AC8 on its
own. Do not persist the store here and do not leave both mechanisms live afterwards.

### Data access

`src/api/events.ts` — all Supabase calls live here, per `CLAUDE.md` section 3.

`eventKeys` is declared in full by [S1.5](S1.5-typed-data-layer-and-shared-helpers.md) in
`src/api/queryKeys.ts`. **Consume it; do not declare a second factory and do not write a literal key**
(S1.5 AC15). This story is the first consumer of the two manager keys, both of which sit under the
`['events']` prefix so a single `invalidateQueries({ queryKey: eventKeys.all })` still reaches everything:

```ts
// src/api/queryKeys.ts — S1.5, imported here, not redeclared
  list:      (teamId: string)   => ['events', 'list', teamId] as const,
  responses: (eventId: string)  => ['events', 'responses', eventId] as const,
```

`eventKeys.list(teamId)` is *the* team event-list key. Any story that talks loosely about
"the `['events', { teamId }]` key" means this one; there is no other.

```ts
// src/api/events.ts
export function useTeamEvents(teamId: string | undefined): UseQueryResult<EventRow[]>
export function useCreateEvent(): UseMutationResult<EventRow, PostgrestError, EventFormValues>
```

`useTeamEvents` selects every column for the team from a cut-off sixty days back, ordered by `starts_at`
ascending, so one query feeds both sections and the list stays bounded without pagination. PostgREST
compares against literal values, not SQL expressions, so the cut-off is computed in the query function and
sent as an ISO string — there is no `now() - interval '60 days'` to send:

```ts
const cutoff = new Date(serverNow().getTime() - 60 * 24 * 60 * 60 * 1000).toISOString()
supabase.from('events')
  .select('*')
  .eq('team_id', teamId)
  .gte('starts_at', cutoff)
  .order('starts_at', { ascending: true })
```

Split in the component against `serverNow()`, not `Date.now()`: Upcoming is `starts_at >= serverNow()`,
ascending; Past is the rest, reversed. Cancelled
events stay in place, badged, never hidden ([D60](../00-decisions.md) and the brief's S3.2 rule applied
to the manager side too).

`useCreateEvent` inserts and returns the row:

```ts
supabase.from('events')
  .insert({ team_id, type, title, location, notes, starts_at, created_by })
  .select()
  .single()
```

`created_by` is set client-side from the session uuid. The RLS insert policy does not check it; it is
audit, not authorisation.

`onSuccess`: `queryClient.invalidateQueries({ queryKey: eventKeys.all })`, then
`navigate('/manage', { replace: true })` and a toast. Every event mutation in Epic 4 invalidates the whole
`eventKeys.all` subtree — at this size, precision buys nothing and risks a stale count.

**Handover to [S4.6](S4.6-recurring-training.md):** `EventForm` is the component S4.6 adds its
"Repeat weekly" `Switch` to, under the type field, with one shared submit path that branches to the
series RPC. Keep the field set in one component so that stays a small change.

**Handover to [S4.3](S4.3-manager-event-view.md):** once the per-event screen exists, the post-create
destination changes to `/manage/event/{id}` so the manager lands where the share button is. Until then,
`/manage`. The toast carries no link before S4.3 ships.

### Error mapping

One exported helper, reused by [S4.2](S4.2-edit-and-cancel-event.md):

```ts
export function eventWriteErrorMessage(error: PostgrestError): string
// 42501            → "You can't add events to that team."
// 23514            → "That doesn't fit. Check the title and location lengths."
// 23503            → "That team no longer exists."
// anything else    → "Couldn't save. Try again."
```

`42501` is what RLS returns for both an unmanaged team and an inactive one ([D50](../00-decisions.md)).
The message does not distinguish them; the manager's fix is the same either way.

## Test plan

- **Unit** — `dublinLocalToUtcIso()` for a GMT instant (January), an IST instant (July), and both DST
  boundaries, all asserted as fixed UTC instants with `TZ=UTC` in the runner ([D53](../00-decisions.md));
  `utcIsoToDublinParts()` round-trips each; `eventFormSchema({ requireFuture: true, now: new Date('2026-03-14T12:00:00Z') })`
  accepts a good payload and rejects each of AC5 and AC6's cases with the exact message, with no reliance
  on the wall clock of the machine running the suite; `shouldRewriteTitle()` across the four combinations;
  `toEventInsert()` maps blank notes to `null`; `eventWriteErrorMessage()` for each code.
- **Integration / RLS** — Covered by [S1.4](S1.4-rls-test-suite.md), which already asserts that a manager
  can insert for a team they manage, cannot insert for another team, cannot insert for an inactive team,
  and that a player cannot insert at all. This story adds no new policy, so it adds no new RLS test. It
  does add one API-level test that `useCreateEvent` surfaces a `42501` as AC9's copy.
- **E2E** — Playwright, against the local stack via `vite preview` ([D17](../00-decisions.md)): sign in as
  a seeded manager, create a training for a fixed future date, assert the row appears on `/manage` with
  the expected Dublin time string, and assert the stored `starts_at` through a service-role read in the
  test helper. The full journey version lives in [S7.3](S7.3-end-to-end-journey.md).
- **Manual** — On a real phone: the date and time fields open the native OS pickers, and the whole form
  is fillable one-thumbed at 375px without zooming.

## Open questions

1. **Should a manager be able to create an event in the past, to back-fill attendance for a session
   nobody logged?** Proposed default, already specified: no. AC6 rejects it. A past event can never take
   a response ([D12](../00-decisions.md)), so creating one is almost always a mis-typed year. If the club
   asks for back-fill later it is a change to one `superRefine` clause and one message.
2. **Should `/manage` page beyond the 60-day past window?** Proposed default: no. Twenty players and two
   fixtures a week is a short list, and [S3.5](S3.5-own-attendance-history.md) covers the player's own
   history. Revisit only if a manager asks.
