## Goal
An admin opens History and sees **every team's** past events — a god view of the whole club's
record — each showing how many players attended and tapping straight through to the manager
attendance record. No empty screen for the membership-less admin.

## Context
The player History (S3.5) reads the viewer's own past events with **their own** attendance embedded.
The admin (0899999001) holds no team memberships, so that personal read is always empty for them —
History loaded but showed nothing. [V14](../00-decisions-v1.1.0.md) makes every admin surface a god
view; History is the last one still personal-only. RLS already returns all events and all attendance
to an admin, so this is UI scoping only — no schema or RLS change.

## Scope
**In**
- For an admin viewer, History reads **all teams'** past events (newest first, 25 a page behind
  "Show more"), via a dedicated `useAdminAttendanceHistory` — the whole squad's attendance embedded
  (no `.eq('attendance.user_id')` filter), so each row derives an **attended count**. No
  `filterHistory` membership narrowing: an admin sees the club, not a team.
- The admin row (`AdminHistoryRow`) is a manage surface: title · attended count (or **Cancelled**) ·
  date · type · **team name**, linking to the **manager event view** (`paths.manageEvent`), not the
  player detail. No personal attendance pill (the admin has none).
- Both hooks are called so the rules of hooks hold; the inactive one is `enabled: false` and never
  fetches. The **player History path is byte-for-byte unchanged**.
- Four states preserved: loading skeleton, inline retry, an "empty" that means "no past events across
  the club", and the populated list with "Show more".

**Out**
- Any write. History is read-only; attendance is recorded from the manager view (S4.5).
- A manager god view — a manager still sees only their own history (they are a squad member).
- Any schema or RLS change (V14 already grants the admin all).

## Acceptance criteria
- [x] **AC1** An admin's History lists past events across **every** active team, newest first — verified live: admin 001 → 2 events across 2 teams; a player → 1 event, own team only.
- [x] **AC2** Each admin row shows the count of players who attended, derived from the full embedded attendance — verified live: newest event embed = 9 rows, 8 attended → row reads "8 attended".
- [x] **AC3** An admin row links to the manager record (`/manage/event/:id`), not the player detail — unit test asserts the `href`.
- [x] **AC4** A cancelled past event shows **Cancelled**, not a count — unit test.
- [x] **AC5** The **player** History path is unchanged: the personal read still filters the embed to the viewer (`.eq('attendance.user_id', userId)`), `filterHistory` still runs, rows still link to the player detail — the player read is `enabled` only when NOT an admin; existing S3.5 tests still pass.
- [x] **AC6** The admin read never fires on the player path (`enabled: false`) and does not write — unit test asserts the disabled query never calls the client; grep confirms no INSERT/UPDATE/UPSERT/DELETE in the read.
- [x] **AC7** Four UI states handled (loading, empty "No past events yet.", inline retry, populated + "Show more") — the shell is shared with the player screen.
