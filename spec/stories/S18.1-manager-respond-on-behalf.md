# S18.1 — Manager records availability on a player's behalf

| **Depends on** | S1.3 (RLS), S4.3/S4.4 (manager event view) |

## Goal
A player texts the manager "I'm in" but never taps the link. From the event's **Who's in** list the
manager sets that player's availability on their behalf (Chris, 2026-09-16 — "just in case there's a need").

## Context
`event_responses` is player-written by design: the table policies let a player insert/update only their own
row (S1.3). Rather than widen those policies (which would let a manager write the table freely), a manager
answers through **one security-definer RPC**, `set_response_for`, mirroring how the squad and reset writes are
done — a single audited entry point, refusals enforced in the DB.

## Scope
**In**
- `set_response_for(event_id, user_id, response)` RPC: allowed only for a manager of the event's team (or an
  admin); the subject must be a member of that team; the window is the same as a player's own (D12) —
  `scheduled` and before kick-off. Any refusal raises `not_authorised`. Idempotent upsert on `(event_id, user_id)`.
- On the manager event screen (S4.3), the availability **pill becomes a menu** — *Mark available / Mark
  unavailable* — for each player, shown only while the event is open. Optimistic (D48): the pill flips at
  once, a refusal rolls back with an inline line.
- The player keeps their own controls; a manager-set value is a starting point the player can still change.

**Out**
- Clearing a response back to awaiting (players can't either, D61). Setting availability after kick-off
  (record attendance then, S4.5). Any bulk "mark everyone available".

## Acceptance criteria
- [x] **AC1** — From the Who's in list a manager sets a player available or unavailable on their behalf.
- [x] **AC2** — The write goes through `set_response_for`; the `event_responses` table policies are unchanged (player-only).
- [x] **AC3** — A non-manager is refused by the RPC (`not_authorised`), not just the UI; verified by the RLS suite.
- [x] **AC4** — The window closes at kick-off and on a cancelled event, in the DB; the UI hides the menu then too.
- [x] **AC5** — Optimistic with rollback and an inline failure line; the counts and roster update in step.

## Implementation
