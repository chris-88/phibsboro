## Goal
A manager can create a **Social** event (club social, team meal, awards night) alongside Training and Match.
Socials behave like training: a title, location, time, notes — no opponent, no home/away, no squad.

## Context
v1.0.0's `event_type` enum is `('training','match')`. [V2](../00-decisions-v1.1.0.md) adds `'social'`,
nullable match fields untouched. This is the smallest Epic 8 story and the enum change other stories build on.

## Scope
**In**
- Migration adding `'social'` to the `event_type` enum (its own migration file — see gotcha).
- The create/edit form (S4.1/S4.2) Type control gains a third option, Social.
- Title default for social (e.g. "Social") mirroring the training default.
- Regenerated `database.types.ts`; the event Zod schema's type union includes `'social'`.

**Out**
- Opponent / home-away / meet time — those are match-only ([S8.2](S8.2-match-details-and-title.md), [S8.3](S8.3-meet-and-kickoff.md)).
- Any social-specific display beyond the type badge.

## Acceptance criteria
- [x] **AC1** — A migration adds `'social'` to `public.event_type`; `node scripts/db.mjs "select enum_range(null::public.event_type)"` returns `{training,match,social}`.
- [x] **AC2** — The New/Edit Event Type control offers Training | Match | Social; selecting Social creates an event with `type='social'`, verified by SQL.
- [x] **AC3** — The event Zod schema and generated types accept `'social'`; typecheck is clean and the union is exhaustive (a `switch` over type has a social branch, no `default` swallow).
- [x] **AC4** — Social events render a Social type badge everywhere a badge shows (home card, lists, detail, manager view), reusing the badge component.
- [x] **AC5** — The migration runs clean on the live database and existing rows are unaffected.

## Implementation notes
- Migration `NNNN_event_type_social.sql`: `alter type public.event_type add value if not exists 'social';`
  **Gotcha:** `ALTER TYPE ... ADD VALUE` cannot be followed by use of the new value in the same transaction.
  Supabase applies each migration file in a transaction, so this must be its own file with nothing that
  uses `'social'`; the form/schema changes are code, not SQL.
- Regenerate types (`npm run db:types`) and update the event schema union in `src/features/events/schema.ts`.
- Badge: extend the existing type→label/variant map; give social its own token colour (not a hardcoded hex).
- Title default: extend the by-type default in the create form (S4.1) — social defaults to "Social".
