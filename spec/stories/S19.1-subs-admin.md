## Context / decisions
Owner brings **subs (fees/membership) into scope** (Y1) — an override of `CLAUDE.md`'s "payments/fees
out of scope" line, the way stats (X1) and team selection (V1) were. The app **tracks** subs and links
out to an admin-set pay link; it never handles money (no processing, no PCI).

- **Y1** — one **club-wide amount** everyone owes, on a singleton `club_settings` row with the pay link.
- **Y2** — **part-payments** recorded by an **admin** into `subs_payments`; a member's outstanding is
  amount − total paid, derived, never stored.
- **Y3** — reads are RLS-scoped: a player their own, a manager their teams' members, an admin all.
- **Y4** — the reminder is an auto player modal + a manager nudge (S19.3, later slices).

## Scope (this slice)
**In**
- `club_settings` (singleton; everyone reads, admin updates) and `subs_payments` (admin writes; own /
  manager / admin reads) with RLS.
- API: `useClubSettings` / `useUpdateClubSettings`, `useSubsPayments`, `useRecordSubsPayment`,
  `useDeleteSubsPayment`; pure `buildSubsRows` / `summariseSubs` / `mySubs` / `formatMoney`.
- **Admin desk** `/admin/subs`: set the amount + pay link; a summary (collected / outstanding / paid-up);
  the full membership with each member's paid + outstanding; record and undo part-payments.

**Out (later slices)**
- The player's profile card + the pay button (S19.2). The auto reminder modal + manager nudge (S19.3).
  The manager team view (S19.4).

## Acceptance criteria
- [x] **AC1** — An admin sets the club-wide amount and pay link.
- [x] **AC2** — An admin records and undoes part-payments; outstanding = amount − paid, clamped at zero.
