## Goal

A manager can copy their squad's join link and paste it into the team WhatsApp group, so players add
themselves with no manual user creation. An admin can additionally mint a single-use link that grants
the manager role. Either link can be revoked the moment it leaks, and regenerated.

## Context

The brief's S6.2 bundles link lifecycle with member administration.
[D20](../00-decisions.md) splits them: this story is generate, revoke and regenerate, and the player and
manager variants. Member administration is [S6.4](S6.4-member-administration.md). The split exists
because this half blocks Epic 2 — registration has nothing to test against without a token — while the
other half depends on Epic 2 being finished.

Decisions this story rests on:

- [D28](../00-decisions.md) — the **player link** is multi-use, expires 90 days after issue, and there is
  at most one active player link per team. The **manager link** is single-use, expires after 24 hours, is
  issuable only by an admin, and is consumed on the first successful join. A partial unique index on
  `(team_id, role) where active` enforces one live link per team per role.
- [D29](../00-decisions.md) — the write path is `create_team_invite(p_team_id, p_role)` and
  `revoke_team_invite(p_team_id, p_role)`. Clients never insert or update `team_invites`.
- [D5](../00-decisions.md) — a token is 32 bytes from `gen_random_bytes(32)`, base64url, generated inside
  the RPC and never client-side.
- [D62](../00-decisions.md) — tokens are stored in plaintext in a table no client can select, and are
  never logged, never sent to Sentry, and never put in a query string the app constructs. Hashing was
  rejected precisely because a manager must be able to **re-copy** a live link at any time.
- [D16](../00-decisions.md) — Sentry truncates anything after `/#/join/` in URLs and transaction names.
- [D34](../00-decisions.md) — `/join/:token` and `/manage/team/:teamId/members` are routes of record.
- [D49](../00-decisions.md) — a squad with no members shows the join-link share button.

D62 requires re-copying a live link, but `spec/data-model.md` lists no read path for one:
`lookup_team_invite` takes a token you already hold, and `create_team_invite` returns a token only at the
moment it mints one. That gap is closed by `get_team_invite`, specified below and raised as Open
question 1.

The invite-token gate on registration is a **UX gate on membership, never on account creation**
([D37](../00-decisions.md)). Anyone holding the public anon key can call `auth.signUp` directly. Nothing
in this story may be described, or designed around, as a boundary on who can have an account. The
boundary is on who ends up in `team_members`.

## Scope

**In**

- The `/manage/team/:teamId/members` route, created here with the join-link panel. The member list is
  added to the same screen by [S6.4](S6.4-member-administration.md).
- Squad join link panel: show the live link, create one when there is none, regenerate, revoke.
- Manager join link panel, rendered only for an admin, with its own copy about single use and 24 hours.
- `copyText()` in `src/lib/clipboard.ts`, the codebase's only clipboard helper, with a fallback that
  works when the Clipboard API is unavailable or refused.
- The copy field's URL, built with `joinUrl(token)` from `src/lib/paths.ts` ([S0.3](S0.3-routing.md)).
  No new URL module: S0.3 AC8 permits the `/#/` literal in `src/lib/paths.ts` alone, and S1.5 AC6 permits
  `import.meta.env` in `src/lib/env.ts` alone.
- Hooks in `src/api/invites.ts`.
- An entry point: the `/admin` team row from S6.1 links to this screen.

**Out**

- A share sheet or a `wa.me` hand-off for join links. Copy is the action.
  [S5.2](S5.2-share-action.md) owns sharing, and what it shares is events. A manager copies the link once
  a season and pastes it; a second sharing mechanism for a second kind of payload is not worth the
  surface.
- Redeeming a link. `/#/join/:token` is [S2.4](S2.4-join-by-link.md).
- Any per-invite analytics: no use count, no "who joined with this link", no last-used timestamp.
  Nothing reads them and the table has no columns for them.
- Emailing, texting or otherwise sending the link. The app never sends a message.
- Inviting a specific person by number. Links are per team and per role, never per person.
- Creating an account for someone. The brief's "No manual user creation" is literal: no form anywhere in
  this story takes a name, a number or a password. People exist because they registered
  ([S2.1](S2.1-registration.md)).
- Granting admin. Not grantable through the app at all ([D2](../00-decisions.md)).

## Acceptance criteria

Each criterion is independently checkable by a person or a test.

- [ ] **AC1** — `/#/manage/team/{teamId}/members` renders the squad join link panel for a manager of that
      team and for an admin. A player of that team is redirected to `/` (convenience); the enforcement is
      that `create_team_invite` and `revoke_team_invite` raise `not_authorised` for them and
      `get_team_invite` returns zero rows (S1.4).
- [ ] **AC2** — With no live player link, the panel shows its empty state and a single primary button,
      "Create join link". Tapping it calls `create_team_invite(teamId, 'player')` and the panel switches
      to the populated state showing the full URL.
- [ ] **AC3** — The URL rendered and copied is exactly
      `` `${env.VITE_APP_BASE_URL}/#/join/${token}` ``, built by `joinUrl(token)` from `@/lib/paths`
      ([S0.3](S0.3-routing.md) AC9). No string concatenation at the call site, no `/#/` literal in this
      feature, and no `import.meta.env` read outside `src/lib/env.ts`. Checked by
      `scripts/check-conventions.mjs` (S0.3 AC8), which already fails the build on either.
- [ ] **AC4** — Tapping Copy writes that exact string to the clipboard and shows a transient "Copied"
      confirmation. When `navigator.clipboard` is missing or rejects, the panel falls back to a readonly
      input with its text selected and the line "Copy this link", and throws nothing.
- [ ] **AC5** — The populated panel states the expiry as `formatEventTime(expires_at, 'short')` and
      carries one line saying anyone with the link can join as a player. No ad-hoc date formatting.
- [ ] **AC6** — Regenerate is confirmed first, and the confirmation says in one line that the old link
      stops working immediately, including links already sitting in WhatsApp. On confirm, a new token is
      shown, the old one returns zero rows from `lookup_team_invite`, and exactly one `team_invites` row
      for `(team_id, 'player')` has `active = true`.
- [ ] **AC7** — Revoke is confirmed, sets `active = false`, and returns the panel to its empty state.
      The revoked token returns zero rows from `lookup_team_invite` on the very next call, with no
      grace period. Members who already joined with that link keep their membership: the `team_members`
      count is unchanged.
- [ ] **AC8** — The manager link panel renders only when `useCurrentUser().isAdmin`. A manager never sees
      it, and a manager calling `create_team_invite(teamId, 'manager')` raises `not_authorised` (S1.4).
- [ ] **AC9** — The manager link panel states, in two short lines, that the link is single use, expires in
      24 hours, and should be sent to one person rather than pasted into the squad group.
- [ ] **AC10** — For an inactive team the panel is read-only: create, regenerate and revoke are disabled
      with the line "Reactivate this team to issue join links", and the RPC refuses as well
      (Open question 2).
- [ ] **AC11** — Tokens never reach the console, Sentry or any analytics. Checked by
      [S0.6](S0.6-observability.md) AC8 — `scrubString()` truncates `/#/join/<token>` to `/#/join/` in
      messages, breadcrumbs, URLs and transaction names — and by a grep gate in this story's PR:
      `grep -rn "console\.\|captureMessage" src/features/teams src/api/invites.ts` returns nothing.
- [ ] **AC12** — The TanStack Query cache holding tokens is memory-only. No query persister is installed,
      and no token is written to `localStorage`, `sessionStorage` or IndexedDB.
- [ ] **AC13** — All four UI states are handled for both panels, per the table below.
- [ ] **AC14** — At 375px the URL wraps rather than scrolling the page horizontally, and every button is
      at least 44px tall.
- [ ] **AC15** — Each row of the S6.1 `/#/admin` teams list carries a link to
      `paths.teamMembers(team.id)`, so an admin reaches this screen without typing a URL. That link is
      this story's only edit to `AdminTeamsScreen.tsx`; the manage-view link on the same row is
      [S6.3](S6.3-all-teams-view.md)'s.

## Implementation notes

### The invite read path, owned by S1.3

`get_team_invite` is the read path D62 assumes. It is now the fourteenth RPC in
[data-model.md](../data-model.md), specified below, implemented in [S1.3](S1.3-rls-policies-and-rpcs.md)'s
migration under its AC26, and covered positively and negatively by
[S1.4](S1.4-rls-test-suite.md) matrix row 31a:

```sql
create or replace function public.get_team_invite(
  p_team_id uuid,
  p_role    public.member_role
)
returns table (token text, role public.member_role, expires_at timestamptz, created_at timestamptz)
language sql
security definer
stable
set search_path = ''
as $$
  select i.token, i.role, i.expires_at, i.created_at
  from public.team_invites i
  where i.team_id = p_team_id
    and i.role    = p_role
    and i.active
    and (i.expires_at is null or i.expires_at > now())
    and (
         (p_role = 'player'  and public.is_team_manager(p_team_id))
      or (p_role = 'manager' and public.is_admin())
    );
$$;

revoke execute on function public.get_team_invite(uuid, public.member_role) from public;
grant  execute on function public.get_team_invite(uuid, public.member_role) to authenticated;
```

It follows the lookup convention from `data-model.md`: zero rows on every failure, including an
unauthorised caller, so nothing can be probed by comparing errors.

### URLs

The builder already exists. [S0.3](S0.3-routing.md) owns `src/lib/paths.ts`:

```ts
// src/lib/paths.ts — S0.3, imported here, not redeclared
export function absoluteUrl(path: string): string      // throws when VITE_APP_BASE_URL is empty
export const joinUrl  = (token: string): string => absoluteUrl(paths.join(token))
export const eventUrl = (id: string): string    => absoluteUrl(paths.event(id))
export const resetUrl = (token: string): string => absoluteUrl(paths.reset(token))
```

Import `joinUrl` and `paths` from `@/lib/paths`. Do not add `src/lib/urls.ts`:
[A8](../00-decisions.md) settles the three builders into one module, `absoluteUrl` reads the one env
constant through `src/lib/env.ts` (S1.5 AC6), and a second home would break the `/#/` convention check.

### Hooks

```ts
// src/api/invites.ts
export function useTeamInvite(teamId: string, role: MemberRole): UseQueryResult<TeamInvite | null>
export function useCreateTeamInvite(teamId: string): UseMutationResult<string, PostgrestError, MemberRole>
export function useRevokeTeamInvite(teamId: string): UseMutationResult<void, PostgrestError, MemberRole>
```

`useTeamInvite` calls `supabase.rpc('get_team_invite', { p_team_id, p_role }).maybeSingle()` and parses
the result with `teamInviteSchema`. Set `staleTime: 0` and `gcTime: 60_000`: a revoked token should not
linger in the cache behind a back navigation.

Regenerate is not a third mutation. `create_team_invite` deactivates the live row and inserts the
replacement in one transaction ([D29](../00-decisions.md)), so regenerate calls `useCreateTeamInvite` and
only the button label and the confirmation copy differ.

The query key already exists: `teamKeys.invite(teamId, role)` in `src/api/queryKeys.ts`, declared by
[S1.5](S1.5-typed-data-layer-and-shared-helpers.md) and first consumed here. It nests under the
`teamKeys.detail(teamId)` prefix so one invalidation clears both invite roles:

```ts
// src/api/queryKeys.ts — S1.5, imported here, not redeclared
  invite: (teamId: string, role: Enums<'member_role'>) => ['teams', teamId, 'invite', role] as const,
```

Every mutation invalidates `teamKeys.invite(teamId, role)`. No optimistic update: there is no plausible
token to show before the server mints one.

### Error mapping

`toAppError(error)` from `src/lib/errors.ts` ([S1.5](S1.5-typed-data-layer-and-shared-helpers.md))
classifies the `PostgrestError` into an `AppErrorCode`. The panel overrides the copy for the one code it
can say something more useful about, and falls through to `mapRpcError()` for everything else:

```ts
// src/features/teams/components/JoinLinkPanel.tsx
const copyFor = (code: AppErrorCode, role: MemberRole): string =>
  code !== 'not_authorised'  ? mapRpcError(code)                      // "Something went wrong. Try again."
  : role === 'manager'       ? 'Only an admin can create a manager link.'
  :                            "You can't manage this team."
```

The message is rendered inline in the panel with a Retry button, never as a toast and never as raw
Postgres text.

### Panel

One `JoinLinkPanel` component taking `role: MemberRole`, so the manager variant is a second instance and
not a second component. It differs only in its heading, its explanatory lines and its gate.
shadcn: `Card`, `Button`, `Input` (readonly, for the fallback), `AlertDialog`, `Skeleton`, `Alert`,
`Badge`.

Copy implementation. There is **one** clipboard helper in the codebase and this story creates it,
because this is the first screen that needs one. `CopyLinkField` calls it; so do
[S2.3](S2.3-password-reset-by-manager.md), [S5.2](S5.2-share-action.md),
[S6.4](S6.4-member-administration.md) and [S2.7](S2.7-escape-the-whatsapp-browser.md), which describes
its webview behaviour in detail:

```ts
// src/lib/clipboard.ts
export async function copyText(text: string): Promise<boolean> {
  try {
    if (navigator.clipboard?.writeText) { await navigator.clipboard.writeText(text); return true }
  } catch { /* fall through */ }
  return false
}
```

A `false` return switches the field to the select-it-yourself fallback and focuses it. Do not assume a
secure context: the manager may be standing in an in-app webview.

### Gotchas

- Render the URL in a `break-all` container. A 43-character token plus the origin overflows 375px
  otherwise, and S4.4's no-horizontal-scroll rule is the house standard.
- The token is 43 characters: 32 bytes base64url encoded without padding. Assert the shape in the
  integration test rather than the length alone: `/^[A-Za-z0-9_-]{43}$/`.
- An admin who is not a member of the team still passes `is_team_manager`, which is
  `is_admin() or ...`. Do not add a membership check in the UI.
- `expires_at` is nullable in the schema. The player link always has one, but render defensively: a null
  expiry shows "No expiry" rather than "Invalid Date".

## Test plan

- **Unit** — Vitest + RTL. `joinUrl('abc')` from `@/lib/paths` equals `` `${base}/#/join/abc` `` and
  contains exactly one `/#/` (the builder's own tests are S0.3's; this asserts the panel renders that
  string and no other). `teamInviteSchema` rejects a row with a `role` of `admin`. Panel rendering: the manager panel is
  absent for a non-admin; the empty, loading, error and populated states each render their specified
  content; regenerate fires no mutation until the dialog is confirmed; a rejecting
  `navigator.clipboard.writeText` falls back to the selectable field and shows no error boundary. Expiry
  renders through `formatEventTime`, asserted against a fixed UTC instant with `TZ=UTC`
  ([D53](../00-decisions.md)).
- **Integration / RLS** — extends `tests/rls/invites.spec.ts` from S1.4:
  - manager of the team creates a player invite; the returned token matches `/^[A-Za-z0-9_-]{43}$/`
  - `get_team_invite` returns that token to the manager and to an admin, and zero rows to a player of the
    team, to a manager of another team, and to the no-team role from D37
  - manager calling `create_team_invite(team, 'manager')` raises `not_authorised`
  - admin creates a manager invite; `expires_at` is within 24 hours; a player invite's is within 90 days
  - creating twice leaves exactly one `active` row for `(team_id, role)` and the first token now returns
    zero rows from `lookup_team_invite`
  - `revoke_team_invite` makes `lookup_team_invite` return zero rows while `team_members` is unchanged
  - a direct `select` on `team_invites` as every role returns zero rows
  - create and revoke against an inactive team both raise (Open question 2)
- **E2E** — none here. The generated token is consumed by [S2.4](S2.4-join-by-link.md)'s Playwright test.
- **Manual** — on a real iPhone in Safari: create a link, copy it, paste it into WhatsApp, confirm the
  whole URL arrived including the fragment. Repeated on Android Chrome. This is step 19 of
  [S7.4](S7.4-device-pass.md)'s checklist, and its AC17.

## Open questions

1. **Should `create_team_invite` refuse on an inactive team?** `lookup_team_invite` already checks
   `teams.active`, so a link minted for an inactive team resolves to nothing and the manager is handed a
   dead URL with no explanation. Proposed default: add `teams.active` to the authorisation check in
   `create_team_invite`, raising `not_authorised`, and disable the control in the UI with the AC10 line.
   Revoke stays permitted on an inactive team so a leaked link can always be killed.
2. **Should regenerating be offered at all, given revoke plus create does the same?** Proposed default:
   yes, as one button. Revoke-then-create is two confirmations and leaves a window with no live link, and
   the RPC already does both in one transaction.
3. **What happens to a manager link that is never used?** Proposed default: nothing. It expires after 24
   hours and `lookup_team_invite` stops resolving it. No cleanup job, no expiry sweep — the rows are tiny
   and the partial unique index only counts `active` ones.
