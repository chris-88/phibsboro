|---|---|

## Goal
A manager can reach their squad in one tap. The bottom nav gains a **Squad** tab that opens the managed
team's member list, where the reset / remove / change-role actions already live — fixing the v1.0.0 gap
where that screen was only reachable through an event.

## Context
[V11](../00-decisions-v1.1.0.md): `navItemsForRole` gains Squad for managers (and admins keep Admin). The
target is the existing S6.4 team-members screen (`/manage/team/:teamId/members`), already guarded `'manager'`.
A manager of more than one team uses the active-team selector (as the Manage screen does).

## Scope
**In**
- `navItemsForRole` adds a Squad item for managers: Home | History | Manage | **Squad**. Admins keep Home |
  History | Manage | Admin (they reach members via Admin — avoid a 5th tab, [Q4](../00-decisions-v1.1.0.md)).
- A `/squad` route that resolves the manager's active/managed team and renders the S6.4 team-members screen
  for it (reuse the active-team hook; if they manage several, show the team selector then the members).
- The nav highlight and the four states inherited from the members screen.

**Out**
- Any change to the member actions themselves (S6.4 already built them).
- A player-facing squad view (players have no such tab).

## Acceptance criteria
- [ ] **AC1** — A manager's bottom nav shows Home | History | Manage | Squad; a player's shows only Home | History; an admin's shows Home | History | Manage | Admin (no Squad, to avoid five tabs — or Squad replaces Admin per Q4, decided at build).
- [ ] **AC2** — Tapping Squad opens the managed team's member list with the reset / remove / change-role actions (the S6.4 screen), in one tap, without going through an event.
- [ ] **AC3** — A manager of more than one team sees a team selector on Squad (reusing the Manage active-team mechanism) and the members of the chosen team.
- [ ] **AC4** — A player navigating to `/squad` is redirected (guard `'manager'`); RLS still bounds what any member list can read/write.
- [ ] **AC5** — The four states (loading, empty squad, error, populated) come through from the members screen; Squad is highlighted when active.
- [ ] **AC6** — 375px, 44px targets; four tabs fit without crowding.

## Implementation notes
- `src/lib/nav.ts`: add the Squad item under the manager/admin branch per Q4. Icon from lucide (e.g. Users).
- `paths.squad()` → `/squad`; the route (guard `'manager'`) resolves the active managed team (reuse
  `useActiveTeam`/`managedTeams` from S2.9/S4.x) and renders the S6.4 `team-members-screen` for that teamId,
  or a team picker first when `managedTeams.length > 1`.
- No new data. No new screen — a thin route wrapper around the existing members screen.

## Data and API surface
None new. Reuses `useCurrentUser` managedTeams and the S6.4 members screen/hooks.

## UI states

|---|---|---|---|---|
| `/squad` | members skeleton (S6.4) | "No members yet." (S6.4) | error card (S6.4) | the managed team's member list + row actions |

- **Integration** — a manager reaches the members screen via the tab; a player is redirected.
- **Manual** — as a manager, tap Squad, issue a reset link — the flow Chris flagged as unreachable now works in one tap.
