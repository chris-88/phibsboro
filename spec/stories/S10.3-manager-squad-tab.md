## Goal
A manager gets a **Squad** tab that is their squad hub: upcoming matches to pick a squad for at the top, and
the team roster (reset / remove / change-role) below — so both the matchday XI and the member actions are one
tap away.

## Context
[V11](../00-decisions-v1.1.0.md) and [V12](../00-decisions-v1.1.0.md): the Squad tab holds **Matchday** (the
managed team's upcoming matches, each opening the squad picker) on top and **Members** (the existing S6.4
roster actions) below. It is built **before** Epic 9 so the picker (S9.2) has a home. This story builds the
tab, the members section (reusing S6.4), and the matchday match-list with entry points; S9.2 fills in the
actual picker and share.

## Scope
**In**
- `navItemsForRole` adds a **Squad** item for managers: Home | History | Manage | Squad. Admins keep Home |
  History | Manage | Admin (no 5th tab — [Q4](../00-decisions-v1.1.0.md)); an admin managing a team is a
  documented edge (default: admins use Admin → members and reach matchday via the match view).
- `paths.squad()` → `/squad` (guard `'manager'`), rendering a Squad screen with two sections:
  - **Matchday** (top): the managed team's upcoming **matches** (type='match', future), each as a row showing
    the fixture, KO/Meet and a squad-status hint ("Squad not picked" / "18 picked"), linking to the squad
    picker route for that event (the picker is [S9.2](S9.2-squad-selection-screen.md); until S9.2 lands the
    link target is the match manager view).
  - **Members** (below): the existing S6.4 team-members list with reset / remove / change-role, unchanged.
- A team selector when the manager manages more than one team (reuse the Manage active-team mechanism); both
  sections follow the selected team.
- Four states for each section (loading, empty, error, populated) via the shared components.

**Out**
- The squad **picker** UI and its writes — that is [S9.2](S9.2-squad-selection-screen.md).
- Non-manager access (players have no Squad tab).

## Acceptance criteria
- [ ] **AC1** — A manager's bottom nav shows Home | History | Manage | Squad; a player's shows Home | History only; an admin's shows Home | History | Manage | Admin (no Squad).
- [ ] **AC2** — `/squad` shows a Matchday section listing the managed team's upcoming matches (future, type='match'), newest-relevant first, each with the fixture + KO/Meet and a squad-status hint, and a Members section with the S6.4 reset / remove / change-role actions.
- [ ] **AC3** — Tapping a match in Matchday navigates to that event's squad picker route (the S9.2 target; before S9.2, to the match manager view) — verified by the link target.
- [ ] **AC4** — Training and social do **not** appear in Matchday (matchday squads are for matches only).
- [ ] **AC5** — A manager of more than one team gets a team selector; both sections reflect the chosen team.
- [ ] **AC6** — A player navigating to `/squad` is redirected (guard `'manager'`); RLS still bounds every read/write the sections make.
- [ ] **AC7** — Four states per section; Squad is highlighted when active; 375px, 44px targets; four tabs fit without crowding.

## Implementation notes
- `src/lib/nav.ts`: add Squad under the manager (not admin) branch per Q4; lucide `Users` icon.
- `paths.squad()` → `/squad`; route guard `'manager'`. New `src/features/teams/squad-screen.tsx` composing:
  a `MatchdayList` (reads the managed team's upcoming matches — reuse the events hook, filter type='match' &
  future) and the existing S6.4 `team-members-screen` content (extract its list into a component if needed so
  it can be embedded, rather than duplicated).
- Team selection reuses `useActiveTeam`/`managedTeams` (S2.9/S4.x).
- The squad-status hint reads `useEventSquad` once it exists (S9.1); until then show "Squad" with no count —
  record that as a deviation to fill when S9.1/S9.2 land, or build S10.3 to read an empty squad gracefully.

## Data and API surface
Reads: the managed team's upcoming matches (events hook), the members directory (S6.4), and (once available)
`useEventSquad` for the hint. No new tables. Reuses S6.4 mutations for the member actions.
