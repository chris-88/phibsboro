## Goal
A reusable `Avatar` that shows a user's photo or a coloured initials fallback, and an upload flow that lets a
user set/replace/remove their own photo.

## Context
[W9/W10](../00-decisions-v1.2.0.md). The avatar appears in the header (S16.3) and on the profile; the upload
lives on the profile. Photos are downscaled in the browser before upload to keep them small.

## Scope
**In**
- `Avatar` component: given `avatarPath` + `name` + size, render `<img>` from the public URL, else a coloured
  circle with the name's initials. Decoding/`alt` handled; broken image falls back to initials.
- `useSetAvatar` (upload) and `useClearAvatar` mutations: pick an image → downscale to ~512px square (canvas)
  → upload to `avatars/{uid}/{ts}.jpg` → `set_own_avatar(path)`; clear removes the row's path (and optionally
  deletes the object). Invalidate the current-user read so the header avatar updates.
- Handles: too-large/invalid file (reject with a message), upload failure (inline error, keeps the old
  photo), and a busy state on the control.

**Out**
- The profile screen layout (S16.3). Cropping UI (a simple centre-crop on downscale is enough).

## Acceptance criteria
- [ ] **AC1** — With a photo set, the avatar renders it; with none, it renders initials on a coloured circle.
- [ ] **AC2** — Selecting an image uploads a downscaled version and sets `avatar_path`; the header/profile avatar updates without a reload.
- [ ] **AC3** — Remove clears the photo back to initials.
- [ ] **AC4** — An invalid/oversized file is rejected with a message; an upload error keeps the previous photo and shows an inline retry.
- [ ] **AC5** — A broken image URL falls back to initials rather than a broken-image icon.

## Implementation notes
- `src/features/profile/` — `Avatar`, `useSetAvatar`/`useClearAvatar` (in `src/api/avatar.ts`), a small
  `downscaleImage(file, 512)` canvas helper (unit-tested for output size/type).
- Public URL from the path (one helper); no signed URLs. `current-user` read carries `avatar_path`.
- Initials: first letters of the name (1–2), deterministic muted background.

## Data and API surface
Upload via Storage + `set_own_avatar` (S16.1). Reads `avatar_path` from the current-user query.

## UI states
| Screen | Loading | Empty | Error | Populated |
|---|---|---|---|---|
| Avatar / upload control | uploading (busy) | initials fallback | inline "couldn't upload", old photo kept | the photo |

## Test plan

  mutation uploads then calls `set_own_avatar`.
- **Manual** — set/replace/remove a photo on a phone.
