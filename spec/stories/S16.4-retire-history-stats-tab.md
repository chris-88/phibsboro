## Goal
The History tab is gone and a disabled **Stats** tab sits in its slot — a visible signpost that a richer
stats surface is coming, not yet selectable.

## Context
[W8](../00-decisions-v1.2.0.md). The calendar Home covers reverse-chronology; stats get their own future
epic. The profile (S16.3) already carries what a user needs day-to-day, so History leaves no gap now.

## Scope
**In**
- Remove the `History` nav item and add a `Stats` item in the same position, marked **disabled**: rendered
  greyed, `aria-disabled`, not a link, no navigation on tap (a "coming soon" affordance, optional tooltip).
- Remove the `/history` route and `HistoryScreen`; remove the admin god-view history (`useAdminAttendanceHistory`,
  `AdminHistoryRow`) retired with the tab. Keep `useAttendanceHistory`/`HistoryRow` only if the future Stats
  work will reuse them; otherwise remove and note they return with the Stats epic.
- Update the route table, `navItemsForRole`, the intended-route allowlist, and their tests.

**Out**
- Any real Stats screen/data (the later Stats epic). A route for `/stats` (the tab does not navigate yet).

## Acceptance criteria
- [ ] **AC1** — The bottom nav shows **Stats** where History was, greyed and non-interactive; tapping it does nothing and it is `aria-disabled`.
- [ ] **AC2** — `/history` no longer resolves (falls through to 404); no nav item links to it.
- [ ] **AC3** — The admin god-view history is gone; the calendar still shows past events.
- [ ] **AC4** — Route-table / allowlist / nav tests updated and green; no dead imports.

## Implementation notes
- `navItemsForRole` (`src/lib/nav.ts`) gains a `disabled?: boolean` on the item; `BottomNav` renders a
  disabled item as a non-link (a `span`/`button[disabled]`) with muted styling, keeping the 44px target.
- Removing `/history` touches `routes.tsx`, `routes.test.tsx`, `intended-route.ts` + its drift test.

## Data and API surface
None (removal). Any now-unused history hooks/components deleted.
