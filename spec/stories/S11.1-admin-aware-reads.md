# S11.1 — Admin-aware reads and widened pickers

| | |
|---|---|
| **Epic** | 11 — Admin god mode (v1.1.0) |
| **Status** | Not started |
| **Depends on** | S2.9 (useCurrentUser), S1.5, S4.1, S6.3, S9.2, S10.2 |
| **Blocks** | [S11.2](S11.2-admin-home-all-teams.md) |
| **Size** | M |
| **Risk** | medium — the event reads and pickers are read across the app; scoping must change for admins without leaking anything (RLS is the backstop) and without changing player behaviour |

## Goal
An admin's screens surface every team, matching the full access RLS already grants: the event reads include
all active teams, and every team picker offers all teams — so an admin can see and act anywhere.

## Context
[V14](../00-decisions-v1.1.0.md): the data layer is already god mode (RLS), but the UI scopes to membership.
This story makes the reads and pickers admin-aware. Players are unaffected.

## Scope
**In**
- The event reads (`useMonthEvents`, `useUpcomingEvents`, and any team-scoped events read) stop filtering by
  the viewer's `teamIds` when the viewer is an admin — they read across all active teams (RLS scopes the
  rest; for an admin that is everything). For a player they keep the membership filter exactly as now.
- The team pickers widen for an admin to every **active** team: create-event team select (S4.1), the Squad
  tab team selector (S10.3), squad-picker access (S9.2), member admin (S6.4). `managedTeams` / a new
  `administrableTeams` on `useCurrentUser` exposes "all active teams" for an admin vs memberships for others.
- A single source of truth for "which teams can this viewer act on" so the widening is not re-derived per
  screen.

**Out**
- The admin Home all-teams calendar UI ([S11.2](S11.2-admin-home-all-teams.md)) — this story is the data/hook
  layer plus the pickers.
- Any RLS or schema change (none — RLS already permits it).

## Acceptance criteria
- [ ] **AC1** — For an admin, `useMonthEvents`/`useUpcomingEvents` return **every active team's** events for the window (verified against the live project as the seeded admin, who has no memberships, now sees both teams' events); for a player they return only their teams' events (unchanged), verified.
- [ ] **AC2** — `useCurrentUser` exposes the set of teams a viewer can administer: all active teams for an admin, `managedTeams` (memberships) otherwise; one helper, used everywhere a picker widens.
- [ ] **AC3** — The create-event team select, the Squad-tab team selector, the squad picker and member admin all offer every active team for an admin, and only the manager's own teams for a manager — asserted by tests.
- [ ] **AC4** — An **inactive** team is excluded from the admin's reads and pickers (D50 — inactive teams stay invisible to normal flows); an admin still administers inactive teams through the Admin screen (S6.1/S6.3), not the everyday pickers.
- [ ] **AC5** — No membership is inferred as permission anywhere; the widening reads `is_admin` from `useCurrentUser`, and RLS remains the enforcement layer (a comment says so). A player's reads and pickers are byte-for-byte unchanged.
- [ ] **AC6** — `test:rls` stays green; the reads still return nothing for a signed-out or cross-team **player** (RLS), proving the client change did not widen anyone but admins.

## Implementation notes
- `src/api/events.ts`: the month/upcoming reads take the viewer. For an admin, drop `.in('team_id', teamIds)`
  and the `enabled: teamIds.length > 0` guard (enable unconditionally, RLS returns all); for a player keep
  both. Read `is_admin` from `useCurrentUser` at the hook call site or pass it in. Do NOT rely on
  `teamIds.length` for the admin's empty-state (they have events without memberships).
- `useCurrentUser`: add `administrableTeams` (or a boolean `seesAllTeams` + a resolved team list). It needs
  the full active-teams list for an admin — reuse the existing `useTeams` read (active only) rather than a
  new query.
- Every picker that currently reads `managedTeams` switches to the new helper. Grep for `managedTeams` to
  find them.

## Data and API surface
No schema/RLS change. `useCurrentUser` gains an administrable-teams helper. The event hooks become
viewer-aware. Reuses `useTeams`.

## UI states
Not a new screen. The pickers gain more options for an admin; their existing states are unchanged.

## Test plan
- **Unit** — the events hook filters by teamIds for a player and not for an admin; `administrableTeams` = all active teams for admin, memberships otherwise; a picker renders all teams for admin, own for manager.
- **Integration / RLS** — as the seeded admin, the month read returns both teams' events; as a seeded player, only their team's; `test:rls` green.
- **Manual** — sign in as the admin (0899999001) and confirm events from teams you're not a member of are readable/reachable.
