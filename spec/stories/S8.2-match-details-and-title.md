## Goal
When a manager creates a **match**, they enter the **opponent** and pick **home** or **away** instead of
typing a title. The title generates automatically — home → "Firsts v Kilbarrack", away → "Kilbarrack v
Firsts" — and is stored, so everything that shows a title keeps working.

## Context
[V3](../00-decisions-v1.1.0.md): opponent + home/away are stored on `events` and the title is derived and
stored in `events.title`. Home team first (football convention). Training/social keep the typed/defaulted
title from v1.0.0.

## Scope
**In**
- `events.opponent` (text, null) and `events.home_away` (enum home|away, null), match-only, via migration.
- Match branch of the create/edit form: opponent field + home/away toggle; the Title field is replaced by a
  read-only generated preview for matches.
- A pure `matchTitle({ teamName, opponent, homeAway, sep })` generator; `sep` is `'v'` on screen, `'vs'` in
  the share (S9.3). Title stored on submit.
- Event detail (S3.3) and the manager view show the generated title and a Home/Away indicator.

**Out**
- Meet/kick-off times ([S8.3](S8.3-meet-and-kickoff.md)) and the Bogies location default ([S8.4](S8.4-location-maps-and-home-default.md)).
- The share rewrite ([S9.3](S9.3-match-share-rewrite.md)) — this story keeps the existing share working with the new title.

## Implementation notes
- Two migrations or one (opponent+home_away can share a file; the enum `home_away` is a normal type add, no
  same-transaction-use restriction since it is not `event_type`).
- `src/features/events/match-title.ts` — pure generator, exhaustively tested; the only place titles are
  built. The form calls it for the preview and on submit.
- Form: conditional fields by `type`. RHF + zod; the event schema gains `opponent`/`homeAway`, required when
  `type==='match'`, forbidden otherwise (zod refinement). Title becomes derived (not a user field) for match.
- Store the generated title in `title` so S3.1/S3.2/S5.1/calendar need no change; also store the raw fields.
- Home/Away label component reused by detail, manager view and (later) the calendar day list.

## Data and API surface

generator. Regenerated types.
