## Goal

After a player answers their first Yes or No in a real browser, they are shown, once, how to put the app
on their home screen: a real Install button on Android Chrome, three illustrated steps on iOS Safari.
Next time there is no WhatsApp link and no browser, just an icon.

## Context

Twenty-eighth in the build order (D20), immediately after
[S2.7](S2.7-escape-the-whatsapp-browser.md), which builds the install-context provider, the
post-response trigger, the exclusivity gate and the dismissal helpers. This story fills the second branch
of that gate. It writes no detection logic of its own.

Decisions this story rests on, from [00-decisions.md](../00-decisions.md):

- **D46** — the two prompts are ordered and mutually exclusive. Inside an in-app webview the player gets
  S2.7's escape prompt and never this guide, because installing from that webview is impossible and the
  copy would be a lie. This guide appears only when the context is `ios-safari` or `installable`.
  Dismissal lives in `localStorage` under `pfc.installGuideDismissed`, is per browser, and deliberately
  does not follow a player from the WhatsApp webview into Safari — the first thing they see in Safari,
  after signing in again, should be the guide.
- **D45** — on Android, classification is by whether `beforeinstallprompt` fires within 3 seconds, never
  by user agent. The captured event is what this story's Install button calls.
- **D44** — `isStandalone()` covers both `display-mode: standalone` and iOS's `navigator.standalone`, and
  it is the suppression rule: an installed user sees neither the automatic card nor the menu item. iOS
  installability itself is not automatable; it is checked by hand in [S7.4](S7.4-device-pass.md), with a
  build-time assertion that `apple-touch-icon` and `apple-mobile-web-app-capable` are present.
- **D47** — a player who escaped the WhatsApp webview signs in once more first. This guide is shown only
  after that sign-in succeeds and they respond, which falls out of the D46 gate without special handling.
- **D43** — the service worker is `autoUpdate` with a network-first shell, so an installed home-screen
  launch never pins a stale build.

The brief asks for written Android steps "if the event is unavailable". Under D45 that case is classified
`android-inapp` and belongs to S2.7's escape prompt, so the written Android steps never appear in the
automatic slot. They are not dropped: they are what the **menu item** shows on Android when no install
event is held. That is how both rules are honoured at once, and it is the one place this story and D45
need reading together.

## Scope

**In**
- The install card rendered in S2.7's post-response slot for `ios-safari` and `installable`.
- A real Install button on `installable`, calling the captured `beforeinstallprompt` event.
- An iOS Safari sheet with three steps, illustrated with the actual iOS share glyph as inline SVG.
- Written Android steps, reachable from the menu item when no install event is held.
- A permanent "Add to home screen" item in the app-shell header menu, suppressed when installed.
- Show-once behaviour for the automatic card, and remembered dismissal.
- Copy written for a footballer in a car park.

**Out**
- Detection, the 3-second Android window, the post-response trigger, the exclusivity gate, the dismissal
  helpers and `isStandalone()`. All delivered by S2.7 and S0.4; this story imports them.
- The escape prompt and anything about WhatsApp's webview. S2.7.
- The manifest, the icons, the service worker and the Lighthouse installability gate. [S0.4](S0.4-pwa.md).
- Push notifications of any kind. Out of scope in the brief, and `beforeinstallprompt` is not a
  notification permission.
- Counting installs, or storing whether a player installed. No column is added to the data model (D46),
  and there is no analytics in this app.
- Desktop. The context resolves to `other` and nothing renders.

## Acceptance criteria

Each criterion is independently checkable by a person or a test.

- [ ] **AC1** — the guide renders in the post-response slot only when the install context is `ios-safari`
      or `installable`. For `ios-inapp`, `android-inapp`, `standalone`, `other` and `resolving` it renders
      nothing, and S2.7's gate is the single place that decides (D46).
- [ ] **AC2** — `isStandalone()` true suppresses the guide **and** hides the header menu item entirely. An
      installed player never sees either (D44).
- [ ] **AC3** — the automatic card is shown at most once per browser. After it has been shown it writes
      `pfc.installGuideShown`, and a later response never re-opens it. Only the menu item brings it back.
- [ ] **AC4** — dismissing writes `pfc.installGuideDismissed` and the card does not return automatically.
      A `localStorage` that throws is treated as "not dismissed" and nothing breaks.
- [ ] **AC5** — on `installable`, the card's primary control is a button labelled "Install", not a link and
      not a set of instructions. Tapping it calls `prompt()` on the captured event exactly once.
- [ ] **AC6** — after `prompt()`, `userChoice` resolving `accepted` hides the card permanently; resolving
      `dismissed` writes `pfc.installGuideDismissed`. The captured event is nulled after the call, since
      it cannot be reused.
- [ ] **AC7** — on `ios-safari`, the card's primary control is "Show me how", opening a sheet with exactly
      three steps, and step one contains the iOS share glyph rendered as inline SVG, inline in the
      sentence. Not the word "Share" alone, not an emoji, not a bitmap (brief, S2.8).
- [ ] **AC8** — the menu item "Add to home screen" is present on every `chrome="nav"` route — `/`,
      `/history`, `/manage`, `/manage/*`, `/admin` (S0.3's route table, D34) — for a non-installed player,
      and opens the platform-appropriate sheet: the iOS steps on iOS, the Install button when an install
      event is held, the written Android steps otherwise. It is absent on the `bare` routes, which carry a
      back affordance and no menu.
- [ ] **AC9** — the written Android steps read: tap the three dots at the top right; tap "Install app" or
      "Add to Home screen"; tap Install. Three steps, no more.
- [ ] **AC10** — no copy anywhere in this story contains "PWA", "progressive", "web app manifest",
      "service worker", "standalone" or "shortcut". Checkable by grep over the copy module.
- [ ] **AC11** — every sentence in the guide is under fifteen words. The card is at most two lines at
      375px width.
- [ ] **AC12** — every control in the card and the sheet is at least 44px in its smallest dimension, and
      the sheet's close control is reachable one-thumbed at 375px (D40).
- [ ] **AC13** — the sheet is a shadcn component, keyboard dismissable, focus-trapped while open, and
      returns focus to the control that opened it. Not a hand-rolled overlay.
- [ ] **AC14** — nothing in this story blocks, delays or alters an availability response. The card appears
      after the response is saved and below the controls, which stay interactive.

### The card

Two shapes, chosen by context. Both are a shadcn `Card` in the flow, never an overlay.

| Context | Line | Primary | Secondary |
|---|---|---|---|
| `installable` | "Put Phibsboro on your home screen. One tap next time." | **Install** — calls `promptInstall()` | "Not now" |
| `ios-safari` | "Put Phibsboro on your home screen. One tap next time." | **Show me how** — opens `InstallSheet` | "Not now" |

"Not now" calls `dismiss('install')` from S2.7's `src/lib/prompt-dismissal.ts`. Showing the card at all
calls `markShown('install')` from the same module, in a mount effect, which writes
`pfc.installGuideShown`:

```ts
// src/lib/prompt-dismissal.ts — S2.7's module, imported here, not re-implemented
export function isDismissed(key: 'escape' | 'install'): boolean
export function dismiss(key: 'escape' | 'install'): void
export function wasShown(key: 'install'): boolean
export function markShown(key: 'install'): void
```

S2.7's gate already checks `isDismissed('install') || wasShown('install')` before rendering this card
automatically, so AC3 and AC4 are two keys and two rules — shown-once, and dismissed-forever. The menu
item ignores both: the player asked for it.

### Install, on Android Chrome

`useInstallContext()` (S2.7) exposes:

```ts
promptInstall: (() => Promise<'accepted' | 'dismissed' | 'unavailable'>) | null
```

The implementation calls `event.prompt()`, awaits `event.userChoice`, nulls the stored event, and maps
`outcome`. `'unavailable'` is returned when no event is held — which is the state the menu item finds on
Android when `beforeinstallprompt` never fired — and the caller then renders the written steps instead of
a dead button. The event is single-use by specification: never keep it after `prompt()` resolves.

Type it locally rather than reaching for a DOM lib that may not carry it:

```ts
type BeforeInstallPromptEvent = Event & {
  prompt: () => Promise<void>
  userChoice: Promise<{ outcome: 'accepted' | 'dismissed' }>
}
```

Declared once in `src/lib/install-context.ts` (S2.7's file) and exported. No `any`.

### The iOS sheet

shadcn `Sheet`, `side="bottom"`, title "Add to your home screen".

```
1. Tap  [share glyph]  at the bottom of the screen.
2. Scroll down. Tap Add to Home Screen.
3. Tap Add.
```

The glyph sits inline in step one's sentence, at `1em`, `currentColor`, `aria-hidden` with the surrounding
text carrying the meaning — a square with an arrow pointing up out of the top:

```tsx
// src/features/install/ios-share-icon.tsx
export function IosShareIcon(): JSX.Element  // 24x24 viewBox, stroke="currentColor", fill="none"
// arrow: M12 3 v12  with a chevron head at the top; box: M8 9 H6 a2 2 0 0 0-2 2 v8 a2 2 0 0 0 2 2 h12 ...
```

Inline SVG, not an icon font and not a PNG: it has to take the text colour in both themes and stay sharp
at any size. Do not substitute a lucide "share" icon — the Android share glyph is a different shape and a
player looking for it on an iPhone will not find it.

### The menu item

```ts
export function useInstallMenuItem(): { visible: boolean; open: () => void }
```

`visible` is `!isStandalone() && context !== 'other'`. `open()` shows `InstallSheet` with:

- iOS → the three steps above.
- `promptInstall !== null` → a sheet whose only content is the Install button and one line.
- Android with no event → the written steps (AC9).

Unlike the automatic card, the menu item uses the **latest** state rather than the state frozen at the
3-second mark, so a late `beforeinstallprompt` still yields a real Install button here. S2.7 is explicit
that the automatic slot never flips; the menu item is the place where flipping is safe, because the player
asked.

The item is appended to the S0.2 header menu beneath S2.9's "Sign out". Two items, no submenu, no
settings screen.

### Copy

Every string lives in `src/features/install/install-copy.ts` as a frozen object, so AC10 and AC11 are one
grep and one unit test over one file rather than a hunt through JSX.

```ts
export const installCopy = {
  cardLine:       'Put Phibsboro on your home screen. One tap next time.',
  install:        'Install',
  showMe:         'Show me how',
  notNow:         'Not now',
  sheetTitle:     'Add to your home screen',
  iosStep2:       'Scroll down. Tap Add to Home Screen.',
  iosStep3:       'Tap Add.',
  androidStep1:   'Tap the three dots at the top right.',
  androidStep2:   'Tap Install app, or Add to Home screen.',
  androidStep3:   'Tap Install.',

```

iOS step one is assembled in JSX because it contains the glyph. Every other string is a plain sentence.
British English, full stops, no exclamation marks, no "just", no "simply".

## Data and API surface

None. No table, no RPC, no Zod schema, no query key and no mutation. The only persisted state is two
`localStorage` keys, `pfc.installGuideShown` and `pfc.installGuideDismissed`, both per browser and neither
server data. D46 is explicit that no column is added to the data model for install state.

## Open questions

1. **Should the automatic card be shown once per browser, or once per player?** Proposed default, written
   above: once per browser, using `pfc.installGuideShown`. Per-player would need a column, and D46 rules
   that out. The cost is that a player who uses two browsers sees it twice, which is the correct outcome
   anyway, since each browser installs separately.
2. **Does the iOS sheet need a fourth step for iPadOS, where Share sits top right rather than bottom?**
   Proposed default: no. The squad is on phones; the copy says "at the bottom of the screen" and iPad is
   not a target device in S7.4. Revisit only if a player asks.
3. **What if `beforeinstallprompt` fires on a browser that then refuses to install — Samsung Internet,
   say?** Proposed default: treat it as `installable` and let the browser's own sheet handle it. The
   Install button calls a standard API; if the browser declines, `userChoice` resolves `dismissed` and the
   card is dismissed, which is the right outcome with no extra branch.
