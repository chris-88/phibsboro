## The report
#7 "Managers should be able to correct player names so they are correct for the team sheet"

## Goal
A wrong name (typo at sign-up) can be fixed so the team sheet, roster and shares read right.

## Context
The app stores one `profiles.name` per person, read by the team sheet, roster and every share. There's no
client write path to another person's profile today (profiles is own-row + RPC). So this needs a
security-definer RPC.

## Shipped shape (Z1 decided: managers + admins)
- `set_member_name(p_user_id, p_name)` — security definer, sibling of `set_member_phone`/`set_member_role`.
  Guard: `is_admin() OR exists(team_members where user_id = target AND is_team_manager(that team))` — an
  admin anywhere, or a manager of any team the target is on. Validates 1–60 chars trimmed (the
  registration bound); a bad length raises `not_authorised` as the backstop, exactly as `set_member_phone`
  does for a bad number. Migration `20260930120000_set_member_name.sql`.
- Client: `useSetMemberName()` → `callRpc('set_member_name', …)`, invalidating every family a name is read
  in (teams, events, stats, subs) so a fix reads right everywhere, including the team sheet.
- UI: a "Correct name" action + `CorrectNameDialog` in the member card's action menu (Squad → Members and
  Admin → Members). The menu is now always present there, since name correction is available to every
  viewer of that (manager/admin-gated) list.
- No audit row: the sibling member corrections keep no history either; an audit log is out of scope.

## Acceptance criteria
- [x] **AC1** — A manager fixes a name for a player on their team; broad invalidation updates it everywhere.
- [x] **AC2** — RPC refuses a manager of another team, a player and a stranger; anon has no execute
  (verified live, rolled back; codified in `tests/rls/rpc-members.test.ts`).
- [x] **AC3** — Validated 1–60 chars, trimmed (client `correctNameSchema` + RPC backstop). No audit (scoped out).
