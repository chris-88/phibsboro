## Goal
The database can hold a match's per-player stats and its MOTM + final score, with RLS that lets managers
write and read all, and a player read only their own.

## Context
[X4/X6/X8](../00-decisions-v1.3.0.md). See [data-model-v1.3.0.md](../data-model-v1.3.0.md).

## Scope
**In**
- Migration: `match_stats` table (data-model), PK `(event_id, user_id)`, checks, `match_stats(user_id)` index,
  the `updated_at` trigger; `events.motm_user_id`, `events.score_us`, `events.score_them` (match-only checks).
- RLS on `match_stats`: write = `is_team_manager(event_team_id(event_id)) or is_admin()`; read = that **or**
  `user_id = auth.uid()`.
- Regenerated types; Zod `matchStatsRowSchema` (S1.5 parity).
- RLS suite rows: a manager upserts/reads all; a player reads only their own and cannot write; anon nothing.

**Out**
- The collection UI (S17.4). The aggregate RPC (S17.6).

## Acceptance criteria
- [ ] **AC1** — Migration clean; `db diff` empty; the three `events` columns are match-only.
- [ ] **AC2** — A team manager/admin inserts/updates a `match_stats` row and reads every row for the match.
- [ ] **AC3** — A player reads only their own `match_stats` row and cannot write any.
- [ ] **AC4** — anon can neither read nor write; a non-member reads nothing.
- [ ] **AC5** — `matchStatsRowSchema` matches the generated type (parity test).

## Implementation notes
- Reuse `public.event_team_id(event_id)` (the attendance policies use it). `updated_at` trigger like other
  tables; never sent by the client.

## Data and API surface
`match_stats` + `events` columns + Zod schema. No RPC here.

## Test plan
- **Integration / RLS** — AC2–AC4 as manager / player / non-member / anon. **Unit** — Zod parity.

## Definition of done
- [ ] ACs met; `typecheck`/`lint` clean; RLS rows pass on the next on-demand run; data-model matches.
