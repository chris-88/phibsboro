## Goal

A player who taps the event link inside WhatsApp answers Yes or No first, and only then is told, in one
line, how to get out of WhatsApp's browser and into Safari or Chrome, where the app can actually be
installed. Nobody loses their response to an install prompt.

## Context

WhatsApp opens links in its own webview. On iOS that webview cannot add anything to the home screen and
has its own cookie and storage jar, so a session created in it does not follow the player into Safari.
Every install that fails, fails here.

Twenty-seventh in the build order (D20), after the home screen and the event detail screen exist, because
the prompt is rendered under the response controls those two stories own.

Decisions this story rests on, from [00-decisions.md](../00-decisions.md):

- **D45** — detection is per platform, and the brief's blanket claim is corrected here. On **iOS**, treat
  it as an in-app webview when the UA contains `WhatsApp`, or the UA is WebKit with no Safari UI marker.
  On **Android**, do not use the UA at all: WhatsApp commonly hands links to a Chrome Custom Tab carrying
  Chrome's own user agent *and Chrome's session*, so the brief's "does not share Safari or Chrome's
  session" is simply wrong for Android. Instead, wait up to 3 seconds for `beforeinstallprompt`. If it
  fires, the player is in a real Chrome context and belongs to
  [S2.8](S2.8-add-to-home-screen-guide.md). If it does not, and `isStandalone()` is false, show the escape
  prompt.
- **D46** — this story and S2.8 are ordered and mutually exclusive. In an in-app webview, show *only* the
  escape prompt and never the install guide, because installing is impossible where the player is
  standing. Dismissals live in `localStorage` under `pfc.escapePromptDismissed` and
  `pfc.installGuideDismissed`. No column is added to the data model.
- **D47** — the copy admits the cost rather than hiding it: "You'll sign in once more." The button copies
  the **app root URL**, not the event URL, so the player lands on sign-in and then home, having already
  answered. No session transfer between browsers is attempted, because none is possible.
- **D44** — one `isStandalone()` helper, delivered by [S0.4](S0.4-pwa.md) and exported from
  `src/lib/standalone.ts`, covering both the `display-mode: standalone` media query and iOS's
  `navigator.standalone`. Nothing here re-implements the check.
- **D41** — `/event/:id` hides the bottom nav, so there is room under the YES / NO buttons and nothing is
  underneath the fixed bar.

This story also builds the install-context provider that S2.8 consumes, because `beforeinstallprompt`
fires early in the page lifecycle — long before the player responds — so the listener has to be installed
at app start, in one place, once.

## Scope

**In**
- `detectIosInAppWebview(ua)`, a pure function over a user-agent string.
- An install-context provider mounted at the app root: captures `beforeinstallprompt`, runs the 3-second
  Android window, and resolves one `InstallContext` value for the page load.
- A "has just responded" UI flag, set by the response mutation.
- The escape prompt itself: one line of copy, a copy-link button, a dismiss control.
- The visible fallback for webviews that block the Clipboard API, on top of [S6.2](S6.2-team-join-links.md)'s `copyText()`.
- Dismissal persistence, tolerant of a `localStorage` that throws.
- The exclusivity rule in one component, so S2.8 cannot accidentally stack on top.
- One mount point added on `/event/:id`, under `<AvailabilityButtons />`. S3.1 already has one; S3.3 does
  not.

**Out**
- The install guide, the Install button and the iOS share-icon steps. All S2.8.
- Any attempt to open Safari or Chrome programmatically. iOS webviews cannot do it, and
  `intent://…#Intent;scheme=https;package=com.android.chrome;end` fails silently when Chrome is not
  installed or not the default. The copy-link button is the whole mechanism, and the copy says so.
- Any attempt to move the session between browsers. D47 settles this: the player signs in again.
- Changing the response flow, the mutation, or the optimistic update. Those are S3.1 and D48.
- Prompting before a response. The brief is explicit: respond first, prompt second.
- Anything server side. No table, no column, no RPC.

## Acceptance criteria

Each criterion is independently checkable by a person or a test.

- [x] **AC1** — `detectIosInAppWebview` returns true for a WhatsApp iOS user agent and for an iOS WebKit
      UA with no `Safari/` token, and false for iOS Safari, iOS Chrome (`CriOS`), iOS Firefox (`FxiOS`),
      Android Chrome and desktop Chrome. Asserted against a committed fixture table of real strings.
- [x] **AC2** — on Android, the user agent is never consulted. Classification is decided solely by whether
      `beforeinstallprompt` fires within 3000ms of app start, and by `isStandalone()` (D45).
- [x] **AC3** — `isStandalone()` true short-circuits everything: the context resolves to `standalone` and
      neither this prompt nor the S2.8 guide ever renders.
- [x] **AC4** — the escape prompt is not rendered until the player has successfully submitted a response
      in this session. A failed response (D48 rollback) does not trigger it.
- [x] **AC5** — the prompt renders **below** the response controls, inline in the page. It is not a modal,
      not a dialog, not an overlay and not a full-screen sheet, and the YES / NO buttons stay visible and
      interactive with it on screen.
- [x] **AC6** — the copy is one line. iOS: "Open in Safari to add this to your home screen. You'll sign in
      once more." Android in-app: the same with "Chrome". No other sentence, no jargon, no "PWA".
- [x] **AC7** — the copy button copies `absoluteUrl(paths.home())` — the app root, e.g.
      `https://app.phibsboro.ie/#/` — and never the event URL (D47). The value is built in
      `src/lib/paths.ts` ([S0.3](S0.3-routing.md)), the only file permitted to contain the literal `/#/`
      (S0.3 AC8), so no URL is concatenated here. On success the button's label becomes "Link copied" and
      a line reads "Paste it into Safari." (or "Chrome").
- [x] **AC8** — when the Clipboard API is unavailable or rejects, the prompt reveals a read-only, selectable
      input holding the URL and the line "Copy didn't work. Tap and hold the link to copy it." Nothing
      throws and nothing is silently swallowed.
- [x] **AC9** — dismissing writes `pfc.escapePromptDismissed` and the prompt does not return on a later
      response in the same browser. A `localStorage` that throws is treated as "not dismissed"; the app
      still works, the prompt just reappears.
- [x] **AC10** — dismissal is per browser: the only persistence is the `localStorage` key. No cookie, no
      query parameter, no table and no column carries it, so it deliberately does not follow the player
      from the WhatsApp webview into Safari (D46). Checkable by grep — `pfc.escapePromptDismissed` appears
      in `src/lib/prompt-dismissal.ts` and nowhere else.
- [x] **AC11** — when the escape prompt is shown, the S2.8 install guide is not rendered. The two are
      resolved in one component and cannot both be on screen (D46).
- [x] **AC12** — the dismiss control and the copy button are each at least 44px in their smallest
      dimension and both are reachable one-thumbed at 375px width (D40).
- [x] **AC13** — no analytics, no logging of the user agent to Sentry, no breadcrumb carrying the copied
      URL. The escape prompt is silent.

### The context value

```ts
export type InstallContext =
  | 'resolving'     // Android, still inside the 3s beforeinstallprompt window
  | 'standalone'    // already installed. Show nothing, ever (D44)
  | 'ios-inapp'     // iOS WhatsApp or another non-Safari webview → this story's prompt
  | 'android-inapp' // no beforeinstallprompt inside the window → this story's prompt
  | 'installable'   // beforeinstallprompt captured → S2.8's Install button
  | 'ios-safari'    // real iOS Safari → S2.8's written steps
  | 'other'         // desktop, or anything unrecognised. Show nothing
```

### Detection

```ts
export function detectIosInAppWebview(ua: string): boolean {
  const isIos = /iPhone|iPad|iPod/.test(ua)
  if (!isIos) return false
  if (/WhatsApp/i.test(ua)) return true
  const isWebKit = /AppleWebKit/.test(ua)
  const hasSafariUi = /Safari\//.test(ua)
  const isOtherRealBrowser = /CriOS|FxiOS|EdgiOS|OPiOS/.test(ua)
  return isWebKit && !hasSafariUi && !isOtherRealBrowser
}
```

Pure, exported, and tested against `src/lib/__fixtures__/user-agents.ts`, which holds real strings with a
one-line comment each naming the app and OS version they came from. When WhatsApp changes its UA, the fix
is one row in that table plus one test case, and nothing else moves. That is the whole reason the
function is pure and the table is separate.

Android is deliberately absent from this function. Under D45 a Chrome Custom Tab is indistinguishable
from Chrome by UA — because it *is* Chrome — and it already shares Chrome's session, so treating it as a
trapped webview would be both wrong and harmful.

### Resolving the context

`InstallProvider` mounts once in `src/main.tsx`, above the router, inside `SessionProvider`
([S2.9](S2.9-auth-guard-and-role-context.md)) and outside `AppBoot` ([S2.6](S2.6-session-persistence.md)),
so the `beforeinstallprompt` listener is registered even while the splash is up.

```ts
export function useInstallContext(): {
  context: InstallContext
  promptInstall: (() => Promise<'accepted' | 'dismissed' | 'unavailable'>) | null
}
```

The classification itself is a pure function, so it is testable without a DOM. The provider owns the
timer; the function owns the rules.

```ts
// src/lib/install-context.ts — pure, no DOM, no React, no timers
export function resolveInstallContext(input: {
  ua: string
  standalone: boolean
  installPromptSeen: boolean   // did beforeinstallprompt fire inside the window
}): InstallContext
```

On mount:

1. `if (isStandalone()) → 'standalone'`, stop. No listener needed.
2. Register `beforeinstallprompt`: `e.preventDefault()`, store the event. Chromium fires it once per page
   load; keep the reference for S2.8's Install button and null it after a successful `prompt()` call.
3. iOS (`/iPhone|iPad|iPod/.test(navigator.userAgent)`): resolve synchronously to `ios-inapp` or
   `ios-safari`. iOS never fires `beforeinstallprompt`, so there is nothing to wait for.
4. Android (`/Android/.test(navigator.userAgent)`): stay `resolving`, set a 3000ms timer. If the event
   arrives first, resolve `installable` and clear the timer. If the timer fires first, resolve
   `android-inapp`.
5. Anything else: `other`.

Steps 3, 4 and 5 are `resolveInstallContext` calls with whatever `installPromptSeen` is true at that
moment. The provider contributes the listener and the timer and nothing else, which is why the rules can
be tested without a DOM.

The context is resolved **once per page load and never flips**. A `beforeinstallprompt` that arrives after
the window has closed still updates `promptInstall`, so S2.8's menu item can use it, but it does not
reclassify a player who is already looking at the escape prompt. Flipping a prompt out from under a thumb
is worse than being slightly wrong.

### Triggering on a response

Zustand, UI state only — this is a per-session boolean, not cached server data.

```ts
// src/stores/prompt-store.ts
export const usePromptStore = create<{
  hasRespondedThisSession: boolean
  markResponded: () => void
}>(...)
```

`markResponded()` is called from the `onSuccess` of S3.1's `useSetResponse` mutation, not from `onMutate`.
An optimistic write that the D12 policy then rejects must not produce a prompt (AC4). The flag is not
persisted: it resets on reload, and `pfc.escapePromptDismissed` is what stops repeat showings.

### The exclusivity gate

One component decides, so the two stories cannot both render (D46):

```tsx
// src/features/events/components/PostResponsePrompts.tsx — S3.1 ships it returning null
export function PostResponsePrompts(_props: { eventId?: string }): JSX.Element | null {
  const { context } = useInstallContext()
  const hasResponded = usePromptStore(s => s.hasRespondedThisSession)
  if (!hasResponded) return null
  if (context === 'ios-inapp' || context === 'android-inapp') {
    return isDismissed('escape') ? null : <EscapePrompt platform={context} />
  }
  if (context === 'ios-safari' || context === 'installable') {
    if (isDismissed('install') || wasShown('install')) return null  // S2.8 owns both install keys
    return <InstallGuideCard />                                     // S2.8
  }
  return null                                                       // standalone, other, resolving
}
```

The file, the name and the props are S3.1's, not this story's.
[S3.1](S3.1-home-screen-with-next-event.md) already ships
`src/features/events/components/PostResponsePrompts.tsx` as a typed component whose body is `return null`,
and calls it as `<PostResponsePrompts eventId={…} />`; this story fills that file in and keeps the
signature so the call site does not change. The `eventId` prop is accepted and never read — D47 copies the app root, not the
event URL — and it stays optional so the second call site can omit it.

It is rendered in exactly two places: under the next-event card's YES / NO on `/` in `HomeScreen`
(S3.1, the existing mount point) and under `<AvailabilityButtons />` on `/event/:id` in
`src/features/events/routes/EventDetailScreen.tsx` ([S3.3](S3.3-event-detail-screen.md)), which this story
adds, because S3.3 leaves no seam of its own.

### The prompt itself

A shadcn `Card` with `role="status"`, inline in the flow, not a `Dialog` and not a `Sheet`. AC5 is the
reason: a dialog steals focus and covers the buttons the player just used.

```
Open in Safari to add this to your home screen. You'll sign in once more.
[ Copy link ]                                                        [ × ]
```

- `platform === 'ios-inapp'` → "Safari". `platform === 'android-inapp'` → "Chrome".
- Copy target: `absoluteUrl(paths.home())`. Same module as the share link (D13), so trailing-slash
  handling is settled once in S0.3 and there is no concatenation at the call site.
- The `×` dismiss is a 44px icon button labelled "Not now" for screen readers.

### Clipboard

```ts
// src/lib/clipboard.ts — created by S6.2 at build position 14, imported here
export async function copyText(text: string): Promise<boolean>
```

It tries `navigator.clipboard.writeText(text)` and returns false on a missing API, an insecure context, or
a rejection. It never throws and never logs. This story adds no second implementation. On false the prompt renders a read-only `<input>` holding the URL with
`onFocus={e => e.currentTarget.select()}` and the AC8 line. This path is real: several in-app webviews
block the async clipboard, and it is precisely the browsers this story exists for.

### Dismissal

```ts
// src/lib/prompt-dismissal.ts
type PromptKey = 'escape' | 'install'
const DISMISSED: Record<PromptKey, string> = {
  escape:  'pfc.escapePromptDismissed',
  install: 'pfc.installGuideDismissed',
}
const SHOWN = 'pfc.installGuideShown'

export function isDismissed(key: PromptKey): boolean   // false if localStorage throws
export function dismiss(key: PromptKey): void          // no-op if localStorage throws
export function wasShown(key: 'install'): boolean      // false if localStorage throws
export function markShown(key: 'install'): void        // no-op if localStorage throws
```

Both dismissal keys are named in D46. `pfc.installGuideShown` is the third key, added here because the
module is owned here; [S2.8](S2.8-add-to-home-screen-guide.md) owns what it means — shown-once for the
automatic card, separate from dismissed-forever — and imports all four functions rather than
re-implementing them. Every function wraps `localStorage` in try/catch and degrades to "not dismissed,
not shown" rather than throwing.

## Data and API surface

None. This story reads no table, writes no table, calls no RPC and adds no Zod schema, no query key and no
mutation. The only state it touches is one Zustand boolean and the three `localStorage` keys its dismissal
module owns — `pfc.escapePromptDismissed`, which this story writes, plus `pfc.installGuideDismissed` and
`pfc.installGuideShown`, which S2.8 writes. None of it is server data. D46 is explicit that no column is
added to the data model for this.

## UI states

The prompt is a region inside two existing screens rather than a screen of its own.

| Screen | Loading | Empty | Error | Populated |
|---|---|---|---|---|
| `/event/:id` prompt region | Context `resolving` (Android, first 3s) renders nothing and reserves no height, so nothing shifts under the player's thumb | Context `standalone` or `other`, or already dismissed, or not yet responded: renders nothing | Clipboard failure: the selectable input plus "Copy didn't work. Tap and hold the link to copy it." The prompt stays on screen | One line of copy, a "Copy link" button, a dismiss control, below the availability controls |
| `/` next-event card prompt region | As above | As above | As above | As above |

The host screens own their own loading, empty and error states; this story changes none of them, and AC5
requires the response controls to stay interactive in every cell of this table.

## Open questions

1. **Is the Android `intent://` hand-off worth it?** Proposed default, already written above: no. It is
   silent on failure, it only helps when Chrome is installed and default, and under D45 the Android in-app
   branch is the uncommon fallback rather than the normal path. Copy-link covers both platforms with one
   mechanism.
2. **Should the prompt also appear on the home screen for a returning player who never installed?**
   Proposed default: no. It fires after a response and only after a response, per the brief. A returning
   player who wants the app reaches the S2.8 guide from the menu item.
3. **What if WhatsApp drops the `WhatsApp` token from its iOS user agent?** Proposed default: the second
   clause — WebKit with no `Safari/` marker — already catches it, which is why the detector is written as
   two conditions rather than one. Confirmed on a real device in S7.4, and a change is one fixture row.
