## Goal
An admin opens Admin → Users, sees every person and the teams/roles they hold, and can assign anyone to a
team, change their role, or remove them — the repair tool of W6.

## Context
[W6](../00-decisions-v1.2.0.md). Admin-only, under the Admin surface (Epic 11), linked from the Admin screen
next to Feedback (S12.3). Reads compose over `profiles` + `team_members` + `teams` (all admin-readable);
writes go through `admin_set_membership` (assign / set role) and `remove_member` (remove).

## Scope
**In**
- A route `/admin/users`, linked from the Admin screen. Admin-guarded (S2.9) + inline gate (convenience;
  RLS is the boundary).
- A searchable list of every profile: name, phone, and each team membership with its role. A user on no team
  shows as "No teams".
- Per user: **assign to a team** (team picker over all active teams + a player/manager choice → 
  `admin_set_membership`), **change role** on an existing membership (player↔manager), and **remove** from a
  team (`remove_member`). Confirm the remove.
- Four states: loading, empty (no users — unreachable in practice, still handled), error, populated. Search
  filters client-side; the list may page if large.

**Out**
- Editing name/phone (a separate concern; `set_member_phone` exists but is not surfaced here in v1.2.0).
- Deleting accounts. Issuing reset links (already on the team members screen, S6.4).

## Acceptance criteria
- [ ] **AC1** — The list shows every profile and, per user, their teams and role; a teamless user is shown.
- [ ] **AC2** — An admin assigns a user to a team with a chosen role; the row appears without a reload
  (optimistic or invalidated).
- [ ] **AC3** — An admin changes an existing membership's role; the change reflects immediately.
- [ ] **AC4** — An admin removes a membership after a confirm; the user's other memberships are untouched.
- [ ] **AC5** — A non-admin cannot reach the screen (redirected) and, via the API, the RPCs refuse them.
- [ ] **AC6** — Four states handled; search narrows the list by name/phone.

## Implementation notes
- `src/features/admin/` (or `teams/`) — `AdminUsersScreen`; `useAllUsers` (compose profiles + memberships +
  teams), `useAdminSetMembership`, reuse `useRemoveMember`/`useSetMemberRole` from S6.4's `members` API.
- Reuse the member-row action patterns from the team members screen (S6.4) where possible.
- Team picker reuses `useTeams` (active teams; the RPC still accepts inactive, but the everyday picker shows
  active — D50).

## Data and API surface
Reads `profiles`, `team_members`, `teams` (admin). Writes via `admin_set_membership`, `remove_member`,
`set_member_role`. Keys under the existing factories.

## UI states
| Screen | Loading | Empty | Error | Populated |
|---|---|---|---|---|
| `/admin/users` | skeleton | "No users yet." | inline retry | searchable user list with per-user team/role actions |

## Test plan
- **Unit** — the screen's four states off mocked hooks; assign/role/remove call the right mutation with the
  right args; search filters.
- **Integration / RLS** — S14.1 covers the assign; role/remove covered by S6.4's rows.
- **E2E / Manual** — optional: assign a seeded player to a second team and flip their role.
