## Goal

A developer clones the repo, runs `npm ci`, and gets a running app, a clean typecheck, a clean lint and a
passing test run without access to Supabase, Sentry or the club's GitHub org. Nothing is built for a user
yet. This story exists so that every story after it has one command for each of those four things, and so
the compiler catches the class of mistakes the brief refuses to allow.

## Context

`CLAUDE.md` section 2 fixes the stack and section 3 fixes the conventions. This story installs both and
makes them enforceable rather than aspirational: TypeScript strict with `noUncheckedIndexedAccess`, no
`any`, the `@/` path alias, and feature-first directories.

Decisions this story depends on, from [00-decisions.md](../00-decisions.md):

- **D14** — CI is S0.7, not this story. S0.1 only guarantees the four scripts CI will
  call: `typecheck`, `lint`, `test`, `build`.
- **D38** — `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` are public values, not secrets, and
  `.env.example` commits the local-stack values so a clean checkout runs without org access. The
  service-role key is a real secret and must never appear under `src/`.
- **D35** — `formatEventTime()` is the only date formatter in the codebase, "lint rule enforces it". The
  rule ships here; the helper ships with [S1.5](S1.5-typed-data-layer-and-shared-helpers.md).
- **D53** — `TZ=UTC` in `vitest.config.ts`, so date assertions do not depend on the machine.
- **D56** — the standard definition of done has stated exemptions. S0.1 precedes [S1.4](S1.4-rls-test-suite.md) and adds no screen,
  so neither the RLS gate nor the four-states gate applies.

## Scope

**In**

- Vite + React + TypeScript project at the repo root, npm, committed lockfile, pinned Node version.
- Strict compiler configuration and the `@/` alias in both TypeScript and Vite.
- ESLint flat config with typescript-eslint type-checked rules, plus the project's own restriction rules.
- Prettier, wired so it never fights ESLint.
- Vitest configured, with one smoke test so `npm run test` is meaningful from day one.
- The empty feature-first directory tree and the typed `import.meta.env` surface.
- `.env.example`, `.gitignore`, `.editorconfig`, `.nvmrc`.
- `scripts/check-conventions.mjs`, the grep-level guard that ESLint cannot express.

**Out**

- Tailwind, shadcn/ui, the app shell — [S0.2](S0.2-ui-system.md).
- Any route beyond the single placeholder root — [S0.3](S0.3-routing.md).
- GitHub Actions of any kind — S0.7 for CI, S0.5 for deploy.
- The Supabase client, TanStack Query provider, Zustand store, Zod schemas — S1.5. Their packages are not
  installed here either; a story installs its own dependencies.
- Sentry — S0.6.
- Git hooks. Conventional commits are checked in CI on the PR title (S0.7), not by a local hook.

## Acceptance criteria

Each criterion is independently checkable by a person or a test.

- [ ] **AC1** — On a clean clone with no `.env` file and no network access to Supabase, `npm ci` followed
      by `npm run typecheck`, `npm run lint`, `npm run test` and `npm run build` all exit 0.
- [ ] **AC2** — `npm run dev` serves the app at `http://localhost:5173` and hot-reloads an edit to
      `src/App.tsx` without a full page reload.
- [ ] **AC3** — `tsconfig.app.json` sets `strict`, `noUncheckedIndexedAccess`, `noImplicitOverride`,
      `noFallthroughCasesInSwitch`, `noUnusedLocals`, `noUnusedParameters` and `verbatimModuleSyntax`, all
      true. A test file that indexes an array and uses the result without a narrowing check fails
      `npm run typecheck`.
- [ ] **AC4** — A file containing `const x: any = 1` fails `npm run lint` with
      `@typescript-eslint/no-explicit-any`. A file containing an unchecked `JSON.parse(...)` assignment
      fails on `@typescript-eslint/no-unsafe-assignment`.
- [ ] **AC5** — `import { thing } from '@/lib/thing'` resolves at build time, at dev time, in the editor,
      and in Vitest. A single test asserts the alias resolves at runtime.
- [ ] **AC6** — A call to `date.toLocaleString()`, `toLocaleDateString()`, `toLocaleTimeString()` or
      `new Intl.DateTimeFormat()` anywhere under `src/` except `src/lib/time.ts` fails `npm run lint`
      with a message naming `formatEventTime()`.
- [ ] **AC7** — The identifier `SUPABASE_SERVICE_ROLE_KEY`, or any identifier matching `/SERVICE_ROLE/`,
      appearing anywhere under `src/` fails `npm run lint`.
- [ ] **AC8** — `src/vite-env.d.ts` declares every `VITE_` variable the project will ever read, each typed
      `string`, and reading an undeclared `import.meta.env.VITE_WHATEVER` fails `npm run lint` on
      `@typescript-eslint/no-unsafe-assignment`. It is a lint criterion, not a typecheck one: Vite's own
      `ImportMetaEnv` carries `[key: string]: any`, and our interface merges with it, so the compiler
      cannot be made to reject an unknown key.
- [ ] **AC9** — `.env.example` is committed, contains the local Supabase stack URL and anon key and no real
      secret, and `.gitignore` excludes `.env`, `.env.local` and `.env.*.local` while keeping
      `.env.example`.
- [ ] **AC10** — The directories `src/features/{events,availability,attendance,teams,auth}/`,
      `src/components/`, `src/lib/` and `src/api/` all exist in the clone.
- [ ] **AC11** — `npm run test` runs with `TZ=UTC`; a smoke test asserts
      `new Date().getTimezoneOffset() === 0` inside Vitest.
- [ ] **AC12** — `npm run format:check` passes on the committed tree, and Prettier and ESLint disagree
      about nothing (`eslint-config-prettier` is last in the flat config array).
- [ ] **AC13** — `.nvmrc` and `package.json#engines` pin the same major Node version, and the README
      records the one-liner to get from clone to running app.

## Implementation notes

Scaffold with `npm create vite@latest . -- --template react-ts`, then replace the generated configs.
Node 22 LTS, npm, `package-lock.json` committed. TypeScript `^5.9` or later, because `tsc -b --noEmit`
is required by the typecheck script.

**Scripts** — these four names are load-bearing; S0.7 calls them verbatim.

```json
{
  "dev": "vite",
  "build": "tsc -b --noEmit && vite build",
  "preview": "vite preview --port 4173 --strictPort",
  "typecheck": "tsc -b --noEmit",
  "lint": "eslint . && node scripts/check-conventions.mjs",
  "lint:fix": "eslint . --fix",
  "test": "vitest run",
  "test:watch": "vitest",
  "format": "prettier --write .",
  "format:check": "prettier --check ."
}
```

`preview` pins port 4173 because D17 points Playwright at `http://127.0.0.1:4173`.

**tsconfig.app.json** — the settings that matter:

```jsonc
{
  "compilerOptions": {
    "target": "ES2022",
    "lib": ["ES2022", "DOM", "DOM.Iterable"],
    "module": "ESNext",
    "moduleResolution": "bundler",
    "jsx": "react-jsx",
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "noImplicitOverride": true,
    "noFallthroughCasesInSwitch": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "verbatimModuleSyntax": true,
    "isolatedModules": true,
    "skipLibCheck": true,
    "noEmit": true,
    "types": ["vite/client", "vitest/globals"],
    "baseUrl": ".",
    "paths": { "@/*": ["./src/*"] }
  },
  "include": ["src"]
}
```

`exactOptionalPropertyTypes` is deliberately **off**. It fights React Hook Form and the shadcn component
props for no defect-catching gain at this size. That is the one strictness dial we do not turn, and this
line is the record of why.

**Alias** — declared twice, once for the compiler and once for the bundler, with no extra plugin:

```ts
// vite.config.ts
resolve: { alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) } }
```

`vitest.config.ts` imports the same Vite config so the alias is defined once:

```ts
// vitest.config.ts
process.env.TZ = 'UTC' // before anything constructs a Date; test.env applies too late for the runner itself

export default mergeConfig(
  viteConfig,
  defineConfig({
    test: {
      globals: true,       // matches "vitest/globals" in tsconfig.app.json#types
      environment: 'node', // [S0.2](S0.2-ui-system.md) switches this to 'jsdom' with Testing Library
      env: {
        TZ: 'UTC', // D53
        VITE_APP_BASE_URL: 'http://localhost:5173',
        VITE_SUPABASE_URL: 'http://127.0.0.1:54321',
        VITE_SENTRY_DSN: '',
      },
    },
  }),
)
```

Those `test.env` defaults are what make AC1 true. A clean clone has no `.env`, so without them any test
that reads `import.meta.env` sees `undefined` and `npm run test` fails on a fresh checkout.

**ESLint** — flat config, ESM, in this order: `js.configs.recommended`,
`tseslint.configs.strictTypeChecked`, `tseslint.configs.stylisticTypeChecked`,
`react-hooks` recommended, `react-refresh`, the project block below, then `eslint-config-prettier` last.
Enable the type-aware rules with `languageOptions.parserOptions.projectService: true`.

Project rules:

```js
{
  files: ['src/**/*.{ts,tsx}'],
  rules: {
    '@typescript-eslint/no-explicit-any': 'error',
    '@typescript-eslint/consistent-type-imports': 'error',
    'no-restricted-syntax': ['error',
      { selector: "MemberExpression[property.name=/^toLocale(String|DateString|TimeString)$/]",
        message: 'Use formatEventTime() from @/lib/time. CLAUDE.md section 3, decision D35.' },
      { selector: "NewExpression[callee.object.name='Intl'][callee.property.name='DateTimeFormat']",
        message: 'Use formatEventTime() from @/lib/time. CLAUDE.md section 3, decision D35.' },
      { selector: "Identifier[name=/SERVICE_ROLE/]",
        message: 'The service-role key never appears in the browser bundle. Decision D38.' },
    ],
  },
},
// The one formatter in the codebase is allowed to format. Scoped to the date rules only, so
// no-explicit-any and everything else still apply to this file.
{
  files: ['src/lib/time.ts'],
  rules: { 'no-restricted-syntax': 'off' },
},
```

The `time.ts` exemption is written now even though the file arrives with
[S1.5](S1.5-typed-data-layer-and-shared-helpers.md); a config block whose `files` glob matches nothing is
inert, not an error. It must be a separate block, not an `ignores` entry on the project block: `ignores`
there would lift `no-explicit-any` too. Turning off `no-restricted-syntax` also lifts the `SERVICE_ROLE`
selector for that one file, which is why `scripts/check-conventions.mjs` repeats that check across the
whole tree.

**`scripts/check-conventions.mjs`** — a plain Node script, no dependencies, that walks the tree and exits
1 with a file and line on any hit. It carries the checks ESLint cannot see, and later stories append to
it:

| Check | Owner | Rule |
|---|---|---|
| `SERVICE_ROLE` outside `.env.example` and `supabase/` | S0.1 | belt and braces alongside the lint rule (D38) |
| A hex colour literal under `src/` outside the token stylesheet | [S0.2](S0.2-ui-system.md) | no hardcoded hex in components |
| The literal `'/#/'` outside `src/lib/paths.ts` | [S0.3](S0.3-routing.md) | one URL builder, D13 |

S0.1 ships the script with the first check and the table above as a comment at the top.

**Typed env** — the whole surface, declared once, so no later story adds an untyped variable:

```ts
// src/vite-env.d.ts
/// <reference types="vite/client" />
interface ImportMetaEnv {
  readonly VITE_SUPABASE_URL: string        // public, D38
  readonly VITE_SUPABASE_ANON_KEY: string   // public, D38
  readonly VITE_APP_BASE_URL: string        // share links, D13
  readonly VITE_SENTRY_DSN: string          // S0.6
  readonly VITE_SENTRY_RELEASE: string      // the commit SHA, D16
  readonly VITE_SENTRY_ENVIRONMENT: string  // 'production' | 'preview' | 'local'
}
interface ImportMeta { readonly env: ImportMetaEnv }
```

Runtime validation of these values with Zod belongs to S1.5, which owns the Supabase client. S0.1 only
types them.

**`.env.example`** — committed, with the Supabase CLI's fixed local values, which `supabase start` prints
and which are published constants, not secrets (D38):

```
VITE_SUPABASE_URL=http://127.0.0.1:54321
# The value below is the anon key `supabase start` prints. It is fixed by the CLI version, identical on
# every machine, published in Supabase's own docs, and therefore committed (D38). Paste it verbatim.
VITE_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
VITE_APP_BASE_URL=http://localhost:5173
VITE_SENTRY_DSN=
VITE_SENTRY_RELEASE=local
VITE_SENTRY_ENVIRONMENT=local
```

Empty `VITE_SENTRY_DSN` must be a supported state: S0.6 skips Sentry init when it is blank, so a clean
checkout never reports local noise to the club's Sentry project.

**Vite config** — `base: '/'`. The site is served from a custom apex path at `app.phibsborofc.com`
(S0.5), not from `/{repo}/`, so no base prefix is needed and none should be added. `build.sourcemap` is
set by S0.6 per D16; leave it alone here.

**Prettier** — `printWidth: 100`, `singleQuote: true`, `semi: false`, `trailingComma: 'all'`. S0.2 adds
`prettier-plugin-tailwindcss`. No other plugins.

**Gotchas**

- `verbatimModuleSyntax` means every type-only import needs `import type`. The
  `consistent-type-imports` rule autofixes it, so run `npm run lint:fix` before arguing with the compiler.
- `tsc -b --noEmit` requires TypeScript 5.6 or later. On an older version it silently does the wrong
  thing, so the version floor in `package.json` is not decoration.
- Vite's `ImportMetaEnv` in `vite/client.d.ts` declares `[key: string]: any`. Our interface merges with
  it, so an undeclared `VITE_` key resolves to `any` instead of erroring — hence AC8 is enforced by lint.
  Do not "fix" it by dropping `vite/client` from `types`; the asset-import module declarations go with it.
- Do not add `@types/node` to `tsconfig.app.json#types`. It leaks `process` into browser code and makes
  the D38 rule easy to dodge. `tsconfig.node.json` gets it; `src/` does not.

## Build notes — deviations from this spec

Recorded at build time. The spec was written against assumed versions; these are what the current
toolchain actually required.

| Spec said | Built as | Why |
|---|---|---|
| Node 22 LTS, `.nvmrc` `22` | Node 24, `.nvmrc` `24` | Node 24 is what the dev machine runs and is LTS. `engines.node` is `>=24`. S0.7 must pin 24 in `node-version-file`. |
| `tsconfig.app.json` sets `baseUrl: "."` | `baseUrl` removed | TypeScript 6 errors `TS5101: Option 'baseUrl' is deprecated`. `paths` now resolves relative to the config file, so the alias works without it. AC5 still passes. |
| `reactHooks.configs['recommended-latest']` | `reactHooks.configs.flat['recommended-latest']` | In eslint-plugin-react-hooks 7 the top-level key is the legacy eslintrc shape (`plugins` as a string array) and ESLint 10 rejects it. The `flat` namespace holds the flat-config version. |
| — | Added a `**/*.{js,mjs,cjs}` block extending `tseslint.configs.disableTypeChecked` | `eslint.config.js` and `scripts/*.mjs` sit outside both tsconfigs, so type-aware rules had no program and ESLint failed to load `await-thenable`. |
| — | `scripts/check-conventions.mjs` exempts itself | It names the `SERVICE_ROLE` pattern it searches for, so it matched its own source. |
| — | `vitest.config.ts` imports `./vite.config.ts` with the extension, and `tsconfig.node.json` sets `allowImportingTsExtensions` | Vite 8's native config loader warns on extensionless relative imports. |

Installed: React 19.3, Vite 8.3, TypeScript 6.0, ESLint 10.10, Vitest 5.0.

**Verified at build time.** All four scripts exit 0 on a clean tree. The negative criteria were each proved
by writing a probe file and confirming the failure: AC3 (`TS18048: 'first' is possibly 'undefined'`),
AC4 (`no-explicit-any`, `no-unsafe-assignment`), AC6 (both selectors name `formatEventTime()`),
AC7 (lint rule and `check-conventions.mjs` both fire).

## Test plan

- **Unit** — three Vitest tests: the `@/` alias resolves at runtime; `TZ` is UTC inside the runner (D53);
  `import.meta.env.VITE_APP_BASE_URL` is a non-empty string, supplied by the `test.env` defaults above so
  the assertion holds with no `.env` file present. Enough to prove the harness works, and no more.
- **Integration / RLS** — none. There is no database.
- **E2E** — none. Playwright arrives with [S7.3](S7.3-end-to-end-journey.md).
- **Manual** — clone into an empty directory on a second machine, `nvm use && npm ci && npm run dev`,
  confirm the app serves with no `.env` present. That is the criterion that actually catches mistakes here.

## Open questions

1. **Are conventional commits enforced by a local hook or in CI?** Proposed default: CI only. S0.7 adds a
   PR-title check against the conventional-commit grammar. No husky, no lint-staged, nothing that slows a
   local commit down. Recorded here so S0.7 picks it up.
2. **Does the repo enforce the feature-first boundary in lint, so `src/features/auth` cannot import from
   `src/features/events`?** Proposed default: not yet. The convention is documented in the README and in
   `CLAUDE.md` section 3, and a boundary rule is revisited only if a cross-feature import actually shows up
   in review. Adding one now would be tooling for a problem nobody has.
3. **Is `src/lib/` or `src/lib/utils.ts` the home for `cn()`?** Proposed default: `src/lib/utils.ts`,
   because that is where the shadcn CLI writes it and fighting the generator costs more than it saves.
   Settled properly in [S0.2](S0.2-ui-system.md).
