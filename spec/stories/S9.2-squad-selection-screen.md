## Goal
On a match, a manager picks the matchday squad from the players who said they're available, gives each a
shirt number, and marks the captain — ready to publish to WhatsApp.

## Context
Sits on the manager event view (S4.3). Pool = available responders ([V7](../00-decisions-v1.1.0.md)). Writes
go through the S9.1 mutations. Numbers 1–20, one captain.

## Scope
**In**
- A "Squad" section/screen on the match manager view: the available players, each with a way to add to the
  squad and assign a number (1–20), and a captain toggle. Selected players show their number; unselected
  show an add control. A running count (e.g. "14 / 20 picked").
- Optimistic add/remove/renumber/captain through the S9.1 mutations, with rollback on error.
- Guards: a number already used is offered only once; picking the captain clears any previous captain; a
  player who has since changed to unavailable is shown flagged (still removable/renumberable) per V7.
- Only a manager of the team (or admin) sees the section — RLS is the enforcement; the UI gate is convenience.
- Four states: loading the pool+squad, empty (no available players yet), error, populated.

**Out**
- Non-match events (training/social have no squad section).
- The share text ([S9.3](S9.3-match-share-rewrite.md)) — this story ends at a persisted squad.

## Acceptance criteria
- [ ] **AC1** — On a match, a manager sees a Squad section listing the **available** players (from S9.1's read), each addable with a number; training/social show no squad section.
- [ ] **AC2** — Adding a player with a number persists an `event_squad` row (verified by SQL); removing deletes it; both update optimistically and roll back with a message on failure.
- [ ] **AC3** — A shirt number can be used only once per match; the UI prevents a duplicate and the DB backs it up; numbers are 1–20.
- [ ] **AC4** — Marking a captain sets `is_captain` on that row and clears any previous captain; at most one captain shows a "(C)".
- [ ] **AC5** — A picked player who later becomes unavailable is shown flagged; the manager can remove or keep them; the pool never offers a non-available player to be added.
- [ ] **AC6** — A running "{n} / 20" count; adding beyond 20 is prevented.
- [ ] **AC7** — A non-manager (player) navigating to the match sees no squad-editing controls; a manager of another team cannot load or write it (RLS).
- [ ] **AC8** — Readable and thumb-usable at 375px; number entry is a tap, not free typing where avoidable; targets ≥44px.

## Implementation notes
- New `src/features/events/components/SquadPicker.tsx`, mounted in the S4.3 manager view for `type==='match'`.
- Reads `useEventSquad(eventId)` (S9.1) and the available slice of the response list (S4.4 data — reuse the
  same query, filter `response==='available'`); do not refetch differently.
- Number assignment UX: a compact number selector (a `Select`/stepper of the free numbers) per player, or a
  tap-to-assign-next-free with manual override — pick the fastest on a phone and note it. shadcn components.
- Optimistic updates keyed on `eventKeys`; rollback restores the previous squad on mutation error.
- Captain toggle: one call that sets the new captain and unsets the old (an RPC or two-step; S9.1 decides).

## Data and API surface
Reads: `useEventSquad`, the response list query (available filter). Writes: `setSquadMember`,
`removeSquadMember`, captain toggle from S9.1. No new tables.

## UI states
| Screen | Loading | Empty | Error | Populated |
|---|---|---|---|---|
| Match manager view → Squad | skeleton rows | "No one's available yet." (no available responders) | "Couldn't load the squad." + retry | Available players, picked ones numbered, captain (C), n/20 |

## Test plan
- **Unit / component** — add/remove/renumber/captain against a fake mutation; duplicate-number prevention; the n/20 cap; the unavailable-flag.
- **Integration / RLS** — a manager persists a squad and a captain against the live project; a player cannot; cleaned up.
- **Manual** — pick a squad on a phone; assign numbers and a captain quickly; confirm it persists across a reload.
