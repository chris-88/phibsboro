## Goal

A manager's event becomes a block of text they can paste into the squad WhatsApp group: what it is, when
it is, where it is, and a link that opens straight onto that event. This story produces the text and the
link only. Putting it in front of the manager is [S5.2](S5.2-share-action.md).

## Context

The journey the brief cares about is *create → share → tap → yes/no*. The share step is a copy-paste into
a group chat that already exists, so the message is the whole product surface between the manager and
twenty players. CLAUDE.md §1 and the Epic 5 stories are the source; the brief's only functional criterion
was "output matches the agreed format", and no format appeared anywhere in it.

Decisions this story rests on, from [00-decisions.md](../00-decisions.md):

- **D13** fixes the message format literally. The template below is not a suggestion. Both variants are
  asserted byte for byte in Vitest, so a wording change is a deliberate edit to a test, not a drift.
- **D6** makes `events.id` a `uuid` that is itself the join credential. No token is appended to the link.
  The message therefore contains nothing secret and nothing that expires, which is why it is safe to sit
  in a group chat for a season.
- **D35** owns `formatEventTime(iso, style)`. This story consumes the `'share'` style and does no date
  formatting of its own. CLAUDE.md §3 bans ad-hoc `toLocaleString`; a lint rule enforces it.
- **D52** requires the `wa.me` body to be percent-encoded, because the link contains `#` and an unencoded
  body is silently truncated at the fragment. That is a bug that only appears on a real phone.
- **D53** pins `TZ=UTC` in Vitest, so every date assertion here uses a fixed UTC instant.
- **S1.5** owns `src/lib/env.ts`, the one module allowed to read `import.meta.env`, and already carries
  `VITE_APP_BASE_URL: z.string().url()` in its Zod schema. This story imports `env` from there and reads
  `import.meta.env` nowhere.

## Scope

**In**
- `src/lib/shareMessage.ts` with `buildShareMessage()` and `waMeUrl()`.
- The one place the share text is built. The URL inside it comes from `eventUrl()` in
  `src/lib/paths.ts` ([S0.3](S0.3-routing.md)), the only file permitted to contain `/#/`.
- Vitest coverage of every branch, asserted as literal strings, including both Dublin offsets.

**Out**
- Any React component, button or screen. S5.2 owns all of that.
- `buildReminderMessage()`. Same file, different story ([S5.3](S5.3-reminder-share.md)).
- A cancellation message. Cancelling an event does not generate a "match is off" message in v1; see
  Open questions.
- Per-player messages, mentions, or anything addressed to an individual. Nothing here takes a name.
- Sending. The app never talks to WhatsApp. It hands the operating system a string.

## Acceptance criteria

Each criterion is independently checkable by a person or a test.

- [x] **AC1** — `buildShareMessage()` returns exactly this, joined with `\n`, no trailing newline:

  ```
  {emoji} {title}
  {dateLine}
  {location}
  {notes}          ← this line omitted entirely when notes are absent

  Are you available? {url}
  ```

- [x] **AC2** — `{emoji}` is `⚽` when `type = 'match'` and `🏃` when `type = 'training'`. No other emoji
      appears anywhere in the output.
- [x] **AC3** — `{dateLine}` is `formatEventTime(event.starts_at, 'share')` and nothing else. A January
      (GMT) instant and a July (IST) instant both render the correct Dublin wall-clock time.
- [x] **AC4** — `{url}` is `eventUrl(event.id)`, imported from `@/lib/paths`
      ([S0.3](S0.3-routing.md) AC8, AC9). This module contains no `/#/` literal and concatenates no URL;
      `npm run lint` fails if it does.
- [x] **AC5** — With `notes = null`, the output is five lines. With notes present, six.
      `message.split('\n').length` asserts both.
- [x] **AC6** — Notes that are whitespace-only are treated as absent. Notes containing newlines or runs of
      whitespace are collapsed to a single space, so the message is always five or six lines whatever a
      manager typed into the textarea.
- [x] **AC7** — `title` and `location` are trimmed before interpolation.
- [x] **AC8** — D13's worked example reproduces byte for byte in a test, emoji included.
- [x] **AC9** — `waMeUrl(message)` returns `` `https://wa.me/?text=${encodeURIComponent(message)}` ``. The
      result contains `%23%2Fevent%2F` and contains no raw `#`.
- [x] **AC10** — The functions are pure: no `Date.now()`, no `navigator`, no `window`, no network, no
      React import. They run under Node in Vitest with no DOM.
- [x] **AC11** — The output contains no player name, no phone number and no token. A test passes an event
      whose `title` is a person's name and asserts nothing else leaks in.
- [x] **AC12** — A missing or malformed `VITE_APP_BASE_URL` never reaches a group chat as
      `undefined/#/event/...`. `src/lib/env.ts` ([S1.5](S1.5-typed-data-layer-and-shared-helpers.md) AC6)
      fails its Zod parse at module load, so the app throws on start and the
      [S0.6](S0.6-observability.md) error boundary catches it on the manager's own screen. This module
      contains no `import.meta.env` reference at all: `grep -n "import.meta.env" src/lib/shareMessage.ts`
      returns nothing. A link nobody can edit once it is in a group chat is worse than a loud failure.

## Implementation notes

One new module, one new test file. No component, no hook.

```ts
// src/lib/shareMessage.ts
import type { Database } from '@/lib/database.types'
import { formatEventTime } from '@/lib/time'

type EventRow = Tables<'events'>

/** The only fields the share text needs. Deliberately narrower than the row. */
export type ShareEvent = Pick<
  EventRow,
  'id' | 'type' | 'title' | 'location' | 'notes' | 'starts_at'
>

export const EVENT_EMOJI: Record<EventRow['type'], string> = {
  match: '⚽',
  training: '🏃',
}

export function buildShareMessage(event: ShareEvent): string
export function waMeUrl(message: string): string
```

Internals, module-private, shared with [S5.3](S5.3-reminder-share.md) which adds
`buildReminderMessage()` to this same file:

```ts
function normaliseNotes(notes: string | null): string | null
// trim, collapse /\s+/g to ' ', return null when the result is empty

function eventHeader(event: ShareEvent): string[]
// [`${EVENT_EMOJI[event.type]} ${event.title.trim()}`,
//  formatEventTime(event.starts_at, 'share'),
//  event.location.trim(),
//  ...(notes ? [notes] : []),
//  '']                                   ← the blank separator line
```

`buildShareMessage` is then `[...eventHeader(event), `Are you available? ${eventUrl(event.id)}`].join('\n')`.
S5.3's reminder swaps only the last element. Keep it that way: one header builder, two last lines.

**The base URL.** This story does not build it. `eventUrl(id)` lives in `src/lib/paths.ts`
([S0.3](S0.3-routing.md)), the one file allowed to contain `/#/`, and it strips a trailing slash from the
configured base:

```ts
import { eventUrl } from '@/lib/paths'
```

`VITE_APP_BASE_URL` is the origin with no trailing slash and no hash, e.g.
`https://app.phibsboro.ie`. [S0.1](S0.1-project-scaffold.md) declares it in `src/vite-env.d.ts` and
commits it to `.env.example`; [S0.5](S0.5-deployment.md) injects it as a GitHub Actions repository
**variable**, not a secret (D38) — there is nothing confidential in a public site's own address.
`src/lib/env.ts` ([S1.5](S1.5-typed-data-layer-and-shared-helpers.md)) parses it with `z.string().url()`
and is the only module permitted to touch `import.meta.env`; `paths.ts` reads the parsed value from
there. Set the value to `http://127.0.0.1:4173` in `.env.test`, matching the `vite preview` origin
Playwright drives (D17).

**Gotchas.**

- `encodeURIComponent` encodes `#` to `%23` and `/` to `%2F`. That is the entire point of D52. Do not
  "tidy" it by switching to `URLSearchParams`, which encodes spaces as `+` — WhatsApp renders those as
  literal plus signs.
- Do not append `&phone=` to `wa.me`. An empty `wa.me/?text=` opens the chat picker, which is what a
  manager sharing into an existing group wants. A number would open a one-to-one chat.
- No trailing newline. WhatsApp renders one as an empty line above the keyboard and it looks like a
  mistake.
- The emoji are two separate characters in source (`⚽` U+26BD, `🏃` U+1F3C3). Save the file as UTF-8 and
  assert them as literals in the test, not as escapes, so a bad transcode fails the build.
- `type` comes from the `event_type` Postgres enum (data-model.md), so `Record<EventRow['type'], string>`
  is exhaustive by construction. Do not widen it to `Record<string, string>`.

## Test plan

- **Unit** — `src/lib/shareMessage.test.ts`, Vitest, literal string assertions. No `toMatchSnapshot`: a
  wording change must be a visible diff in the test. Cases:
  1. D13's worked example — a match with notes — byte for byte.
  2. Training, no notes — five lines, `🏃`, correct last line.
  3. `notes: null`, `notes: '   '`, `notes: 'Bring both kits.\n\nPitch 3.'` → absent, absent, collapsed
     to one line.
  4. `title: '  Kilbarrack away  '` and a padded `location` → trimmed.
  5. A GMT instant (`2026-01-17T19:30:00Z`) and an IST instant (`2026-07-18T18:30:00Z`), asserting the
     Dublin wall-clock time appears in the date line under `TZ=UTC` (D53).
  6. An event in a different calendar year, with `vi.setSystemTime` fixed, asserting the year reaches the
     message (the rule itself belongs to `formatEventTime`).
  7. The last line contains exactly the string `eventUrl(event.id)` returns, with no re-encoding.
     `eventUrl()`'s own trailing-slash cases belong to [S0.3](S0.3-routing.md) AC9.
  8. `waMeUrl()` contains `%23%2Fevent%2F`, contains no `#`, and round-trips through
     `decodeURIComponent` back to the exact message.
  9. An event titled with a player's name — assert the output contains no other name, no `+353`, no token.
- **Integration / RLS** — none. No database access, and no policy changes, so the
  [S1.4](S1.4-rls-test-suite.md) suite is untouched.
- **E2E** — none in this story. [S5.2](S5.2-share-action.md) asserts the generated string reaches the
  share sheet.
- **Manual** — paste the generated string into a WhatsApp group by hand once, on a real phone, and confirm
  the link is tappable and the emoji renders. Formally part of [S7.4](S7.4-device-pass.md).

## Open questions

1. **Does a cancelled event need its own message?** A manager who cancels Saturday will want to say so in
   the group. **Proposed default: no, not in v1.** They type "off tomorrow" themselves, as they do today.
   Adding a third variant means a third format to agree, and the brief fixes the share text at one shape.
   If the club asks for it later it is a new story and a new D13 entry, not a widening of this one.
2. **Is `app.phibsboro.ie` the base URL at launch?** D13's example assumes it; Q12 in
   [00-decisions.md](../00-decisions.md) assumes the DNS is ours. **Proposed default: yes**, with the
   value carried entirely in `VITE_APP_BASE_URL` so a change is a repository-variable edit and a redeploy,
   never a code change.
3. **What is the datetime helper module actually called?** Settled:
   [S1.5](S1.5-typed-data-layer-and-shared-helpers.md) owns the file (D35) and names it `src/lib/time.ts`,
   with its own lint override on that path. This story imports `@/lib/time` and nothing else.
   [S0.1](S0.1-project-scaffold.md)'s ESLint override and lint messages now name `src/lib/time.ts` too,
   so nothing is stale. [S7.2](S7.2-unit-tests.md) names the test file `src/lib/time.test.ts`, which
   matches.
