## Goal
Make **state** legible at a glance with meaningful colour, while the chrome stays the calm grey (Z1).

## Scope
**In** — one small semantic token set (success/danger/info/warning) defined once in the theme (light +
dark), then applied to:
- Availability Yes → green, No → red (the pressed/selected state), on `AvailabilityButtons` + the
  manager on-behalf and attendance controls where it reads the same.
- Role tag: Player green, Manager blue (the profile, member list, admin users).
- Event-type chip: training blue (match / social keep their existing chips; confirm their colours).
- Subs badge: paid-up green, owing red/amber (Z2 — colour by paid-up vs owing; hold the €250 band).

**Out** — the grey chrome, buttons and nav (unchanged). The €250 amount band (Z2, OPEN).

## Acceptance criteria
- [ ] **AC1** — Colours come from theme tokens, no hardcoded hex in components (S0.2); work in dark mode.
- [ ] **AC2** — Each state above reads in its colour; greyscale still distinguishes them (glyph/weight, D's AC10).
- [ ] **AC3** — Contrast passes (the contrast test).

## Open questions
- Z1 palette exact values; Z2 whether €250 is a real threshold; match/social event-chip colours.
