## Goal

The three things the whole product silently depends on — what time an event says it is, what the WhatsApp
message says, and how many players are counted as awaiting — are proved by tests that run in under a
second with no database. A change to any of them goes red in CI before it goes wrong in a car park.

## Context

`CLAUDE.md` asks Epic 7 for "Vitest covering the message generators, date and timezone helpers, and count
derivation". [D57](../00-decisions.md) narrows that: every story already ships its own tests, so this story
adds **only the cross-cutting cases nobody owns** and then locks in a coverage floor so they cannot rot.
The cases are named in D57: DST boundaries, count derivation with an empty squad and with an orphaned
response row, the Sentry PII scrubber, and the `wa.me` encoding.

Everything here is a pure function in `src/lib/`, by design:

- `formatEventTime()` lives in `src/lib/time.ts` and `toE164()` in `src/lib/phone.ts`, both
  [S1.5](S1.5-typed-data-layer-and-shared-helpers.md) deliverables with their own basic tests
  ([D35](../00-decisions.md)).
- Count derivation is a pure function over squad rows plus response rows, put there deliberately so it can
  be tested with no database ([D22](../00-decisions.md)).
- `buildShareMessage()` and `waMeUrl()` in `src/lib/shareMessage.ts`, and `eventUrl()` in
  `src/lib/paths.ts`, are pure and their
  format is fixed literally ([D13](../00-decisions.md)); the `wa.me` body is percent-encoded
  ([D52](../00-decisions.md)).
- The Sentry scrubber, `src/lib/sentry-scrub.ts`, is required to be a pure function with Vitest coverage
  ([D16](../00-decisions.md)). [S0.6](S0.6-observability.md) owns `sentry-scrub.test.ts` and the positive
  redaction cases; this story adds only the over-redaction and non-mutation cases to that same file.

[D53](../00-decisions.md) is the reason this story is cheap and not flaky: `TZ=UTC` in the CI job and in
`vitest.config.ts`, and every date assertion written as a fixed UTC instant. A test that reads the wall
clock is a test that fails in January.

## Scope

**In**

- DST and year-boundary cases for `formatEventTime()`, including the ambiguous repeated hour in October.
- `toE164()` edge cases: the forms Irish players actually type, plus rejection cases.

- The things the Sentry scrubber must **not** redact, and its non-mutation of the Sentry event object.
- `waMeUrl()` percent-encoding and round-trip.
- One share-message case that crosses a DST boundary, which neither [S5.1](S5.1-message-generator.md) nor
  [S1.5](S1.5-typed-data-layer-and-shared-helpers.md) owns.
- A coverage threshold over `src/lib/**`, enforced in the `check` CI job.
- A short inventory listing the cross-cutting tests and where each lives.

**Out**

- Re-testing what a feature story already tests. [S5.1](S5.1-message-generator.md) owns the byte-for-byte
  share format; [S5.3](S5.3-reminder-share.md) owns the reminder line; [S1.5](S1.5-typed-data-layer-and-shared-helpers.md)
  owns the happy paths of both helpers. This story does not duplicate them.
- Component tests. Screen behaviour is [S7.1](S7.1-state-coverage-audit.md)'s harness.
- Anything touching Supabase. No client, no stub, no network.
- Property-based testing libraries. Not in the stack table; hand-written case tables are enough at this size.

## Implementation notes

### Fixed instants and the frozen clock

Freeze the clock once per file so the year-appending rule is deterministic:

```ts
beforeAll(() => { vi.useFakeTimers(); vi.setSystemTime(new Date('2026-03-01T12:00:00Z')) })
afterAll(() => { vi.useRealTimers() })
```

The expected strings, asserted literally:

| Input (UTC instant) | Style | Expected | Why it is here |
|---|---|---|---|
| `2026-01-17T19:30:00Z` | `share` | `Saturday 17 January, 7.30pm` | GMT, winter |
| `2026-07-18T18:30:00Z` | `share` | `Saturday 18 July, 7.30pm` | IST, summer: UTC+1 applied |
| `2026-03-29T00:30:00Z` | `share` | `Sunday 29 March, 12.30am` | 30 minutes before the clocks go forward |
| `2026-03-29T01:30:00Z` | `share` | `Sunday 29 March, 2.30am` | 30 minutes after; the 01:00–02:00 hour does not exist |
| `2026-10-25T00:30:00Z` | `share` | `Sunday 25 October, 1.30am` | First pass through the repeated hour, IST |
| `2026-10-25T01:30:00Z` | `share` | `Sunday 25 October, 1.30am` | Second pass, GMT. Same string on purpose (AC3) |
| `2027-01-16T19:30:00Z` | `share` | `Saturday 16 January 2027, 7.30pm` | Year appended when not the current year |
| `2026-07-18T18:30:00Z` | `short` | `Sat 18 Jul, 7.30pm` | Abbreviated form |
| `2026-07-18T18:00:00Z` | `time` | `7pm` | Minutes omitted on the hour |
| `2026-01-18T00:00:00Z` | `time` | `12am` | Midnight, not `0am` |
| `2026-01-18T12:00:00Z` | `time` | `12pm` | Midday, not `0pm` |

The helper is imported as `formatEventTime` from `@/lib/time`. If a string above disagrees with what
[S1.5](S1.5-typed-data-layer-and-shared-helpers.md) implemented,
the table is the specification and the implementation changes — except for the two October rows, which must
agree with each other rather than with anything else.

### Count derivation

The signature is fixed by [S4.3](S4.3-manager-event-view.md) and must not change; this story only adds
cases against it.

```ts
export type SquadMember = { readonly userId: string }
export type ResponseRow = { readonly userId: string; readonly response: AvailabilityResponse }
export type Counts = {
  readonly available: number
  readonly unavailable: number
  readonly awaiting: number
  readonly squad: number
}

export function deriveCounts(
  squad: readonly SquadMember[],
  responses: readonly ResponseRow[],
): Counts
```

Cases:

| Squad | Responses | Expected |
|---|---|---|
| `[]` | `[]` | `{ available: 0, unavailable: 0, awaiting: 0, squad: 0 }` |
| `[a, b, c]` | `[]` | `{ 0, 0, 3, 3 }` |
| `[a, b, c]` | `[a: available, b: unavailable]` | `{ 1, 1, 1, 3 }` |
| `[a, b]` | `[a: available, z: available]` | `{ 1, 0, 1, 2 }` — `z` has left the squad ([D33](../00-decisions.md)) |
| `[]` | `[z: available]` | `{ 0, 0, 0, 0 }` — every row orphaned |
| `[a]` | `[a: available, a: unavailable]` | last row wins; no throw |

The invariant is asserted inside a shared helper so it runs for every row of the table, not just the ones
someone remembered:

```ts
const expectSums = (c: Counts) => expect(c.available + c.unavailable + c.awaiting).toBe(c.squad)
```

### The scrubber

[S0.6](S0.6-observability.md) owns `src/lib/sentry-scrub.ts` and its test, exporting `scrubString()`,
`scrubDeep()`, `scrubEvent()` and `scrubBreadcrumb()`, and already asserts the positive cases: the three
phone formats and the `/#/join/` and `/#/reset/` truncation. This story adds the other half to the same
file, because over-redaction is the failure nobody notices until an issue is unreadable.

Must-not-redact cases: an event uuid such as `9f1c2d3e-4a5b-6c7d-8e9f-0a1b2c3d4e5f`; the path
`/#/event/9f1c2d3e-4a5b-6c7d-8e9f-0a1b2c3d4e5f`, which must survive whole because it is how an issue gets
traced back to an event; a 13-digit millisecond timestamp such as `1774000000000`; and a Postgres error
code such as `PGRST116`. Each is asserted with `toBe(input)`, not merely `not.toContain('[redacted]')`.

Non-mutation: Sentry reuses the event object, so a scrubber that edits in place corrupts the caller's copy.

```ts
const event = makeEvent()
const before = structuredClone(event)
scrubEvent(event)
expect(event).toStrictEqual(before)
```

`src/lib/supabase.ts` is excluded because it is a client constructor with nothing to assert, and

nothing or force component tests this story explicitly does not want.

## Data and API surface

None. Every function under test is pure and lives in `src/lib/`. No table is read, no RPC is called, no
Supabase client is constructed, no Zod schema is added. The `AvailabilityResponse` type used by
`deriveCounts` comes from the generated enums via the S1.5 Zod schemas
([D24](../00-decisions.md)); this story imports it and adds nothing.

The one thing to watch: every file under test must stay importable without a Supabase client. If adding a
case forces `src/lib/supabase.ts` to load, the helper has acquired a dependency it should not have, and
that is a finding, not a test problem.

## Open questions

1. **Is `353871234567`, with no leading `+` and no leading `0`, accepted as Irish?** Proposed default: yes.
   Twelve digits beginning `353` followed by a valid Irish mobile prefix normalises to `+353871234567`.
   It is what a player gets when they paste a number with the `+` stripped by another app.
2. **Which Irish mobile prefixes count?** Proposed default: `083` to `089` inclusive, so the accepted
   national part matches `^08[3-9]\d{7}$` and the E.164 form `^\+3538[3-9]\d{7}$`. The AC4 case table
   asserts one accepted number per prefix and rejects `081`. Anything narrower will reject a real player's
   number one day; if [S1.5](S1.5-typed-data-layer-and-shared-helpers.md)'s `toE164()` is narrower, that is
   a finding against S1.5, not a change made here.
3. **Should the coverage floor cover `src/api/` too?** Proposed default: no. Those are TanStack Query
   hooks over a network boundary; testing them properly means stubbing the client, which is
   [S7.1](S7.1-state-coverage-audit.md)'s harness and a different kind of test.
4. **October's repeated hour renders two instants identically. Is that acceptable?** Proposed default: yes,
   asserted and commented. Disambiguating would mean printing `IST`/`GMT` in a share message read by
   footballers, which is worse.
