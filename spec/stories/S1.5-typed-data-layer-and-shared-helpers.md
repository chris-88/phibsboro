## Goal

After this story a feature story never writes a Supabase call by hand, never writes a row type by hand,
never formats a date by hand and never parses a phone number by hand. There is one typed client, one Zod
schema per entity checked against the generated types, one query-key factory, one RPC wrapper that turns
the six database error words into copy, one `formatEventTime()` and one `toE164()`. Everything from
Epic 2 onward is assembly.

## Context

Section 3 of `CLAUDE.md` mandates generated Supabase types, one Zod schema per entity shared between
forms and API boundaries, all server state through hooks in `src/api/`, and all display formatting through
a single `formatEventTime()` pinned to `Europe/Dublin`. None of it has an owner until here.

Decisions this story is built on:

- **D35** — `formatEventTime()` and `toE164()` land here, with their unit tests. Seven later stories
  consume them, and S2.2's normaliser must be byte-identical to S2.1's, which only happens if there is
  one function.
- **D24** — the four closed value sets are Postgres enums, so `supabase gen types typescript` emits string
  unions. Zod `z.enum` members are asserted equal to `Database['public']['Enums'][…]` at typecheck, so
  adding a value in SQL without adding it here breaks the build.
- **D4** — `profiles.id` is the `auth.users` id, so `useCurrentUser()` in S2.9 can key on `auth.uid()`
  with no lookup table.
- **D7** — `get_event_preview` is the anonymous read, so the client must work signed out.
- **D38** — `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` are public values baked into the bundle,
  committed in `.env.example` for the local stack. The service-role key is never imported under `src/`.
- **D53** — `TZ=UTC` in `vitest.config.ts`; the DST tests are fixed UTC instants.
- **D23, D48** — query defaults are polling and optimistic-update friendly: no Realtime, and mutations
  need a predictable invalidation surface, which is what the key factory is for.
- **D55** — this is the first story after the S1.4 gate, and the first that may touch team data.

## Acceptance criteria

Each criterion is independently checkable by a person or a test.

- [ ] **AC1** — `npm run db:types` regenerates `src/lib/database.types.ts` from the local stack, and the
  `db` job fails if regenerating produces a diff. No row type, enum or function argument type is
  hand-written anywhere in `src/`.
- [ ] **AC2** — every one of the eight tables has a Zod schema, and a compile-time assertion proves its
  inferred type is identical to `Tables<'that_table'>`. Removing a column in SQL breaks `typecheck`.
- [ ] **AC3** — each of the four enums has a `z.enum` whose inferred type is asserted identical to
  `Enums<'that_enum'>`.
- [ ] **AC4** — `src/lib/supabase.ts` exports exactly one `SupabaseClient<Database>` instance. An ESLint
  rule fails a build that imports `createClient` from `@supabase/supabase-js` anywhere else.
- [ ] **AC5** — the client is configured `persistSession: true`, `autoRefreshToken: true`,
  `detectSessionInUrl: false`, `storageKey: 'pfc.auth'`. The `detectSessionInUrl` value is commented with
  why: HashRouter puts the app's own route in the fragment and GoTrue must not parse it.
- [ ] **AC6** — `src/lib/env.ts` parses `import.meta.env` with Zod at module load and throws a named,
  readable error if `VITE_SUPABASE_URL` or `VITE_SUPABASE_ANON_KEY` is missing or malformed. Exactly two
  modules read `import.meta.env` after this story: `src/lib/env.ts`, and `src/lib/sentry.ts`
  ([S0.6](S0.6-observability.md)), which must be able to initialise **before** `env.ts` is imported so
  that a malformed environment is itself reported. The exemption is declared in the lint rule by path and
  nowhere else.
- [ ] **AC7** — an ESLint rule fails any identifier containing `SERVICE_ROLE` under `src/`, and any
  `VITE_`-prefixed reference to a service key.
- [ ] **AC8** — `callRpc(fn, args)` is typed from `Database['public']['Functions']`, so a wrong argument
  name or a wrong return shape is a typecheck error, and a wrong function name is not callable.
- [ ] **AC9** — `callRpc` throws an `AppError` carrying one of the six codes — `invalid_invite`,
  `invalid_token`, `not_authorised`, `phone_taken`, `series_too_long`, `starts_in_past` — or `unknown`.
  No Postgres message,
  constraint name or column name reaches a component.
- [ ] **AC10** — `mapRpcError` returns fixed copy for each of the six codes, and the two token codes map
  to the same line: "That link's no good. Ask your manager for a new one."
- [ ] **AC11** — `formatEventTime(iso, style)` returns, for the same fixed UTC instant:
  `'share'` → `Saturday 14 March, 7.30pm`; `'short'` → `Sat 14 Mar, 7.30pm`; `'time'` → `7.30pm`. On the
  hour it returns `7pm`. When the event's Dublin year is not the current Dublin year, `'share'` appends
  the year: `Saturday 14 March 2027, 7.30pm`.
- [ ] **AC12** — `formatEventTime` is correct across DST: a January instant renders in GMT, a July
  instant in IST, and the two 2026 boundary instants render on the correct side. Tests run with `TZ=UTC`
  and pass unchanged if the runner's zone is set to `Pacific/Auckland`.
- [ ] **AC13** — an ESLint rule fails any use of `toLocaleString`, `toLocaleDateString`,
  `toLocaleTimeString` or `new Intl.DateTimeFormat` outside `src/lib/time.ts`.
- [ ] **AC14** — `toE164` maps `087 123 4567`, `+353 87 123 4567`, `00353871234567` and `(087)1234567`
  all to `+353871234567`, and returns `null` for an empty string, `12345`, `087123456789`, letters, and a
  landline `014567890`.
- [ ] **AC15** — `src/api/queryKeys.ts` exports exactly three factories — `eventKeys`, `teamKeys` and
  `userKeys` — whose members are `as const` tuples, and no string-literal query key and no fourth factory
  appears anywhere else in `src/`. Later stories add members to these three objects and nothing else.
- [ ] **AC16** — `useEventPreview(eventId)` returns the RPC's row for a signed-out caller against the
  local stack, and returns the "not found" state for an unknown uuid without throwing — proving the
  anonymous path (D7) works end to end through this layer.
- [ ] **AC17** — `npm run typecheck` passes with `strict` and `noUncheckedIndexedAccess`, and `any`
  appears nowhere; `@typescript-eslint/no-explicit-any` is `error`.
- [ ] **AC18** — the brief's "used by both forms and API responses" is structural, not a convention: a
  form schema is only ever derived from its entity's row schema with `.pick()`, `.omit()`, `.extend()` or
  `.partial()`, never written as a second object literal. This story ships the rule and one worked case
  in a code comment on `eventRowSchema`; a reviewer checking a later form story can point at the derived
  chain or reject the PR.

## Implementation notes

### Generated types

```jsonc
// package.json
"db:types": "supabase gen types typescript --local --schema public > src/lib/database.types.ts"   // S1.1's script, unchanged
```

Committed, because a clean checkout must typecheck without Docker. The `db` job (S1.4) gains a step after
the seed:

```yaml
      - run: npm run db:types && git diff --exit-code src/lib/database.types.ts
```

Aliases, so no file outside `src/lib/` indexes into `Database` by hand:

```ts
// src/lib/database.types.ts (generated) is re-exported through src/lib/db.ts
export type { Database } from './database.types'
export type Tables<K extends keyof Database['public']['Tables']> =
  Database['public']['Tables'][K]['Row']
export type Insert<K extends keyof Database['public']['Tables']> =
  Database['public']['Tables'][K]['Insert']
export type Enums<K extends keyof Database['public']['Enums']> = Database['public']['Enums'][K]
export type Fn<K extends keyof Database['public']['Functions']> = Database['public']['Functions'][K]
```

### Parity assertions

```ts
// src/lib/type-assert.ts
export type Equal<A, B> =
  (<T>() => T extends A ? 1 : 2) extends (<T>() => T extends B ? 1 : 2) ? true : false
export type Expect<T extends true> = T
```

Used once per schema. These cost nothing at runtime and are the whole reason the enums are enums:

```ts
// src/features/events/schema.ts
import { z } from 'zod'
import type { Enums, Tables } from '@/lib/db'
import type { Equal, Expect } from '@/lib/type-assert'

export const eventTypeSchema = z.enum(['training', 'match'])
export const eventStatusSchema = z.enum(['scheduled', 'cancelled'])

export const eventRowSchema = z.object({
  id: z.string().uuid(),
  team_id: z.string().uuid(),
  type: eventTypeSchema,
  title: z.string().trim().min(1).max(80),
  location: z.string().trim().min(1).max(120),
  notes: z.string().max(500).nullable(),
  starts_at: z.string(),            // timestamptz, always ISO 8601 UTC over the wire
  status: eventStatusSchema,
  series_id: z.string().uuid().nullable(),
  created_by: z.string().uuid().nullable(),
  created_at: z.string(),
  updated_at: z.string(),
})
export type EventRow = z.infer<typeof eventRowSchema>

type _TypeParity   = Expect<Equal<z.infer<typeof eventTypeSchema>, Enums<'event_type'>>>
type _StatusParity = Expect<Equal<z.infer<typeof eventStatusSchema>, Enums<'event_status'>>>
type _RowParity    = Expect<Equal<EventRow, Tables<'events'>>>
```

Where the entity schemas live, feature-first:

| Entity | Module |
|---|---|
| `profiles` | `src/features/auth/schema.ts` |
| `teams`, `team_members`, `team_invites` | `src/features/teams/schema.ts` |
| `events` | `src/features/events/schema.ts` |
| `event_responses` | `src/features/availability/schema.ts` |
| `attendance` | `src/features/attendance/schema.ts` |
| `reset_tokens` | `src/features/auth/schema.ts` |

`team_invites` and `reset_tokens` are unselectable by clients (S1.3), so their schemas cover only the RPC
return shapes. Keep them anyway: the parity assertion is what catches a column change nobody told the
frontend about.

Form schemas — the shapes React Hook Form validates — are **derived** from the row schema in the story
that owns the form, e.g. `eventRowSchema.pick({ type: true, title: true, location: true, notes: true })`
extended with the date and time fields in S4.1. Never a second hand-written object.

### Errors

```ts
// src/lib/errors.ts
export const APP_ERROR_CODES = ['invalid_invite', 'invalid_token', 'not_authorised',
                                'phone_taken', 'series_too_long', 'starts_in_past',
                                'unknown'] as const
export type AppErrorCode = (typeof APP_ERROR_CODES)[number]

export class AppError extends Error {
  constructor(readonly code: AppErrorCode, readonly cause?: unknown) { super(code) }
}

export function toAppError(error: PostgrestError | null): AppError
// Matches error.message against the six words. Anything else becomes 'unknown' and the original
// is kept on .cause for Sentry, never rendered.

export function mapRpcError(code: AppErrorCode): string
// invalid_invite | invalid_token → "That link's no good. Ask your manager for a new one."
// not_authorised  → "You can't do that."
// phone_taken     → "That number is already registered."
// series_too_long → "That's too many sessions. Pick a shorter run."
// starts_in_past  → "Pick a date in the future."
// unknown         → "Something went wrong. Try again."
```

Copy lives in one place so S2.4, S2.3, S6.2 and S6.4 all say the same thing, which is what the brief's
"ask your manager for a new link" screen requires.

### RPC wrapper

```ts
// src/api/rpc.ts
export async function callRpc<K extends keyof Database['public']['Functions']>(
  fn: K,
  args: Fn<K>['Args'],
): Promise<Fn<K>['Returns']> {
  const { data, error } = await supabase.rpc(fn, args)
  if (error) throw toAppError(error)
  return data as Fn<K>['Returns']
}
```

A lookup RPC that "fails" returns an empty array, not an error (S1.3). Callers must treat `[]` as
not-found, and `useEventPreview` demonstrates it. Never turn an empty lookup into a thrown error; the
difference between "unknown" and "expired" is deliberately unavailable.

### Query layer

```ts
// src/api/queryKeys.ts — the only module in the codebase that constructs a query key
export const eventKeys = {
  all:        ['events'] as const,
  detail:     (eventId: string) => ['events', 'detail', eventId] as const,
  preview:    (eventId: string) => ['events', 'preview', eventId] as const,
  upcoming:   (userId: string)  => ['events', 'upcoming', userId] as const,
  list:       (teamId: string)  => ['events', 'list', teamId] as const,
  responses:  (eventId: string) => ['events', 'responses', eventId] as const,
  attendance: (eventId: string) => ['events', 'attendance', eventId] as const,
} as const

export const teamKeys = {
  all:     ['teams'] as const,
  detail:  (teamId: string) => ['teams', teamId] as const,
  members: (teamId: string) => ['teams', teamId, 'members'] as const,
  invite:  (teamId: string, role: Enums<'member_role'>) => ['teams', teamId, 'invite', role] as const,
  lookup:  (token: string)  => ['teams', 'inviteLookup', token] as const,
} as const

export const userKeys = {
  current: ()               => ['currentUser'] as const,
  history: (userId: string) => ['history', userId] as const,
} as const
```

Three factories, one module, one shape: `['<entity>', '<what>', <id>]`. The entity segment comes first so
a single `invalidateQueries({ queryKey: eventKeys.all })` clears every event query — detail, preview,
upcoming, list, responses and attendance — which is what S3.1's optimistic `onSettled`
([D48](../00-decisions.md)) and S4.3's poll ([D23](../00-decisions.md)) both need. `userKeys.history` sits
under its own `['history']` prefix on purpose, so a response or attendance invalidation does not churn an
infinite query ([S3.5](S3.5-own-attendance-history.md)).

Later stories **extend these three objects**. They do not declare a fourth factory and they do not write a
string-literal key. Everything Epic 3, 4 and 6 need is already here: the members key
([S6.4](S6.4-member-administration.md)), the invite key ([S6.2](S6.2-team-join-links.md)) and the invite
lookup key ([S2.4](S2.4-join-by-link.md)) are declared above so that no story has to invent one.

The worked hook, copied by every later one:

```ts
// src/api/events.ts
export function useEventPreview(eventId: string | undefined) {
  return useQuery({
    queryKey: eventKeys.preview(eventId ?? ''),
    enabled: Boolean(eventId),
    queryFn: async () => {
      const rows = await callRpc('get_event_preview', { p_event_id: eventId! })
      const first = rows[0]
      return first ? eventPreviewSchema.parse(first) : null   // null = not found, not an error
    },
  })
}
```

Every query and mutation hook lives under `src/api/`, one module per entity — `src/api/events.ts`,
`src/api/teams.ts`, `src/api/availability.ts`, `src/api/attendance.ts`, `src/api/members.ts` — which is
what `CLAUDE.md` section 3 requires: "All Supabase reads/writes go through query/mutation hooks in
`src/api/`". `src/features/<feature>/` holds that feature's screens, components and Zod schema, never a
Supabase call. Every later story follows it.

### Helpers

```ts
// src/lib/time.ts
export function formatEventTime(iso: string, style: 'share' | 'short' | 'time'): string
```

Implemented with `Intl.DateTimeFormat('en-IE', { timeZone: 'Europe/Dublin', … }).formatToParts()` and
reassembled by hand, because no locale produces `7.30pm`. Rules, fixed:

- 12-hour clock, lowercase `am`/`pm`, no space before it, a full stop between hour and minute.
- Minutes omitted on the hour: `7pm`, not `7.00pm`. Midday is `12pm`, midnight `12am`.
- `share`: `{weekday long} {day} {month long}, {time}`, with ` {year}` after the month when the event's
  Dublin year differs from the current Dublin year.
- `short`: `{weekday short} {day} {month short}, {time}`.
- "Current year" is computed in `Europe/Dublin`, not in the runner's zone.
- The input is the ISO string PostgREST returns. Never a `Date` built from local parts.

```ts
// src/lib/phone.ts
export function toE164(input: string): string | null
```

Order of operations: strip everything except digits and a leading `+` (including unicode dashes,
non-breaking spaces and brackets); `00` prefix becomes `+`; a leading `0` becomes `+353` plus the rest; a
bare `353…` becomes `+353…`; anything already starting `+` is kept. Then validate: general form
`^\+[1-9]\d{7,14}$`, and additionally, when the result starts `+353`, require an Irish mobile,
`^\+3538[35679]\d{7}$`. A landline returns `null`, because this app can only reach people on mobiles.
Return `null` rather than throwing; the caller renders the field error.

Supabase stores `auth.users.phone` without the leading `+` while `profiles.phone` keeps it (D35). The
client always sends the full `+` form to `signInWithPassword` and `signUp`; no helper strips it, and
nothing in `src/` reads `auth.users.phone`.

## Data and API surface

**Tables read or written** — none directly by this story beyond the `useEventPreview` demonstration,
which calls `get_event_preview`.

**RPCs** — `get_event_preview`, through the worked hook. The other twelve become callable, and typed, but
are exercised by the stories that need them.

**Zod schemas added** — `profileRowSchema`, `teamRowSchema`, `teamMemberRowSchema`, `teamInviteSchema`,
`resetTokenSchema`, `eventRowSchema`, `eventPreviewSchema`, `eventResponseRowSchema`,
`attendanceRowSchema`, plus `eventTypeSchema`, `eventStatusSchema`, `availabilityResponseSchema`,
`memberRoleSchema`, and shared primitives `uuidSchema`, `e164Schema` in `src/lib/zod.ts`.

**Query keys** — the three factories above; `eventKeys.preview` is the only one used in this story.

**Mutations** — none.

## UI states

Not a UI story. It adds no route and no component. The states it makes possible — a `null` from a lookup
meaning "not found", an `AppError` code meaning a fixed line of copy — are consumed by S2.4, S3.3 and S6.x.

## Test plan

- **Unit** — Vitest, `TZ=UTC` (D53). `formatEventTime`: the three styles, on-the-hour trimming, a January
  GMT instant, a July IST instant, both 2026 DST boundary instants, and a next-year instant proving the
  year suffix. `toE164`: the table in AC14, both directions. `mapRpcError` and `toAppError`: all six
  codes, plus an unrecognised Postgres message mapping to `unknown` while keeping `.cause`. `env`: a
  missing variable throws a readable error. The parity assertions need no test; they are `typecheck`.
- **Integration / RLS** — the `db` job gains the generated-types freshness check. `useEventPreview` gets
  one integration test in the `rls` project, signed out, against a seeded event id and an unknown uuid,

## Open questions

1. **Do we Zod-parse every read, or only RPC returns and form input?** Proposed default, written above:
   parse RPC returns and form input; trust the generated types for plain table reads. PostgREST returns
   exactly the shape the generated types describe, and parsing every row of every list costs CPU on a
   phone for a failure mode that the CI freshness check already catches. The schemas still exist for
   every table, so the decision is reversible in one line per hook.
2. **Zod v3 or v4?** Proposed default: pin `zod@^3.23` and `@hookform/resolvers@^3`. v4's `z.enum`
   inference differs and the parity assertions are written against v3's. Revisit only if a later story
   needs something v3 cannot do.
3. **Does `useEventPreview` belong to this story or to S3.3?** Proposed default: here, as the worked
   example, because it is the one hook that must exist before any screen to prove the signed-out path.
   S3.3 consumes it and adds no second copy.
