## Goal
Sharing a match produces the club's real WhatsApp format — title, KO/Meet, home/away venue, and the numbered
squad with the captain — so a manager publishes the teamsheet straight into the group.

## Context
[V8](../00-decisions-v1.1.0.md) rewrites D13's match variant to the club message. It consumes the Epic 8
fields (opponent/home-away/title, KO/Meet, Bogies) and the S9.2 squad. Training/social keep the v1.0.0 D13
format. Reuses the S5.2 share action.

## Scope
**In**
- The match variant of the share generator (extends S5.1's `buildShareMessage`), producing exactly:
  ```
  {team} vs {opponent}
  KO: {kickoff HH:MM} | Meet: {meet HH:MM}
  Home Game: Bogies              ← home; or "Away: {location label}"
  {blank line}
  Squad:
   1. {name}
   2. {name}
   3. {name} (C)
   ...
  20. {name}
  ```
  The Squad block is included only when a squad exists; otherwise the message ends after the venue line (a
  manager can share the fixture first, the squad later). Numbers are right-aligned to two columns as in the
  club message. Meet line omits "| Meet: …" if `meet_at` is null.
- The share button on the match manager view uses this variant via the S5.2 action (navigator.share / wa.me).
- Byte-for-byte unit tests, including with and without a squad, home vs away, and Dublin DST.

**Out**
- Training/social share (unchanged, D13 v1.0.0). The reminder variant (S5.3) is unchanged in shape but may
  gain the KO/Meet line for matches — flag; default keep as-is.

## Acceptance criteria
- [ ] **AC1** — For a home match with a squad, the message is byte-for-byte the format above ("vs", "KO: … | Meet: …", "Home Game: Bogies", blank line, "Squad:", numbered list, "(C)" on the captain), asserted in a unit test.
- [ ] **AC2** — For an away match, line three is "Away: {location label}" (the venue/label from S8.4), not "Home Game".
- [ ] **AC3** — With **no squad selected**, the message stops after the venue line (no "Squad:" block); a unit test covers it.
- [ ] **AC4** — When `meet_at` is null, the second line is just "KO: {kickoff}" with no "| Meet:"; tested.
- [ ] **AC5** — The squad is ordered by shirt number ascending; the captain shows "(C)"; numbers are formatted like the club message (aligned). Names come from the profiles; the message names players (this is the teamsheet — naming here is intended, unlike the reminder S5.3 which names nobody).
- [ ] **AC6** — Times render in Dublin via formatEventTime's time variant; a summer and a winter example both format correctly under TZ=UTC.
- [ ] **AC7** — The share button on the match manager view opens the share sheet / wa.me with this text prefilled; the app never sends it itself.
- [ ] **AC8** — Training and social shares are unchanged (the v1.0.0 D13 format), asserted by their existing tests still passing.

## Implementation notes
- Extend `src/lib/shareMessage.ts` (S5.1) with a match branch that takes the event + squad rows + team name;
  keep it a pure function. One generator, variant by type. The URL/link rules from S5.1 still apply.
- Number formatting: pad to align (" 1." vs "10."); match the club message exactly and pin it in the test.
- The share action (S5.2) already handles navigator.share/wa.me — pass the new text; no new share plumbing.
- Update D13 in `spec/00-decisions.md` (or note the override in the v1.1.0 decisions) to the new match format.

## Data and API surface
Reads the event + `useEventSquad` + team name. Pure generator extension. No schema change.
