# S18.4 — A mandatory reason for not attending

| | |
|---|---|
| **Epic** | 18 — Manager conveniences (post-v1.3.0) |
| **Status** | Done |
| **Depends on** | S3.3 (availability), S18.1 (respond on behalf) |
| **Size** | M |
| **Risk** | medium — adds a step to the core No path; kept to one free-text box |

## Goal
When a player says they can't make training or a match, they give a short reason, so the manager
knows why (Chris, 2026-09-16). Free text (owner's choice), required.

## Context
`event_responses` gains a `reason`, required (non-empty) for `unavailable` and null for `available`
— a DB check enforces both (NOT VALID, so the reason-less rows already there are left alone). Tapping
**No** opens a one-box prompt; the write only fires once something is typed. The manager on-behalf
path (S18.1) collects it the same way, since the check requires it there too.

## Scope
**In**
- `event_responses.reason` + a check: `available → null`, `unavailable → non-empty (≤200)`.
- `ReasonDialog`: a required free-text prompt, Save disabled until non-blank. Shared by the player's
  own No (`AvailabilityButtons`) and the manager menu (`PlayerResponseCard`).
- The reason travels through `useSetResponse` (player) and `set_response_for` (manager on-behalf,
  now a 4-arg RPC).
- Managers see the reason under an unavailable player in the "Who's in" list.

**Out**
- Preset reasons / categories (free text only). Editing history of reasons. Showing a player their
  own reason back (they typed it). Reasons on `available` (there is none).

## Acceptance criteria
- [x] **AC1** — Tapping No prompts for a reason; the response isn't recorded until one is given.
- [x] **AC2** — `unavailable` without a non-empty reason is rejected by the DB, not just the UI.
- [x] **AC3** — A manager marking a player unavailable on their behalf gives a reason too.
- [x] **AC4** — Managers see the reason beside an unavailable player.
- [x] **AC5** — `available` clears any reason; the check keeps the data consistent.

## Implementation
- `supabase/migrations/20260916200000_response_reason.sql` — the column, the check (NOT VALID), and
  the 4-arg `set_response_for`. Seed + RLS suite updated to carry a reason for unavailable rows.
- `event_responses` read/schema/`roster` gain `reason`; `useSetResponse` / `useSetResponseFor` send it.
- `ReasonDialog`, wired into `AvailabilityButtons` and `PlayerResponseCard`.

## Definition of done
- [x] ACs met; mandatory enforced in UI + DB; `typecheck`/`lint`/tests/build green. Check + RPC verified live (rolled back).
