## Goal
Each team has a colour. An admin sets it on the team screen, and it's used to colour that team's events on
the calendar so a player can tell training from a match, and Firsts from Seconds, at a glance.

## Context
[V9](../00-decisions-v1.1.0.md): `teams.colour` (hex, not null, defaulted), admin-editable via a swatch
picker constrained to an accessible palette, consumed by the calendar (S10.2).

## Scope
**In**
- Migration adding `teams.colour text not null default '#1e40af'` with a hex check; seed Firsts/Seconds
  distinct accessible defaults.
- The team create/edit screen (S6.1) gains a colour swatch picker (a fixed accessible palette, not a raw
  hex input) writing through the existing team update hook.
- The team Zod schema + generated types include `colour`; a small `TEAM_PALETTE` constant of allowed values.

**Out**
- Using the colour on the calendar ([S10.2](S10.2-calendar-home.md)) — this story stores and edits it.

## Acceptance criteria
- [x] **AC1** — Migration adds `teams.colour` (not null, default, hex check); runs clean; existing teams get the default, then are seeded distinct; `test:rls` green.
- [x] **AC2** — An admin can change a team's colour on the team screen from a palette of accessible swatches; the change persists (verified by SQL) and the swatch reflects it.
- [x] **AC3** — Only allowed palette values are accepted; a non-palette/invalid hex is rejected by the schema and the DB check.
- [x] **AC4** — A manager (non-admin) cannot change a team's colour (RLS; the picker is admin-only in the UI as convenience).
- [x] **AC5** — The colour is exposed on the team read used elsewhere (so S10.2 can key dots off it) without an extra query.

## Implementation notes
- Migration `NNNN_teams_colour.sql`. `TEAM_PALETTE` (≈6–8 accessible hexes, sufficient contrast on the
  calendar ground in light and dark) in `src/features/teams/palette.ts`; the picker offers only these.
- Team schema gains `colour` (enum of the palette, or string + refinement to the palette). Reuse the S6.1
  team update mutation. Admin-only picker via the existing guard.
- Seed: give Firsts and Seconds two clearly distinct palette entries.

## Data and API surface
`teams.colour`. Team Zod schema + update mutation. `TEAM_PALETTE`. Regenerated types.
