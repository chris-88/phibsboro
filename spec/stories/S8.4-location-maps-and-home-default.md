## Goal
For an away match the manager pastes a Google Maps link as the location; for a home match the location
defaults to the club ground, **Bogies**. Players tap the location to open it in maps.

## Context
[V5](../00-decisions-v1.1.0.md): `events.location` stays free text but may hold a URL. A home match defaults
to name "Bogies" + link `https://maps.app.goo.gl/SD1NJmBYwLqz8Z7M6`. Away matches paste their own link. The
home venue lives in one `HOME_VENUE` constant.

## Scope
**In**
- `src/lib/home-venue.ts` — `HOME_VENUE = { label: 'Bogies', mapsUrl: 'https://maps.app.goo.gl/SD1NJmBYwLqz8Z7M6' }`.
- Form: when a match is set to home, the Location field defaults to the home venue (label shown, maps link
  stored); when away, the field is empty for the manager to paste a link. Manager can override either.
- A `locationDisplay(location)` helper: if the value is a URL, render a tappable link (opens in a new tab /
  the OS maps app) labelled sensibly (Bogies for the home link, "Open in Maps" otherwise); else plain text.
- Event detail, home card, manager view and the calendar day list use `locationDisplay`.

**Out**
- Any schema change (location is already text). No geocoding, no map embed — just a link (out of scope).
- The share line ("Home Game: Bogies" / "Away: …") — that is [S9.3](S9.3-match-share-rewrite.md).

## Acceptance criteria
- [ ] **AC1** — Setting a match to **home** defaults the Location to the Bogies maps link (showing "Bogies"); setting **away** clears it for the manager to paste a link. The manager can override both.
- [ ] **AC2** — `locationDisplay` renders a `https?://` value as a tappable link (target/rel safe) and any other value as plain text; unit-tested for a maps link, a plain place name, and empty.
- [ ] **AC3** — The Bogies label and link come from the single `HOME_VENUE` constant (grep: the URL literal appears only there).
- [ ] **AC4** — Event detail, home card, manager view and the calendar day list all use `locationDisplay` (no ad-hoc rendering of `location`).
- [ ] **AC5** — Training/social location is a free-text field with no home default and no link behaviour unless the manager pastes a URL (in which case `locationDisplay` still links it).

## Implementation notes
- No migration. `HOME_VENUE` constant; `locationDisplay(value): { href?: string; label: string }` in
  `src/lib/location.ts` (or `home-venue.ts`). Link opens with `rel="noopener noreferrer"`.
- Form default: on `home_away` change to 'home', if location is empty or equals the previous away value,
  set it to `HOME_VENUE.mapsUrl`. Keep it editable.
- Reuse across screens — one display helper, matching how formatEventTime is the one date formatter.

## Data and API surface
None (no schema change). New `HOME_VENUE` constant and `locationDisplay` helper.
