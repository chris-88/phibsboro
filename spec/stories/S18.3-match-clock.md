## Goal
Kick-off is manual — games get delayed — so the manager runs the clock from the game-stats screen:
tap to start each half, watch the minute tick, and enter the data as it happens. The clock is saved,
so closing the app mid-match doesn't lose it (Chris, 2026-09-16; owner chose "saved clock, 2 halves").

## Context
Four period markers on the event: `first_half_kickoff_at`, `half_time_at`, `second_half_kickoff_at`,
`full_time_at` (match-only, nullable). The running minute is **derived** from these and the current
time — nothing ticking is stored — so a reload rebuilds the exact clock and any device reads the same.
The second half counts from 45:00 (broadcast convention). Managers already update events (S4.2), so
the markers ride the existing events write path (like MOTM/score, X4) — no new RLS.

## Scope
**In**
- The match appears in the Squad tab's **Game Stats** list from **an hour before kick-off** (not only
  once `starts_at` passes), so the screen and clock are ready early.
- On the game-stats screen, a **clock card**: phase (Not started / 1st half / Half time / 2nd half /
  Full time), the live minute, one button to advance (Kick off → Half time → Kick off 2nd half →
  Full time), and a Reset for a mis-tap. Minutes per player stay manual (the existing input).
- Each tap writes a marker (optimistic on the header cache); the minute ticks once a second while a
  half is live.

**Out**
- Auto-filling per-player minutes / sub tracking. Time-stamping goals. Extra-time beyond the running
  count. Any stat beyond X4.

## Acceptance criteria
