## Goal
The backend can hold a user's profile photo and let that user set/clear it, so the profile screen has an
avatar. Nothing user-facing yet.

## Context
[W10](../00-decisions-v1.2.0.md). Photos in a public-read Storage bucket (public URL, no signed-URL churn);
`profiles.avatar_path` points at the object; a user sets their own through `set_own_avatar` (the direct
`profiles` UPDATE stays closed so name/phone remain admin-only). See [data-model-v1.2.0.md](../data-model-v1.2.0.md).

## Scope
**In**
- Migration: `profiles.avatar_path text` (nullable); the `avatars` bucket (`public = true`); storage.objects
  insert/update/delete policies scoping writes to `(storage.foldername(name))[1] = auth.uid()::text`.
- `set_own_avatar(p_path text)` — security-definer, sets `avatar_path` for `auth.uid()` (null clears);
  `revoke from public, anon; grant to authenticated`.
- Regenerated `database.types.ts`; `avatar_path` added to the profile Zod schema.
- RLS/storage tests (S1.4 grows): a user writes only under their own prefix and is refused another's; a user
  sets/clears their own avatar_path via the RPC; anon cannot.

**Out**
- Upload UI / the Avatar component (S16.2). Exposing avatars on other users' cards (a later epic).

## Acceptance criteria
- [ ] **AC1** — Migration runs clean; `avatar_path` is nullable; `avatars` bucket exists and is public; `db diff` empty after.
- [ ] **AC2** — An authenticated user can upload to `avatars/{their-uid}/…`; uploading under another uid's prefix is refused.
- [ ] **AC3** — `set_own_avatar('x')` sets the caller's `avatar_path`; `set_own_avatar(null)` clears it; it never touches another row.
- [ ] **AC4** — A user still cannot UPDATE `profiles` directly (name/phone stay admin-only); anon has no execute on the RPC.
- [ ] **AC5** — The public URL for an existing object resolves (200) without auth.

## Implementation notes
- Bucket + policies live in the migration (idempotent `on conflict do nothing`), so `supabase db push` on
  deploy provisions them; also apply locally to the live project for type-gen and testing.
- Path convention `{uid}/{timestamp}.{ext}`; the timestamp makes each upload a new URL (cache-bust).

## Data and API surface
`profiles.avatar_path`; `avatars` bucket + storage policies; `set_own_avatar` RPC (data-model-v1.2.0).

## UI states
Not a UI story.

## Test plan
- **Integration / RLS** — AC2–AC4 as user / other-user / anon (storage write scoping, the RPC).
- **Manual** — AC5: hit a public object URL.

## Definition of done
- [ ] ACs met; `typecheck`/`lint` clean; new RLS rows pass on the next on-demand RLS run; data-model matches.
