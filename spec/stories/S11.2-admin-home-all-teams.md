# S11.2 — Admin Home: the all-teams calendar

## Goal
An admin opens Home and sees **every team's** events on the calendar — a god view of the whole club — and
can tap any event straight through to manage it. No empty "not on a team" screen for an admin.

## Context
[V14](../00-decisions-v1.1.0.md): with S11.1 feeding all-teams events, the admin Home becomes the all-teams
calendar. An admin is not a squad member, so rows on teams they don't play for are view/manage (counts +
tap-through), not a personal Yes/No. If the admin also plays for a team, that team's events keep the normal
response controls.

## Scope
**In**
- For an admin viewer, the Home calendar renders **all active teams'** events (from S11.1), colour-coded by
  team, exactly like a multi-team player — but the membership empty state ("You're not on a team yet") does
  **not** show for an admin; a membership-less admin still gets the full calendar.
- The day rows adapt to the viewer's relationship to the event's team:
  - **Admin, not a member of that team** → a manage row: time · title (with team) · location · a
    manage-oriented summary (the availability counts, e.g. "6 available"), linking to the **manager event
    view** (S4.3), not the player detail. No Yes/No, no personal pill (the admin isn't responding).
  - **Admin who also plays for that team** (has a membership) → the normal player row (ResponsePill, links
    to the player detail) — they respond like anyone else.
- The awaiting-only top card (V13) is driven by the admin's own memberships only: a pure admin gets no top
  card; a player-admin gets it for their own unanswered events.
- Four states preserved: loading, error, and — for an admin — an "empty" that means "no events across the
  club this month" (not "no team").

**Out**
- The reads/pickers ([S11.1](S11.1-admin-aware-reads.md)). Any manager-screen change beyond the tap-through
  target.
- A separate admin dashboard — the god view lives on Home (V14 option chosen by the owner).

## Acceptance criteria
- [ ] **AC1** — Signed in as the seeded admin (no memberships), Home shows a calendar with **both** teams' events (dots in each team's colour) and their day rows — never the "You're not on a team yet." state.
- [ ] **AC2** — A day row for an event on a team the admin does not belong to shows the availability counts (e.g. "6 available") and links to the **manager event view** (S4.3); it has no Yes/No and no personal "Awaiting" pill.
- [ ] **AC3** — A day row for an event on a team the admin **is** a member of behaves exactly like the player row (ResponsePill, links to the player detail, respondable) — proven with an admin who is also a member.
- [ ] **AC4** — The top card shows only the admin's own unanswered events; a pure admin (no memberships) sees no top card, just the calendar.
- [ ] **AC5** — A **player** (non-admin) Home is byte-for-byte unchanged — the admin branch does not alter it.
- [ ] **AC6** — Four states: loading skeleton; error + retry; the empty case reads "No events this month." for an admin (club-wide), and stays "not on a team" only for a non-admin with no memberships; populated shows the all-teams calendar.
- [ ] **AC7** — 375px, no horizontal scroll, 44px targets; the manage row's tap target is the whole row.

## Implementation notes
- `HomeScreen`: branch on `isAdmin` (from `useCurrentUser`). For an admin, skip the `memberships.length === 0`
  no-team state and render the calendar from the S11.1 all-teams reads. The month/day grouping and dots are
  unchanged (they already key off team colour).
- A `DayEventRow` variant (or a prop on `DayEventCard`) picks the manage layout when the viewer is an admin
  **and** not a member of `event.teamId`. The counts come from the event's response aggregate — reuse the
  S4.3 counts derivation / a lightweight count read; if a per-row count is too heavy, show a simpler manage
  affordance (a "Manage" chip) and note the deviation. Links to `paths.manageEvent(event.id)` for the manage
  case, `paths.event(event.id)` for the member case.
- Keep the player path untouched: the admin logic is additive branches, not a rewrite.

## Data and API surface
Reads: the S11.1 all-teams events; the response counts for the manage rows (reuse S4.3's derivation or a
count read). No schema change. Links to the manager event view for the manage case.

## UI states

|---|---|---|---|---|
| `/` Home (admin) | calendar skeleton | "No events this month." (club-wide) | error + retry | all-teams calendar; manage rows (counts, → manager view) and, for own teams, player rows |

- **Integration** — as the seeded admin, both teams' events appear and a manage row reaches the manager view; `test:rls` green.
- **Manual** — sign in as 0899999001: see the whole club's calendar; tap an event → manage it.
