## Goal
Any signed-in user can open a "Send feedback" form from a consistent place, pick a bucket, type a note and
send it — with their route, app version and device attached automatically.

## Context
[W1/W2](../00-decisions-v1.2.0.md). The entry point lives in the app menu (the same menu S2.8's install guide
is reachable from), so it is one tap from anywhere. RHF + Zod + a TanStack mutation, the S4.1 form pattern.

## Scope
**In**
- A "Send feedback" entry in the app menu, reachable on every screen for any signed-in user (player, manager,
  admin). If no suitable menu exists, a `/feedback` route reached from the menu.
- The form: a one-tap category (Bug / Idea / Other), a message textarea (required, ≤ 2000 chars with a live
  count), a Send button. Inline validation (S4.1 style).
- On submit, capture `context` = `{ route, release, user_agent, standalone, viewport }` (W2) and insert via a
  `useSubmitFeedback` mutation. `user_id` is the session user; never sent from a field.
- On success, a brief thank-you confirmation and the form resets/closes. On error, an inline retry; the typed
  message is preserved.

**Out**
- Reading feedback back (S12.3).
- Attaching screenshots or files.
- Any anonymous/sign-out path — feedback requires a session (RLS needs `auth.uid()`).

## Acceptance criteria
- [ ] **AC1** — "Send feedback" is reachable from the menu on Home, an event, Manage and the admin screens.
- [ ] **AC2** — Category defaults to "Other"; message is required; > 2000 chars is blocked with a count shown.
- [ ] **AC3** — A successful send writes one `feedback` row with `user_id = ` the session user, the chosen
  category, the message, and a populated `context` (route + release at least).
- [ ] **AC4** — The four states are handled: idle form, submitting (button busy, no double-submit), success
  (thank-you + reset), error (inline retry, message kept).
- [ ] **AC5** — `release` in `context` is the `pfc-release` meta SHA (S0.6), read once, not hardcoded.

## Implementation notes
- `src/features/feedback/` — `FeedbackForm`, `useSubmitFeedback` (mutation in `src/api/feedback.ts`), a Zod
  `feedbackInputSchema` ({ category, message }).
- Read `release` from the `pfc-release` meta tag (the same source S0.6/smoke uses); `route` from
  `useLocation().pathname` (hash route); `standalone` from `matchMedia('(display-mode: standalone)')`;
  `viewport` from `window.innerWidth×innerHeight`. Keep it a small pure `collectContext()` helper, unit-tested.
- Present as a dialog/sheet from the menu (shadcn `Dialog`/`Sheet`) or a `/feedback` route — pick one, note it.

## Data and API surface
Insert into `feedback` (S12.1). `useSubmitFeedback` mutation. No new read.

## UI states
| Screen | Loading | Empty | Error | Populated |
|---|---|---|---|---|
| Feedback form (menu) | button busy while submitting | n/a (a form, not a list) | inline "couldn't send, try again", message kept | thank-you, form reset |

## Test plan
- **Unit** — `collectContext()` shape; the form's validation (required message, 2000 cap); the mutation calls
  insert with `user_id`/category/message/context.
- **Integration / RLS** — covered by S12.1's insert rows.
- **E2E** — optional: open menu → send feedback → success (local stack).
- **Manual** — send from a phone; confirm it appears in the S12.3 inbox with correct context.
