## The report
#4 "Let's capture injury status of players where they can be marked as injured themselves or by a manager
and provide updates on date of return etc"

## Goal
A player can be marked **injured** — by themselves or a manager of their team — with an **expected return
date** and a short note, visible where the squad is managed.

## Shipped shape (Z2 decided: self or a manager; informational only)
- **Data**: a `player_injuries` table, one row per player — `user_id` PK, `expected_return` (date, null),
  `note` (≤200), `updated_by`, `updated_at`. A **row means currently injured**; no row means fit (the
  event_responses "absence is a state" pattern) — a single current record, no history. Migration
  `20260930130000_injury.sql`. Its own table, not a `profiles` column, so a manager can read a player's
  injury via RLS (a manager can't read another `profiles` row) without coupling injury into `useCurrentUser`.
- **Write**: `set_injury(p_user_id, p_expected_return?, p_note?)` upserts; `clear_injury(p_user_id)` deletes.
  Security-definer, guarded to **self, a manager of a team the player is on, or an admin** (Z2). The detail
  params default null so an omitted arg clears that field. Bad note length raises `not_authorised` (backstop).
- **Read**: RLS SELECT scoped to self / a team manager / admin (not all teammates — the surfaces that show it
  are the player's own profile and the manager-gated roster). One RLS-scoped `useInjuries` backs both.
- **Surface**: an **Injured** badge + "Back {date}" on the member card (roster, Squad → Members and Admin →
  Members) with a "Mark/Update injury" action; and an **InjuryCard** on the player's own profile to self-report.
  Purely informational (Z2): it changes nothing about availability or squad selection. The squad picker flag
  was left out of scope for now (informational only); trivial to add later if wanted.

## Acceptance criteria
- [x] **AC1** — A player marks themselves injured with an expected return; a manager can too, for their team.
- [x] **AC2** — The flag + return date show on the roster (member card) and the profile.
- [x] **AC3** — RLS: only self / a team manager / admin writes it; reads scoped to the same audience.
- [x] **AC4** — Four states (the roster renders on the directory; the injury read never gates it, and the
  profile card hides while loading/errored — non-blocking like the subs card).
