## Goal

A link posted into a WhatsApp group opens the right screen. Tapping
`https://app.phibsboro.ie/#/event/9f1c…` on a phone that has never seen the app before lands on that
event, survives a hard refresh, and works from the WhatsApp in-app browser as well as from Safari, Chrome
and the installed PWA. Every other address the app will ever use — join links, reset links, the manager
screens — resolves the same way, and anything unknown lands on a 404 screen with a way home.

## Context

`CLAUDE.md` section 2 fixes HashRouter, and section 3's structure rules put the route table in one place.
HashRouter is not a preference: GitHub Pages serves static files, so a path-based deep link to
`/event/abc` would ask the server for a file that does not exist. Everything after the `#` never leaves
the browser, so `/#/event/abc` always fetches `index.html` and the app resolves the rest.

Decisions this story depends on, from [00-decisions.md](../00-decisions.md):

- **D34** — the brief's seven routes are not enough. Four later stories reference addresses the brief never
  lists, so a builder following the brief literally ships an app where every invite and every reset link
  hits the 404 screen. The full route list is fixed here, including `/register`, `/join/:token`,
  `/reset/:token`, `/history` and `/manage/team/:teamId/members`.
- **D41** — deep-link routes hide the bottom nav and show a back affordance, so the large YES / NO buttons
  are never underneath it. That mapping belongs in the route table, which is why it lives here.
- **D17** — the deep-link-after-hard-refresh criterion is checked by the S0.5 post-deploy smoke job against
  the live site, not by an E2E suite pointed at production. That is why this story is built after S0.5.
- **D1** — there is no external auth callback and no callback route. All auth resolves in the same
  document, so no route exists to receive a redirect.
- **D43** — the service worker is network-first for navigations. With HashRouter every route is served by
  the same `index.html`, so one stale shell breaks every link in every WhatsApp group at once. S0.4 owns
  the strategy; this story owns the fact that there is exactly one document to keep fresh.
- **D55, D56** — routing is Epic 0 scaffolding, touches no team data, and is exempt from the [S1.4](S1.4-rls-test-suite.md) gate.

The route guards themselves are **not** in this story. S2.9 owns them, and any guard is a redirect for
tidiness — RLS is the enforcement layer. This story defines the seam a guard plugs into and nothing more.

## Scope

**In**

- `react-router` v7 in library mode, `createHashRouter` plus `<RouterProvider>`.
- One route table module, carrying path, element, chrome and guard level for every route.
- The full D34 route list, each rendering a named placeholder screen owned by a later story.
- The 404 screen, reusable, since S3.3 renders it for an unknown event id (D49).
- The route-level error element, and the seam S0.6 wraps with Sentry.
- `src/lib/paths.ts` — the only place in the codebase that builds a URL containing `/#/`.
- A typed route-param hook, so no screen writes a non-null assertion on `useParams()`.
- Route-level code splitting for the manager and admin routes.
- Per-route document title.
- `public/404.html`, so a link that lost its `#` still reaches the app.

**Out**

- Auth guards, redirects to `/login`, and role checks — S2.9.
- Capturing and restoring the intended route across registration — S2.5, which stores it under
  `pfc.intendedRoute` in `localStorage` (D1).
- The content of any screen. Every route here renders a placeholder naming its owning story.
- The service worker and anything about caching — S0.4 (D43).
- Sentry instrumentation of the router — S0.6.
- Nested layouts beyond the single `AppShell`. There is one shell and one level of routes.

## Implementation notes

**Router.** `react-router` v7, library mode. `createHashRouter(routes)` and `<RouterProvider router={…}/>`
in `src/main.tsx`. Do not use the framework mode, and do not install `react-router-dom` — v7 exports
everything from `react-router`.

**One route table.** `src/routes.tsx` exports a typed array so the chrome mapping, the guard level and the
title are all data, and AC4 is a test over that data rather than a walk through JSX:

```ts
export type GuardLevel = 'public' | 'authed' | 'manager' | 'admin'

export interface AppRouteMeta {
  path: string
  chrome: Chrome            // 'nav' | 'bare', from [S0.2](S0.2-ui-system.md)
  guard: GuardLevel         // declared here, enforced by S2.9. UI convenience only; RLS is the boundary
  title: string
}
```

The table, in full:

| Path | Chrome | Guard | Screen owner |
|---|---|---|---|
| `/` | `nav` | `authed` | S3.1 Home screen with next event |
| `/login` | `bare` | `public` | S2.2 Sign in |
| `/register` | `bare` | `public` | S2.1 Registration |
| `/join/:token` | `bare` | `public` | S2.4 Join by link |
| `/reset/:token` | `bare` | `public` | S2.3 Password reset by manager |
| `/event/:id` | `bare` | `public` | S3.3 Event detail screen |
| `/history` | `nav` | `authed` | S3.5 Own attendance history |
| `/manage` | `nav` | `manager` | S4.1 Create event (the manager landing list lives there) |
| `/manage/event/new` | `nav` | `manager` | S4.1 Create event |
| `/manage/event/:id` | `nav` | `manager` | S4.3 Manager event view; S4.2 adds its edit and cancel actions |
| `/manage/team/:teamId/members` | `nav` | `manager` | S6.4 Member administration |
| `/admin` | `nav` | `admin` | S6.1 Teams, S6.3 All-teams view |
| `*` | `bare` | `public` | This story — 404 |

`/event/:id` is `public` on purpose. A stranger arriving cold from WhatsApp must see the event, which is
what `get_event_preview` exists for (D7), and the event link is a deliberate bearer join credential (D6).
Guarding it would break the one journey that matters.

**Static before dynamic.** React Router v7 ranks static segments above dynamic ones, so `/manage/event/new`
wins over `/manage/event/:id` regardless of array order. AC2 asserts the behaviour rather than trusting
it, because the cost of being wrong is a manager editing an event called "new".

**Code splitting.** Use the data-router `lazy` property on the `/manage/*` and `/admin` route objects:

```ts
{ path: 'manage', lazy: async () => ({ Component: (await import('@/features/events/manage-screen')).default }) }
```

A player's phone on mobile data never downloads the manager screens. Player-facing routes — `/`,
`/event/:id`, `/login`, `/register`, `/join/:token` — stay in the entry chunk, because the journey that
matters is measured in seconds and a second network round trip on a car park connection is not free.

**Paths module.** `src/lib/paths.ts`, the only place that knows the `#`:

```ts
export const paths = {
  home: () => '/',
  login: () => '/login',
  register: () => '/register',
  join: (token: string) => `/join/${token}`,
  reset: (token: string) => `/reset/${token}`,
  event: (id: string) => `/event/${id}`,
  history: () => '/history',
  manage: () => '/manage',
  newEvent: () => '/manage/event/new',
  manageEvent: (id: string) => `/manage/event/${id}`,
  teamMembers: (teamId: string) => `/manage/team/${teamId}/members`,
  admin: () => '/admin',
} as const

/** Absolute, shareable, includes the hash. The only builder of external links.
 *  Throws a named error when VITE_APP_BASE_URL is empty, rather than returning "/#/event/x". */
export function absoluteUrl(path: string): string
export const eventUrl = (id: string): string => absoluteUrl(paths.event(id))
export const joinUrl = (token: string): string => absoluteUrl(paths.join(token))
export const resetUrl = (token: string): string => absoluteUrl(paths.reset(token))
```

All three absolute builders live here, because AC8 allows the `/#/` literal in exactly one file.
[S5.1](S5.1-message-generator.md), [S6.2](S6.2-team-join-links.md),
[S6.4](S6.4-member-administration.md) and [S2.3](S2.3-password-reset-by-manager.md) all import from
`@/lib/paths` rather than building their own. Settled; see open question 3.

`absoluteUrl` strips a trailing slash from `VITE_APP_BASE_URL` before joining, which is what AC9 pins
down. [S5.1](S5.1-message-generator.md)'s message generator calls `eventUrl(id)` rather than concatenating, which is exactly what D13
means by "one env constant, no string concatenation at the call site".

Append the third check to `scripts/check-conventions.mjs`: the literal `/#/` anywhere under `src/` other
than `src/lib/paths.ts` is an error (AC8).

**Typed params.** `noUncheckedIndexedAccess` makes `useParams().id` a `string | undefined`, and the
tempting fix is `params.id!`. Ban it with a hook:

```ts
// src/lib/use-route-param.ts
export function useRouteParam(name: string): string
```

Implementation, in full, because the tempting version calls `useNavigate()` during render and warns:

```ts
export class RouteParamMissingError extends Error {
  constructor(readonly param: string) { super(`Missing route param: ${param}`) }
}

export function useRouteParam(name: string): string {
  const value = useParams()[name]
  if (value === undefined || value === '') throw new RouteParamMissingError(name)
  return value
}
```

React Router catches a throw during render in the route's `errorElement`, so the error element checks
`useRouteError() instanceof RouteParamMissingError` and renders `<NotFound />` for that case and
`<ErrorState />` for everything else. The caller's return type stays `string`, with no assertion. One
implementation, used by `/event/:id`, `/join/:token`, `/reset/:token`, `/manage/event/:id` and
`/manage/team/:teamId/members`.

**404 and error screens.** `src/components/not-found.tsx`, generic enough for S3.3 to reuse when an event
id does not exist (D49):

```tsx
export function NotFound(props: {
  title?: string          // default: "Nothing here."
  body?: string           // default: "That link doesn't point at anything."
  actionLabel?: string    // default: "Go to the app"
  actionTo?: string       // default: paths.home()
}): React.JSX.Element
```

Copy is written for a footballer holding a phone, so it is short and it does not say "route" or "404".
The screen renders inside `<AppShell chrome="bare">`.

The route `errorElement` is `src/components/route-error.tsx`. It renders `ErrorState` from
[S0.2](S0.2-ui-system.md) with `onRetry={() => { window.location.reload() }}` plus a link to
`paths.home()`. A reload, not `useRevalidator()`: a route that threw during render has no loader to
revalidate, and the honest recovery for a broken chunk or a bad param is a fresh document. S0.6 wraps the
root in the Sentry error boundary; this story keeps the error element a plain component with no Sentry
import, so that seam stays clean.

**`public/404.html`.** GitHub Pages serves it for any unknown path, so a link that lost its fragment still
lands:

```html
<script>
  var l = window.location
  l.replace(l.origin + '/#' + l.pathname + l.search + l.hash)
</script>
```

Three lines, no dependencies. It sits in `public/`, so `vite build` copies it into `dist/` and S0.5
publishes it with everything else. Note that it must not run on a *known* path: it only ever executes
because Pages could not find a file.

**Scroll and title.** Render `<ScrollRestoration />` inside the root route element (AC14). The title does
not belong to `AppShell`, which knows nothing about routes ([S0.2](S0.2-ui-system.md)). Each route object
carries `handle: { title }` from the table, and the root layout in `src/routes.tsx` reads it:

```ts
const TITLE_SUFFIX = ' · Phibsboro FC'   // defined once, here
const title = useMatches().at(-1)?.handle?.title ?? 'Nothing here.'
useEffect(() => { document.title = title + TITLE_SUFFIX }, [title])
```

**Placeholders.** Each route renders `<RoutePlaceholder story="S3.1" name="Home" />`, which prints the
story id on screen. Ugly by design: a placeholder that looks finished is a placeholder that ships.

**Gotchas**

- The WhatsApp in-app browser on iOS occasionally strips or mangles a fragment on a long URL. The share
  URL is short by construction — base plus `/#/event/` plus a uuid — and it must stay that way. Do not add
  query parameters to the share link (the rejected list in [00-decisions.md](../00-decisions.md) settles
  this).
- `base: '/'` in `vite.config.ts` from [S0.1](S0.1-project-scaffold.md) is a precondition. If the site
  were ever served from `/{repo}/` instead of the custom domain, every asset URL and `public/404.html`
  would need the prefix. It is served from `app.phibsboro.ie`, so it does not.
- D17's post-deploy smoke asserts a 404 screen for `/#/event/00000000-0000-0000-0000-000000000000`. Until
  S3.3 lands, that path renders the placeholder, not the 404 screen. The smoke job's target for now is
  `/#/nope`; S3.3 switches it to the event id when it starts rendering a real not-found state. Write that
  down in the smoke job, not just here.
- Hash-based navigation does not fire a full document request, so the S0.4 service worker never sees a
  route change. There is exactly one navigation request per session, for `index.html`, which is precisely
  why D43 makes it network-first.

## Data and API surface

None. No table is read, no RPC is called and no query key is introduced. Every route renders a
placeholder. The first server read in a route is S3.3's `get_event_preview`.

## Open questions

1. **Should `/manage` be a nested layout with a team picker, given S6.3 lets an admin administer any
   team?** Proposed default: no nesting. `/manage` is a flat screen and the selected team lives in the
   Zustand UI store, not in the URL. If S6.3 later needs a shareable per-team address, it adds
   `/manage/team/:teamId` as a sibling rather than restructuring the table.
2. **Does `/admin` need sub-routes for teams and members?** Proposed default: no. D50 gives S6.1 a single
   admin screen, and member administration already has its own route at
   `/manage/team/:teamId/members`, reached from the admin screen with the same component for both roles.
3. **Where do the absolute URL builders live?** **Settled: `src/lib/paths.ts`, this story's module.**
   AC8 permits the `/#/` literal in one file only, so several homes for the same literal cannot all be
   right, and the earliest story is the cheapest place to settle it. `src/lib/shareMessage.ts`
   ([S5.1](S5.1-message-generator.md)) keeps the message builders; it just does not build the URL.
   `src/lib/urls.ts` is never created. Recorded as an amendment in
   [00-decisions.md](../00-decisions.md).
4. **Should the 404 screen offer a sign-in link as well as a home link?** Proposed default: no. One action.
   A signed-out user hitting home is redirected to `/login` by S2.9 anyway, and two buttons on an error
   screen is a decision a confused player should not have to make.
